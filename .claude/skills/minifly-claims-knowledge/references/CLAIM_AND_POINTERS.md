# CLAIM, headline and pointers

`MFC` means `python3 -I tools/minifly_check/minifly_check.py`. Field-level schemas: `tools/minifly_check/SCHEMAS.md`
section 15 (CLAIM, `minifly.claim.v1`), 16 (pointer, `minifly.pointer.v1`) and 17 (ERRATA). Example files:
`tools/minifly_check/templates/CLAIM.example.json` and `templates/POINTER.example.json`. CLAIM is generated by
`MFC claim <dir>`; you edit only findings_proposed, findings_none_reason and notes.

## 1. Headline grammar (spec 9.9)

```
<PRIMARY_GATE> | earned <E> (attempted <E>) | held exact own-EOS <x>% [S2+ determined, n=<n>] vs best shortcut <name> <y>% | G <g>pp | OLD final <o>% (drop <d>pp) | <n> <ROLE> worlds | best of k=<k>
```

| Slot | Comes from (CLAIM) |
|---|---|
| `<PRIMARY_GATE>` | primary_gate |
| `earned <E> (attempted <E>)` | level_earned, level_attempted |
| `held exact own-EOS <x>% [S2+ determined, n=<n>]` | objective_metric.held_exact_own_eos over the counted items (determined items in the counted strata) |
| `vs best shortcut <name> <y>%` | objective_metric.best_shortcut (the strongest ladder member for the pool) |
| `G <g>pp` | objective_metric.G (spec 9.6) |
| `OLD final <o>% (drop <d>pp)` | objective_metric.old_final, old_drop |
| `<n> <ROLE> worlds` | n_worlds, worlds_role (computed, CLM-09) |
| `best of k=<k>` | designs_tried_k (computed over distinct (native_closure_sha, params_sha256) pairs) |

Optional suffixes, in this order:
- ` | <arm> >= candidate` when any control or shortcut is at least the candidate: every arm of the decision comparator
  (comparator_arms plus every declared no_prior_teaching, shuf, frozen and lesion arm, spec 20.6), the best other arm
  and the best shortcut are compared;
- ` | amended: co-primary <gate>` after an amendment that kept the original endpoint co-primary;
- ` | priors: <list>` from lineage.priors_added;
- ` | WEAK_COMPARATOR` when a declared comparator arm was below the best shortcut on dev (LAD-03);
- ` | dev shadow <verdict>` when the verdict on dev worlds is shown as a shadow.

When nothing held was measured, the middle slot reads `held exact own-EOS not_measured`.

The generator formats every number and computes the level. The three lines below show the shape; their numbers and
levels are illustrative, not values to imitate. Never retype a headline: copy it from CLAIM.json (SKILL.md section 2).

### Worked headline 1: PASS, E3, MAIN worlds

```
PASS | earned E3 (attempted E3) | held exact own-EOS 62.5% [S2+ determined, n=80] vs best shortcut CANON 12.5% | G 41.3pp | OLD final 91.0% (drop 2.0pp) | 8 MAIN worlds | best of k=2
```

This is the headline of `templates/CLAIM.example.json`. G (41.3pp) is below the candidate-minus-shortcut gap because
G subtracts, per world, the strongest of no_prior_teaching, the shortcut and chance; here NPT (20.0%) is stronger than
CANON. What the line does not say matters as much: reuse_specificity is not_tested (no UDI), and the worlds are MAIN,
not sealed. So the result is plain E3, its G is reported as 'unsealed' and is not program progress, confirm wording
is banned, and adoption or a promotion pointer still needs UDI LCB > 0 and SEALED_CONFIRM (CLM-03).

### Worked headline 2: FAIL, best shortcut FIXED_1

```
FAIL | earned NONE (attempted E3) | held exact own-EOS 10.4% [S2+ determined, n=80] vs best shortcut FIXED_1 10.6% | G -0.4pp | OLD final 90.0% (drop 1.0pp) | 8 MAIN worlds | best of k=3 | FIXED_1 >= candidate | WEAK_COMPARATOR
```

This is the STOP-ONLY pattern (corpus fixture C06a, built from `minifly_address_capacity_v1_dev_20261023/REPORT.md:7`).
The candidate's own output stream, truncated after one byte with EOS assumed there, scores as well as the candidate,
while the declared comparator (DIRECT) scored below the ladder on dev. STOP-ONLY reported a +22.10pp gain against
that comparator after 225,792 records. Under v1 the comparator is max(chance, comparator arms, ladder), so data like
that gives a FAIL line of this shape and nothing softer. Report it as it stands. It is an honest result, and any
follow-up is a new protocol.

### Worked headline 3: NOT_OPENED, dev shadow

```
NOT_OPENED | earned NONE (attempted E3) | held exact own-EOS 31.3% [S2+ determined, n=48] vs best shortcut CANON 12.5% | G 15.0pp | OLD final 92.0% (drop 1.5pp) | 2 DEV worlds | best of k=2 | dev shadow PASS
```

A T1 delivery that ran dev cycles only (corpus fixture C00e: publish exits 0). Nothing official ran, so the primary
is NOT_OPENED. On dev worlds decide returns DEV_NOT_EVIDENCE, and its shadow verdict appears only as the suffix.
Never write that the delivery 'passes' or is 'confirmed'. Never quote the shadow as a result. Never point at it: T1
cannot update pointers. Its primary predictions are scored 'unresolved'.

## 2. Enum tables (CLM-01)

Closed vocabularies. A value outside them is FAIL. Free-text levels are not allowed: the census catalog's 40
free-text evidence_level strings are why (spec 12.4).

| CLAIM field | Values | Computed by |
|---|---|---|
| primary_gate | PASS, FAIL, INVALID, INCOMPLETE, NOT_OPENED, CANNOT_TEST_CLAIM_AS_SPECIFIED | claim, from VERDICT and the stage reached |
| level_attempted | E0, E1, E2, E3, E4 | the lock's claim_level_target |
| level_earned | E0, E1, E2, E3, E4, NONE | claim, under CLM-03 |
| reuse_specificity | not_tested, udi_pass, udi_fail | claim: udi_pass/udi_fail only when UDI-01 passes (E3 promotion only); UDI-01 is planned in checker 1.0.0 (not yet enforced), so claim writes not_tested |
| gate_type | objective, component | LOCK-03 (anything but the unconditional own-EOS metric is component) |
| worlds_role | DEV, PILOT, MAIN, SEALED_CONFIRM | CLM-09 |
| labels[] | integrated_intervention, weak_comparator, priors:`<x>` | CLM-03, LAD-03, lineage.priors_added |
| invalid_reason | INTEGRITY_ALARM, TREATMENT_NOT_DELIVERED, NONFINITE, null | decide preconditions (spec 9.5) |
| dev_shadow_verdict | a VERDICT value or null | decide on dev worlds |
| stop_reason | computed when the delivery stopped before official (for example CANNOT_TEST after ADM-TB-*: corpus C00c, C05a) | claim |
| provenance | {interrupted (bool), resume_attempts[], resumed_units[[world, arm]], replay_units[[world, arm]]}: whether an official attempt was interrupted, and the units a `launch --resume` wrote and replayed (spec 20.8) | claim, from ATTEMPTS and the official and replay rows |

| VERDICT.json verdict | Meaning |
|---|---|
| PASS | Every rule clause, gate and guard passed on non-dev worlds |
| FAIL | Measured and failed |
| INVALID | A precondition failed: INTEGRITY_ALARM, TREATMENT_NOT_DELIVERED or NONFINITE |
| INCOMPLETE | A required cell is missing; a shadow verdict is computed on the complete paired worlds |
| DEV_NOT_EVIDENCE | Some world was technical, dev or rehearsal; a shadow verdict is attached |
| CANNOT_TEST_CLAIM_AS_SPECIFIED | The testbed screen failed (no ceiling passes, or a floor passes) |

DEV_NOT_EVIDENCE never becomes a primary_gate. A delivery without an official run is NOT_OPENED, with its dev
verdict carried as dev_shadow_verdict. Honest exits (FAIL, INVALID, INCOMPLETE, CANNOT_TEST_CLAIM_AS_SPECIFIED) are
ordinary values and are reported exactly like PASS.

Where they are checked: the publish gate (`MFC gate --stage publish <dir>`, all CLM ids), the pointer gate
(`MFC gate --stage pointer --pointer PATH <dir>`, PTR-01..07 and CLM-02), and `MFC lint <files...>` for T0 text
(CLM-06, CLM-12, CLM-16, CLM-17, PTR-01..07; CLM-17 judges a linted file against the CLAIM.json of the v1 delivery
that contains it; a file outside every delivery is judged sentence by sentence, and table row by table row with its
header, against the CLAIM.json of each v1 delivery it names, and is NOT_APPLICABLE when it names none).

- Every text is first read as rendered (spec 20.12): HTML entities decoded, HTML comments and tags and the markdown
  markers `*`, `**`, backticks, `~~` and `__` removed, and a second reading with markdown links and images replaced by
  their text (`[con](#)firmed` is `confirmed`; a link target named confirm* still counts in the first reading). CLM-04
  and CLM-17 share this normalisation.

- 'approved' blocks too: a memo's 'approved' is not authorization ("A prior memo's word 'approved' is not human
  authorization", `minifly_v6_revised_design_20261023/REVIEW.md:12`).
- 'partial' is the word LEARNED-BANK's fail-open reducer produced for 3 of 4 supported worlds
  (origin/charming-head `minifly_learned_bank_v1_20261024/summarize.py:99-100`). Under v1 the locked aggregator
  decides, and the headline shows the result.
- Lists catch only the listed words. A synonym in body prose is not blocked (spec 15: partly open). The generated
  headline is the defence, not your vocabulary.

## 4. Pointer procedure (minifly.pointer.v1)

Preconditions (all of them):
- The publish gate passed for the delivery at the commit you point to.
- The delivery has no open REVIEW_DEBT (DEBT-02). The pointer stage always runs at T2; T1 deliveries cannot be pointed at.
- AUTHORIZATION stage pointer_update is true, or an adoption UD exists (PTR-01). An agent message is neither.
- For an E3 result presented as the track's adopted state (promotion): UDI LCB > 0 and SEALED_CONFIRM (CLM-03).
- No newer v1 delivery in the same track, or you say why you point at the older one (PTR-06 warns).

Steps (track name in lower case as in the pointer's `track` field; `<TRACK>` upper case in the history dir):

1. Snapshot the current pointer first, byte for byte, into the track's history directory:

   ```
   DIR=<delivery dir>; TRACK=<track>; UD=<adoption UD id, or empty>
   POINTER=PROJECT_DOCUMENTS/<CURRENT_POINTER>.json
   PREV=PROJECT_DOCUMENTS/<TRACK>_POINTER_HISTORY/$(date -u +%Y%m%dT%H%M%SZ).json
   mkdir -p "$(dirname "$PREV")" && cp "$POINTER" "$PREV"
   ```

   Existing history directories (`PROJECT_DOCUMENTS/ARITHMETIC_DESIGN_POINTER_HISTORY/`) show the pattern. A track's
   first pointer has nothing to snapshot: set `PREV=` (empty).
2. Generate the new pointer from CLAIM.json. Copy, never retype:

```
python3 -I - "$DIR" "$TRACK" "$PREV" "$UD" > "$POINTER" <<'EOF'
import hashlib, json, sys, time
d, track, prev, ud = sys.argv[1:5]
raw = open(d + '/CLAIM.json', 'rb').read()
c = json.loads(raw)
p = {'schema': 'minifly.pointer.v1', 'track': track, 'delivery': c['delivery'],
     'claim': d + '/CLAIM.json', 'claim_sha256': hashlib.sha256(raw).hexdigest()}
for k in ('level_earned', 'primary_gate', 'gate_type', 'worlds_role', 'objective_metric'):
    p[k] = c[k]
p.update(narrowing_rows=[], updated_utc=time.strftime('%Y%m%dT%H%M%SZ', time.gmtime()),
         previous_snapshot=prev or None, user_decision=ud or None)
print(json.dumps(p, indent=2, sort_keys=True))
EOF
```

3. Fill narrowing_rows with the narrowing or supersession row id of every finding that the pointer, the CLAIM notes
   or the REPORT quotes and whose latest status is narrowed or superseded (PTR-04). Run `MFC kb status` to see them.
   Add nothing else: no prose, no booleans (PTR-03), no local paths (PTR-05).
4. Run `MFC gate --stage pointer --pointer "$POINTER" "$DIR"` and proceed only on exit 0.
5. Commit the snapshot and the new pointer in one commit (PTR-01), with your `Acting-Agent:` trailer.

Never edit a pointer in place to change its meaning, and never write a pointer that a regenerated CLAIM would
contradict (PTR-02 compares against claim_sha256). The legacy pointer
`PROJECT_DOCUMENTS/CURRENT_EXTERNAL_MEMORY_EXPERIMENT_DESIGN.json:5` (`"confirmation_passes": true`, 22 `/Users/`
paths) is the counter-example (corpus fixture C24: PTR-04, PTR-03, PTR-05).

## 5. Legacy pointer rule (PTR-07)

Every delivery that is not schema v1 is legacy: all current `PROJECT_DOCUMENTS/CURRENT_*.json` targets, and
LEARNED-BANK on origin/charming-head. A legacy delivery has no generated CLAIM, so a pointer to it cannot be a
CLAIM copy. PTR-07 requires both of the following:

1. An owner UD that names the pointer change, recorded verbatim in USER_DECISIONS (a protected ledger; see
   `minifly-governance`), with its id in user_decision.
2. A KB/RETRO annotation for the target, cited by path:

   ```
   MFC retro <legacy-dir> --out <scratch-dir-outside-every-delivery>
   ```

   Commit the annotation rows to `PROJECT_DOCUMENTS/KB/RETRO/` as RETRO_ANNOTATION rows: annotations, never verdicts.

For LEARNED-BANK, the KB/RETRO record must also hold a Codex executing review covering the fail-open
`summarize.py`, the lock closure, the D3 reuse and amendment A1's distance from E3, and its findings enter as
provisional (spec 17, Phase 1). Without the UD and the annotation the pointer gate fails, and it fails closed if
either is missing or unreadable.
