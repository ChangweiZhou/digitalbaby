# RAW-RULE V2 — design review and preparation boundary

13 October 2026. Status: **static design reviewed; implementation and three-cycle qualification not performed**.

## Fixed goal and corrected diagnosis

The goal is retained unseen four-operation own-byte output per external sample and production computation, learned from arriving feedback without supplied arithmetic rules. It was not replaced by taught memorization, token loss, format handling or noise tolerance.

The current saved-state evidence localizes the final technical fixture to conditional answer-content learning: 137 of R1's 158 failed complete answers already have a wrong first byte, before any generated-prefix compounding. EOS conditional accuracy is 100%. Equality of complete teacher-forced and own exact counts is expected under deterministic greedy inference and is only a parity check, not independent causal evidence. Frozen readouts satisfy the intended regression identities but fit the context population poorly. Full rank rules out literal whole-cue aliasing, and frozen failure rules out feature drift as the sole cause. The read-only algebra uses post-hoc labels solely to diagnose the old representation; no result is a new candidate, initialization, training life or confirmation.

## Independent review and revisions made before delivery

An independent reviewer proposed a smaller same-GRU joint-learning comparison. The saved-checkpoint suffix geometry and full-inventory review justified also freezing a generic ordered reader alternative in this one package. This produces a 2-by-2 reader/loss comparison, two frozen controls and two exact references, rather than a sequence of unspecified later patches.

The independent [eight-arm audit](../arithmetic_feedback_rule_discovery_dev_v1_20261013/ops/read_only_review_20261013/design_critic/ROSTER8_AUDIT.md) accepted that scope while requiring these qualifications:

1. All literal byte/control events, including reply history, enter the ordered window; absent padding is distinct from payload NUL. Right alignment and leading padding are now explicit.
2. G/L differ in architecture, effective context and parameter count. Full actual state/work is charged; no equal-resource mechanism claim.
3. SQ/CE differ in gradient scale despite sharing the RMS settings. Record component norms/clipping; comparisons are declared recipes.
4. Oracle LS cannot feed the new learner. Taught recovery cannot earn the E3 verdict.
5. Actual-byte EOS can update; generated or prohibited EOS cannot. Pending state and long-record semantics require implementation tests.

The independent [actual-document audit](../arithmetic_feedback_rule_discovery_dev_v1_20261013/ops/read_only_review_20261013/design_critic/V2_DOCUMENT_AUDIT.md) found an inherited statistical issue: an exact sign test cannot be used as an exact population-mean test when all paired sample differences are constant. The V2 design now uses a conservative bounded-mean Hoeffding branch and nonzero-width bounded intervals for that case. It does not alter any frozen experiment.

The feedback-only shortcut envelope B is explicitly a protected evaluator oracle benchmark, not a matched full-history learner. To avoid calling a frequency shortcut arithmetic discovery, V2 prospectively adds four final operation-wise superiority tests against B to the original twelve, a Holm family of 16. This is on the same held queries and budget, with no new task or percentage cutoff. The chosen frequency recipes, fallback and ties must be independently implemented/locked before DEV.

## Remaining qualification obligations

No learner code is included in this design. The formulas, full-record derivatives, token ring semantics, original-reference parity, branch permissions, source separation, resource accounting, complete-job costs and independent analysis/dispatcher remain unqualified. The future three-cycle exercise must test these, save actual-budget behavior and preserve every failure.

The planning counts are audited algebraically: 64 DEV jobs plus at most 288 confirmation jobs; each 2,112 external record applications, three root histories and eighteen inherited cohort forks. Maximum 352 jobs, 743,424 records, 7,392 correlated trajectories, 56 independent world identities. These are planned counts, not committed work.

Cost is deliberately **not** an ETA. V1 took seconds per full technical job, but the joint optimizer/ordered reader needs new measured full-job timing and two-worker parity. Admission requires 3x measured execution plus measured finalization within eight hours, with a ten-hour hard session boundary.

No formal namespaces are admitted. No new trajectories, background processes or GitHub upload were started by this design review.
