## 1. Owner's frame (rulings kept in force)
- Byte stream in, bytes out, feedback (the right byte, or yes/no; the form may be adjusted); strictly local learning, **no global
  backpropagation**; one continuous life; keep what was learned (E2) and generalise (E3); "一切从生物学原理出发".
- Many kinds of cells with their own local rules are fine, **but the architecture must be general**; bitter lesson: no spot fixes.
- Section 20/21: no long window of past bytes; a cell-level short window is allowed; a small episode store for rehearsal is allowed.
- Hyperparameter learning by the network itself is deferred. E1 (byte-level learner) is regarded as essentially solved.
- 23 Nov: stop the bits/Transformer comparison for now; focus on continual learning from biological principles.

## 2. How "has a rule been learned" is measured (designed with the owner, 22 Nov)
- **First encounters in one life**: items are generated by a rule; only answer bytes of items met for the first time are scored,
  before they are read (prequential, learning on). Storage is at chance on them by construction.
- **Layers** of each first-met answer byte: a = storage could know it (the stretch that fixes it was read before); b = new
  combination of symbols seen as answers >= 5 times; n = 1-4 times; c = a symbol never given as an answer.
- **Rule change** in mid-life (copy -> rev -> copy; t23 adds text and a learned mapping): windows after each change (savings).
- **Probes** with learning off for keeping (E2); **total bits of the life** as one number for E2 and E3 together.
- **Baseline**: a back-off n-gram table (storage) of the same window.
- Scripts: `t21_answers.py` (whole answers on never-shown items), `t22_rules.py` (first encounters, copy/rev/copy),
  `t23_life_rules.py` (copy, rev, text, succ, copy, rev; cued or not; probes; bits), `t24_add.py` (column addition, carry written or
  not), `t25_bits.py` (bits per byte on never-read text). Toys: `toys/` (4-region net), outputs `toy_out/`.

## 3. Architecture now: net12 = net10 (K8) + new cell kinds (all options default off; off = net10 exactly, checked)
- net10 K8: two pathways (pure chain + random DAG), context minicolumns, holding cells with clock bands, joint mismatch.
- `W=8` **lag cells** (cell-level short window: "byte u, j back").
- `lagro=1` direct readout of lag cells (factorised (lag, byte) -> answer).
- `relay=1` **gated relay**: lag j's lines project topographically to the answer lines; a learned gate chooses the lag
  (delta rule on the mismatch of the line it carries). `relay=2`: a learned map on the byte's 16-line code instead of the wired map.
- Other options tried (see 6): `ctxg`, `ctxg_err`, `xdg`, `lag_xdg`, `xvig`, `xdg_nov`, `lagro_gate`, `match` (match cells),
  `pairs` (hashed pair cells), `pairs_gate`, `pairs_only`, `relay_inh` (shunting inhibition), `gate_rate`, `hid` (feedback-alignment
  hidden cells), `apical` (slow-trace modulation of the gate), `gbr` (dendritic branches with recruitment), `recall` (episodic store
  and recall compartment). Subclasses by helpers: `net12_cf.py`, `net12_rep.py` (targeted replay, slow/fast gate), `net12_fb.py`.
- Cost (measured): ~1.5-2.5 M operations a byte, ~13 M stored numbers, very sparse (~60 context cells, ~640 holder expansion cells
  active a byte); ~5 ms a byte on one core. The dense dendrite check dominates; the event-driven kernel net7e (3-18x faster) does not
  yet support the K8 topology.

## 6. The diagnosis of the E2 failure, and what was tried
**Lesion tests** (toys/vig_toy_lesion.py, repeated by helpers): after copy returns, the succ mapping is intact in the direct readout
(relay off: succ 0.93-0.98); it is masked by the **relay's gate, which copy training reopens through the symbol lag cells both rules
share**. The delimiter, as a lag cell, is what the gate needs (removing content inputs removes it: IDEA3_REPORT.md). Text loss is
spread over all compartments.

Toy criterion (4 regions; life copy -> rev -> succ -> copy, cued): succ after the last copy >= 0.85, copy/rev >= 0.95, first-200
copy >= 0.6. Baseline: copy after succ 0.53, succ after last copy 0.58.

## 8. Discussion points recorded
- **E2 and E3 together**: knowledge stored as conjunctions neither generalises nor survives; the principle is "share what is
  consistent, separate what conflicts" - factorised shared machinery (lag cells, relay) plus context-specific, protected parts.
- **Scale**: unlikely (my estimate ~10-20%) to explain the gate failure (capacity is not binding; the mechanism is structural;
  scaling made toy gains worse). It may matter for text keeping and for hidden variables. Test: one failing and one partial idea at
  2x/4x cells and 3x data.
- **Dimensions that can be scaled** besides cells, text and questions: number/topology of regions (chain length, pathways, sources),
  columns per region and cells per column, sparseness, synapse slots and growth, holders (bands, longest clock, cells per band), the
  short window W (kept short by ruling), pair/higher-order/recruited conjunction pools, the episodic store (size, episode length, match
  length, keeping rule), replay and sleep ratios, the life's structure (number and kinds of tasks, returns, blocked vs interleaved),
  rule complexity (alphabet, kinds, nesting), feedback sparseness, and the implementation (event-driven kernel). Scale one at a time,
  measuring E2, E3 and total bits each time.
- **vs a Transformer of the same size**: not measured. Expected: single-pass online on 16-64 kB a small Transformer is worse; with many
  epochs on the same data about the level of a count table; with much more data it would be clearly better on text. Our measured
  advantages are rule generalisation in one life, no backprop, ~10x fewer operations a byte.
