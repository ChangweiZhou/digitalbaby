# Physical shared-bank deletion: compact R_center v1

This protocol implements the user's authorized next step after three distinct
design–audit–trial–revision cycles. It compares the existing eight-store R_center
against four private CONTENT stores. The shared bank is physically absent in
the candidate, not just ignored by an evaluator. Both configurations receive
the same observable byte stream and use the inherited private centered write
`c=0, s=.25-y`. The candidate does not receive additional information. Parent
sources and historical receipts remain unchanged. Parameters are not tuned on
technical or science outcomes. A negative scientific result completes the study;
it does not authorize a rescue variant, automatic rerun or extra science seeds.

## Claim, exposure and countermodels

Evidence level is E1: directly taught arbitrary cue→answer acquisition,
retention and revision, with a compression comparison. It is not a reusable
general intelligence core, E3 transfer, unsupervised learning or free byte
generation. Every scored target is explicitly taught. An exact-key or
canonicalized-key table can pass. Balanced, randomly assigned labels prevent
fixed symbol/arithmetic/frequency shortcuts from encoding the target map.
CONTENT's exact recent-four-visible-byte key is retained; no new encoder is
introduced. Generic long-context and similarity limitations are unchanged.
The standing objective contract is honored by reporting the actual E1 level;
the user's later direction explicitly makes E3 optional for this stage.

## Frozen inputs and chronology

96 independent pseudorandomized worlds 491001–491096, paired across arms.
Engineering worlds 490101–490103 never enter inference. Each world uses all
64 twelve-byte cues `eight spaces + a+b=` for a,b in 0–7. They are cue strings,
not addition problems. Last-four-visible-byte keys are unique. A random split
assigns 32 old and 32 new keys; each cohort has eight targets in each ASCII
channel 0–3, assigned independently. Twelve separately shuffled bouts per
cohort supply 384 old and 384 new records. Eight old keys (two per initial
target) are prospectively selected for revision, with a cyclic changed target,
and receive twelve bouts (96 records). Other old keys are not re-taught.

Each record is 165 simulated seconds. Cue byte spacing is 30/14 seconds.
The core predicts after 12 bytes, before the actual answer byte is delivered
at that same scheduled slot; newline follows. After each stage there is one
24-hour simulated rest. Total: 864 records and three 24-hour rests per life.
Read-only cloned probes occur at old_end/old_day, new_end/new_day,
revision_end/final. Each clone is discarded; it receives no target feedback.
All outputs come from the model's fixed argmax, not evaluator comparisons.

Four histories see identical bytes, target bytes and clocks: W writes all
stages; N_old blocks old writes; N_new blocks new writes; N_revision blocks
revision writes. A literal stage/branch matrix governs all store APIs. Every
actual native/signed call is instrumented. Blocked calls must match a separately
evaluated native no-plasticity state transition and apply zero write. Each
physical store is independently canonical-born. The private trajectories must
be exactly equal across the matched arms; deletion only changes operative
readout and resources. This parity is audited, not used to select parameters.

## Primary family and sample-size rule

For each world, one old key among the 24 unrevised keys, one new key among 32,
and one revised key among eight is sampled uniformly before any run, using
separate fixture RNG streams. These final first-response binary outputs are
the primary observations, with the WORLD as independent unit. Every other cue
is still scored and saved, with all-cue means/per-cue errors reported descriptively.
Sampling a key defines marginal reliability on that stratum; it does not
certify uniform accuracy for every individual key. No probe or world is dropped.

There are six one-sided bounds at alpha=.05/6: for each stratum, an exact
Clopper–Pearson upper bound on paired losses (baseline correct, candidate
wrong), and lower bound on candidate accuracy. Mean candidate-minus-baseline
accuracy is at least minus the paired-loss probability. Adopt only if ALL
three loss bounds are strictly below .05 AND ALL three accuracy bounds are
strictly above .90. This is a conservative finite-sample noninferiority rule,
not an equivalence conclusion from nonsignificance. Exact coverage assumes
independent randomized worlds under this frozen generator.

n=96 is fixed before technical trials. With zero losses its family-adjusted
upper bound is 1-(.05/6)^(1/96)=about 4.87%, just below the 5% tolerance.
This is sample-size feasibility at zero losses, not a promised power result
for nonzero loss rates. No optional extension if one loss makes a gate fail.
All-cue W−N_old/new/revision effects and approximate paired t intervals are
descriptive secondary evidence, not additional promotion gates. Constant
descriptive differences have no fitted t interval. The primary exact bounds
remain valid at zero observed variance.

## Three work cycles

1. Audit physical deletion and private trajectory parity; test actual disabled
   calls, arrived-byte teacher routing, independent births, output arithmetic,
   explicit branch matrix and hostile tampered receipts. Revise implementation
   or audit defects only; do not select a better performing configuration.
2. Run both arms' complete 864-record four-branch life on world 490102, including
   all clock boundaries, 64 effective keys and changed targets. Independently
   audit every record/probe and matched private state. Measure cold-start,
   final logging/checkpoint policy, elapsed time, RSS and receipt size.
3. Deliberately stop a technical job at its committed 32-record cursor and
   resume it in a fresh process. Compare the next 32 records and native state
   exactly with an uninterrupted run; test wrong identity, malformed arrays,
   tampered teacher/call/probe/cursor, completed-receipt skip and corrupt-lock
   rejection. Seal final source and bind qualification to those bytes.

Science starts only after three accepted cycles and a qualified final source
lock. Any source revision invalidates earlier final qualification, so affected
tests must be repeated before launch. Science endpoints, n and candidate do
not change in response to the development results.

## Execution, resources and completion

192 world-arm jobs × four branches = 768 lives. Four CPU workers (user-authorized execution amendment); BLAS/Numba
thread counts fixed to one per worker. A durable detached supervisor owns the
workers and caffeinate. Atomic checkpoint includes complete learner, input
suffix, cursor, records and probe history every 32 records; no terminal needed.
Completed receipts are audited and skipped, never overwritten. Exact resume
of an interrupted job requires explicit authorization; no automatic retries
after scientific/integrity/resource failure. Peak worker RSS cap 1 GiB,
job deadline 2400 s, dataset cap 2 GiB, worker budget 40 h. Technical timing
must fit that budget without truncating the scientific roster. Source versions,
logs, failures and committed counts persist. No partial dataset is analyzed as
complete. Full analysis waits for all 192 receipts and matched-arm audits.

Report runtime/RSS/checkpoint/receipt bytes as measured. Four rather than eight
stores halves store count, not necessarily runtime, entire RSS or checkpoint
size. The supervisor generates final REPORT.md/SUMMARY.json and uploads the
source, three cycles, logs and result receipts to the user-authorized digitalbaby
branch. Publication failure is reported separately from a scientific result.
