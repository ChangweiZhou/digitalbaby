# Three-cycle operations audit

The only native launch surface accepts cycle2/cycle3 and checks the fixed world
roster and complete locked source identity. DEV and CONFIRM have no launch path.
Each world/model reserves its state directory before training. An existing
directory or receipt blocks automatic repetition, including incomplete attempts.
Full receipts commit only after the independent permission/data/state auditor
passes. The dispatcher records committed counts only after reading that accepted
certificate. Active per-segment progress is explicitly partial work.

The dispatcher is detached, uses two children with single-thread Torch/BLAS, and
attaches caffeinate to its own PID. Admission stops by eight hours with a job-cost
reserve; the session hard limit is ten hours from the implementation wake lease.
Failures are preserved and are not retried. The dispatcher terminates and reaps
its own children if an error or stop interrupts it. Science does not resume from
this tool. The capped implementation wake lease is released at task completion.

Cycle2 ran all of this with two accepted native jobs. Cycle3 uses the unchanged
dispatcher, worker, model and independent auditor. Only reporting-clock wording
and implementation notes changed after cycle2; snapshots preserve both versions.

The optional monitor binds only 127.0.0.1:8881. GET endpoints are /, /status and
/report only. There are no filesystem traversal, upload, execution or control
endpoints. A denied process-liveness check is displayed as unknown, never stopped.
Its status comes directly from the current per-cycle files, not a startup copy.

finish_technical.py is an operational closeout script, not part of the executed
learner source: it checks original accepted certificates and immutable source
snapshots, verifies archive dimensions, reduces saved outputs once, writes the
three-cycle report and packages the result. It cannot launch training. No GitHub
publication is authorized by this implementation/technical-cycle request.
