# Representation and generalization: local experiments, 2026-11-03

**Rules followed:**
- No backpropagation and no attention. All learning is local: delta / normalized-LMS readouts and a TD(0) successor-representation update. Codes are fixed random sparse expansions.
- No content-addressed key–value reads.

**Status of the evidence:**
- Every result here is a **development check** on synthetic data, with 1 seed for the representation runs and 10 seeds for the generalization runs.
- Under the project's evidence vocabulary it is `BOUNDED_DEV_POSITIVE` / `DEV_SCREEN_FAILED`.
- It is not E1/E3 confirmation: there are no own-generated byte/EOS answers and no sealed sets.

**Code and raw outputs:** `minifly_review_experiments/rep_gen_20261103/`
- `rep.py` and `dual.py`: representation.
- `cyc.py` and `hold.py`: generalization.
- `*.json` and `*.jsonl`: results.

**Substrate:** the recovered V39 stream and learning rule (`origin/codex/minifly-v39-v40-source@4a667352`), scaled to N=16,384 KC units with K=819 active. The previous session showed this size retains facts at load 128.

## Part A — Representation: what breaks identity, and why

### A1. Probe families (R1 from the stage plan)

**Setup:**
- 64 facts in 4 waves, 32 presentations each.
- Each fact is a record such as `~|~|@KEY123:x`.
- Retention is probed on the untouched wave-A keys after waves B, C and D, with renderings the learner **never saw**:
  - `heldout_render`: new header and separator.
  - `shift1` / `shift2`: 1–2 extra bytes between the key and the separator, so the key moves in position.
  - `wrapper`: a different prefix.
  - `prefix_shift`: the key moved to the left.

**Front ends** (all fixed, no learning):
- `lag`: the original position-bound code, 12 bytes × 8 bits.
- `ngram`: a position-free bag of hashed bigrams and trigrams over the last 12 bytes.
- `both`: the two concatenated.

**Results after wave D.** Every byte is written, as in V39; the "target-only" row is an oracle.

| front end / writes | trained | new header/sep | shift 1 | shift 2 | wrapper | whole bits/byte |
|---|---|---|---|---|---|---|
| lag, all bytes | 100% | 100% | **0%** | **0%** | 100% | 1.32 |
| ngram, all bytes | 94% | 0% | 0% | 0% | 6% | 2.65 |
| both, all bytes | 100% | 100% | 0% | 0% | 63% | 1.44 |
| lag, **target-only (oracle)** | 100% | 100% | 0% | 0% | 100% | n/a |
| ngram, **target-only (oracle)** | 100% | 88% | **100%** | **100%** | 94% | n/a |
| both, **target-only (oracle)** | 100% | 100% | **100%** | **100%** | **100%** | n/a |
| both, error-gated writes (label-free) | 100% | 100% | 0% | 0% | 56% | 3.13 |
| dual store: lag predictor + `both` memory written when the predictor is wrong (label-free) | 100% | 100% | 0% | 0% | 81% | 1.53 |
| same dual store, random writes at the matched 15% rate | 100% | 100% | 0% | 0% | 75% | 1.46 |

**Code overlap.** Jaccard overlap between a shifted probe and its trained context:
- lag: 0.07, *below* the 0.14 overlap between two different keys;
- ngram: 0.43.

### A2. What this means

1. **Position binding is the first bottleneck.**
   - The lag code makes a key moved by one byte look like an unrelated key.
   - This is why every byte-line representation result (V36–V40) only covered header and separator swaps. Those keep the key at the same lag positions.
2. **A fixed position-tolerant code carries the needed information.**
   - With the n-gram/both code and writes restricted to answer events, every shifted and wrapped probe is recalled (100%).
   - Old facts survive three interference waves.
   - No learned encoder and no slots are needed.
3. **The second bottleneck is write allocation, and none of the label-free gates fixed it.**
   - When the association store also learns every syntax and key byte, the shared n-gram units carry generic predictions that swamp the key-specific signal.
   - Gating writes on the store's own errors, or on the predictor's errors, does not isolate the answer events. Key bytes are just as unpredictable as answers.
   - The predictor-error gate was no better than random writes at the same rate.
   - This reproduces V52 (target-only writes 7× better) and V54 (context-gain gating failed), now on the scaled store.

**Interpretation: representation = invariant code × correct write allocation.** The invariant code is the easy half. The hard half is deciding *which events become associations*. That is the role of the dopamine teaching signal in the fly mushroom body: the KC→MBON synapses change only when a DAN reports a reinforcing event.

The project's own objective allows "legitimate environmental feedback". An answer or teaching marker supplied by the environment, such as graded answers in a task interface, is the fly-consistent solution. It is not a label leak, provided it marks *when* to learn and not *what* to answer.

### A3. Representation next steps

1. **Environmental teaching channel.**
   - Add a per-byte binary "teach" signal from the environment. It is on for answer bytes of task records and off for prose and syntax.
   - Only the association store writes when it is on. The predictor learns every byte.
   - Arms: teach-gated; random-gated at the same rate; all-byte.
   - **Pass:** the shift and wrapper families stay ≥90% with retention ≥90% at load 256; random-gated stays near the all-byte level.
   - This is the oracle row above turned into a legitimate interface. It needs an owner decision that such a signal is allowed.
2. **If a teaching channel is not allowed:**
   - Test *recurrence-gated* writes: write when the same n-gram context recurs with the same following byte across separated occurrences. This uses the V39 TRACE-CORR idea, but as a gate on a superposed store, not as a slot read.
   - **Falsifier:** no better than random writes at a matched rate. In that case, close label-free allocation for this substrate.
3. **Capacity cost of the both-code:** rerun the capacity grid with the both front end, since position-free features add overlap between different keys (0.18 vs 0.14).
4. **Natural text:** embed fact records inside prose and repeat A1.

## Part B — Generalization: never-taught relations from locally learned structure

### B1. The question

- In the archive, the shared NLMS head on fixed codes transferred *rank* relations (77.5%) but failed *cyclic* ones: 51% on withheld pairs (V9.10D).
- Hypothesis: transfer needs (i) item representations that encode the *structure items occur in*, learned locally from experience, and (ii) a *role conjunction* (first-argument features × second-argument features) read by a shared local head.

### B2. Setup

**Items and experience:**
- 12 arbitrary symbols.
- The background stream shows them in cyclic successor order: runs along a cycle with random restarts. This is like days of the week.
- Item representation: a successor representation M learned by a **local TD(0)** rule, `M[x] += α(onehot(x) + γ·M[next] − M[x])`.

**Relation task (never present in the stream):**
- "x beats y" if y is 1–5 steps ahead of x on the cycle. This is a cyclic tournament.
- It is taught only through ±1 feedback on a subset of pairs.
- Learner: one online normalized-LMS head.

**Feature arms:**
- `lookup`: a pair indicator.
- `rank`: score(x) − score(y), as in V9.10D.
- `concat`: [M(x), M(y)].
- `conj`: the outer product M(x)⊗M(y).
- `kc`: a fixed random sparse expansion of [M(x), M(y)], 2,000 units with 100 active. This is a fly-like KC conjunction with no explicit products.
- Controls: `*_shuffledSR` arms, where M is learned from a stream following a *different* cycle (the same statistics, the wrong structure).

### B3. Results (10 seeds; held-out accuracy, with the minimum across seeds in brackets)

| features | random 50% of pairs withheld | **whole distances withheld** (d=2,10 never taught) | **one item never taught** in any pair |
|---|---|---|---|
| rank (V9.10D-style) | 35.5% | 52.5% | 26.5% |
| concat | 37.0% | 49.2% | 38.0% |
| **conj (SR⊗SR)** | **97.5%** [91.7] | **100%** [100] | **100%** [100] |
| **kc (sparse expansion)** | **85.2%** [73.3] | **100%** [100] | **91.5%** [85] |
| conj, shuffled-structure SR | 38.8% | 53.3% | 34.0% |
| kc, shuffled-structure SR | 41.8% | 47.5% | 42.5% |
| lookup | chance (no information on withheld pairs) | — | — |

A sanity task with a linear order gives the expected result: the rank head transfers (86.8%) and so does conj (98.2%).

### B4. What this means

- **Cyclic transfer worked** under the strict holdouts: a whole relation distance withheld, and an item never taught in any pair. Rank and concat heads stay at or below chance; the shuffled-structure controls are at chance.
- The ingredients are all local and allowed:
  - a TD-learned successor map from unlabelled experience;
  - a fixed conjunction (KC-like sparse expansion works without explicit products);
  - an NLMS head trained on sparse feedback.
- **Mechanism:** the successor map of a cycle contains circular, Fourier-like position features. The cyclic relation sign(sin(θ_y − θ_x)) is *bilinear* in those features. A role conjunction makes it linear for the head.
- **What V9.10D lacked** was the **representation**, structure learned from the stream, not a better writer. Representation and generalization are the same problem seen from two sides: generalization is free when the code factorizes the relevant structure.

### B5. Limits (important)

- The structure (cycle order) was presented directly in a clean symbol stream. The relation must be a function of that structure. Real tasks need the right structure to be discoverable from bytes.
- Items are abstract indices, not byte strings, and answers are ±1 signs. This is not E1/E3 own byte/EOS generation.
- The relation head is trained once. Persistence through later learning was not tested.
- There is no shortcut ladder beyond lookup, rank, concat and shuffled-structure controls.

### B6. Generalization next steps

1. **Move B into bytes.**
   - Items become byte tokens in the stream: letters, digits, words.
   - Learn the successor map from the actual byte stream with the same TD rule over the KC code.
   - Pose relations as text records, e.g. `cmp:x,y=` followed by the answer byte. Score the learner's own answer byte plus EOS.
   - Keep the whole-distance and never-taught-item holdouts.
2. **Persistence:**
   - Learn relation 1, then relation 2 on the same items. For example: cyclic "ahead-of", then "same parity".
   - Measure retention of relation 1, transfer on both, and cross-talk. Use the Part A write-allocation result: the head writes only on taught events.
3. **Toward arithmetic (count-on):**
   - Digits 0–9 in successor order give a successor map, as in B.
   - "a+b" is b successor steps from a. The successor map with γ captures multi-step reachability.
   - Test whether a conjunction of SR(a) with a role code for b, read by an NLMS head, transfers to never-taught (a, b) pairs and orientations.
   - First run a positive control (a non-native reference at the same data budget), per the E3 skill.
   - **Falsifier:** at chance on whole-orbit holdouts. Then stage-wise composition (chained learners) is the next step.
4. **Shortcut ladder:** operand-marginal, nearest-neighbour, frequency and constant baselines on every new task, plus sealed final sets before any E3 claim.

## Part C — How the stages now fit together

| Stage | Mechanism with evidence | Remaining blocker |
|---|---|---|
| Memorization | Fixed sparse superposed store; capacity grows with N (previous session) | Size contract; quantized storage |
| Representation | Position-tolerant fixed n-gram + lag code → full shift/wrapper transfer **when writes are restricted to answer events** | Legitimate write allocation (a teaching channel, or a label-free gate yet to be found) |
| Generalization | Locally learned successor structure + role conjunction + NLMS head → cyclic transfer under whole-distance and novel-item holdouts | Discovering structure from bytes; own byte/EOS outputs; persistence across relations |

One reference learner covers all three stages. A predictor learns all bytes. A sparse KC code is built from a lag + n-gram front end and from locally learned successor features. A teach-gated association store and a relational NLMS head read that code.

**Owner decisions needed:**
1. Is an environmental "teach/answer" marker an allowed signal? It is fly-consistent (DAN gating), and it is the decisive question for representation.
2. Authorize the byte version of Part B.
3. Authorize the capacity grid with the both front end.

## Confidence and gaps

- **Medium-high:** the representation decomposition (position binding, then write allocation). The effects are all-or-none (0% vs 100%) but come from 1 seed and 16 probe keys.
- **Medium:** cyclic transfer from successor representation plus conjunction. It holds across 10 seeds and two strict holdouts with clear controls, but only on an idealized symbolic stream.
- **Not tested:** natural text, own-output scoring, persistence of relational knowledge, arithmetic.
