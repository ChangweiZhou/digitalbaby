# V156 — decision feasibility and native margin dynamics

25 October 2026. **Design only. No model, solver, diagnostic continuation, three-cycle exercise or GitHub publication has been run or authorized by this delivery.** V153 belongs to Claude's text diagnostic; V154 remains completed with no established unseen-addition improvement. This serial identifies the next proposed diagnostic, not a new core.

The goal remains **retained complete own-byte/EOS answers to unseen addition, with fewer total training samples and less actual compute**. Keep gradual warmup, local candidate updates and the native Full151/R_center lineage. There is no arithmetic parser, digit-value feature, carry rule, supplied relation, answer-length signal, class mask or forced EOS. Attention, Transformers and ELM replacements remain excluded. Expected answer bytes remain permissible feedback during warmup.

The attached argument is useful, but its two questions need narrower definitions: **can a declared frozen-tap readout express the taught decisions, and what happens to decisive margins through actual native learning?** Neither question alone establishes native representability or arithmetic generalization. V156 answers those questions before selecting one intervention.

**Latest-source update and numbering.** Claude's branch now includes the completed V155 text headroom check and a proposed V155 local-key-learning design. This proposal is therefore **V156**, not another V155. Both are pinned at [2501683d](https://github.com/ChangweiZhou/digitalbaby/commit/2501683d4867d2111a004f060edd28aaee67ffb4); the consolidated branch still holds V154. The headroom check reports held text BPS **2.963** for the frozen KC linear readout, **2.699** for a dense learned trace representation, **2.625** for an explicit-four-symbol reference and **2.606** for PPM-4. That supports a best-found representation improvement on one text, and Claude has withdrawn the immediate class-bias recommendation. It does **not** prove that every output-side readout is capped at 2.963, counting cannot be beaten at 40 KB, or the native sparse wiring can learn the dense reference. Two linear fits were not formally converged; the references differ in representation, optimization and size. The 0.074-BPS trace/reference difference is not a measured information-loss bound. Lane F concerns finite taught decisions, not a BPS ceiling; Lane M concerns actual native writes and retention, which Claude's text study excludes. Neither repeats that headroom experiment.

## 4. Lane F: finite decision feasibility rather than fitted BPS

Let Φ contain the saved normalized OBS row for each OLD/NEW correct prefix and y its actually observed next byte/EOS. Filter rows by OLD/NEW IDs before any solver work; discard validation rows. There are 128 records and at most 384 target rows per front/world, with 5,177 feature columns. Keep every one of the 257 output classes as a possible rival.

With the unchanged codebook C, define `P=I−11ᵀ/16` and `A=CP/4`. Test exactly these nested families:

| Family | Logits | Explicit offsets |
|---|---|---|
| C0 | `A U φ` | None |
| CQ | `A U φ + b` | One unrestricted 257-class bias |
| FQ | `W φ + b` | Same 257-class bias |

Do not add an extra latent intercept to C0; it would change the V154 comparison. In CQ, any latent intercept is already subsumed by b. C0 ⊂ CQ ⊂ FQ, so a smaller-family witness may be embedded and independently verified in the larger families. Those checks are not independent discoveries or necessarily twelve separate optimizations.

For each required position i, require

`(A[y_i]−A[k]) U φ_i + b[y_i]−b[k] ≥ 1`, for every `k ≠ y_i`,

with b absent for C0; FQ uses `(W[y_i]−W[k])φ_i` instead. Margin one is a scale convention for unrestricted finite parameters, not an empirical accuracy threshold. Use no regularization, norm cap, fitted temperature, observed-class grouping, validation-selected solution or answer mask.

### Bounded solution and certificate policy

1. First try one constructive interpolation solve per feature case. V154 qualified a strict C16 winner for every output class. If Φ has full row rank, choose one winning value vector per target and solve `Φ Uᵀ=V`; this can make even C0 feasible. A numerical solve is only a witness candidate: independently check all actual inequalities. Numerical rank truncation or solver failure is never an infeasibility proof.
2. If no verified witness is obtained, use a deterministic sparse constraint-generation feasibility LP for the registered families, with all rivals checked after each solve. Remove only exactly zero feature columns. Never materialize a giant dense constraint matrix. Allow at most 64 separation scans and 5,000 total solver iterations per family/case, at most 256 new violated constraints per scan, with class/row index tie-breaking. Each cell has at most 60 CPU seconds; Lane F has 900 CPU seconds shared across construction, solving and verification. Limits stop a case as `UNRESOLVED`, without widening it.
3. A **positive witness** needs finite stored parameters and independently verified margins against every rival. A strictly positive witness may first be rescaled by its certified minimum margin; then independently verify the stored, rescaled parameters satisfy every stated unit-margin inequality. Use an outward-rounded/error-bounded dot-product check treating saved floats as their exact stored values. If numerical error prevents verification, report unresolved. Report witness norms, smallest verified margin and conditioning diagnostics without turning them into arbitrary impossibility thresholds.
4. **Infeasibility** requires an independently checked certificate. For `Dθ ≥ 1`, a Farkas witness has `λ≥0`, `Dᵀλ=0`, `1ᵀλ>0`. Approximate zero residual is insufficient when θ is unbounded. Require exact rational verification/reconstruction or another sound proof; otherwise retain `UNRESOLVED`. Identical feature rows with incompatible labels offer a simple certificate, but V154 did not find that case.

A finite witness can be almost automatic interpolation when the feature dimension exceeds the number of prefixes. It says nothing about efficient discovery, native-store reachability, retention or unseen arithmetic. Conversely, certified failure of all tested linear families is not proof of destroyed information or failure of every nonlinear decoder.

### Complete taught-sequence witness check

For each feasible family/case, run the witness only as an evaluator on all 128 taught records, at most **1,536 read-only witness generation queries** overall. Use the unchanged untaught encoder, identical prospective read time, the same feature normalization, independent resets, all 257 legal classes, lowest-index argmax ties, four decision opportunities and its own EOS. Feed only the witness's actual generated prefix; never look up the next feature by an expected answer. Expected bytes are available only to the scorer.

Correct decisions at every correct prefix imply correct greedy completion by induction **only if those prefix states match**. Require regenerated normalized features to match the cached correct-prefix features bitwise, or independently bound the feature discrepancy tightly enough to preserve every certified decision margin. Matching outputs alone does not qualify feature parity. Verify that interface and actual rollouts. A strict cached teacher-prefix witness with failed parity or rollout is an interface/unresolved result, not a native learning failure. The witness is never an E3 baseline or a replacement memory.

## 5. Lane M: track finite native margins through competing writes

### Panel and new continuation

For each world, rank its 64 NEW record IDs by `SHA256("V156|"+world+"|margin-order|"+record_id)` with bytewise digest order and record-ID tie-breaking. Select the first **16**, independent of targets, correctness, margins or held outcomes. Use this same order for both fronts. Lock the IDs and bytes before querying any selected model.

The query panel is **all 64 OLD plus those 16 NEW records: 80 records per state**. Including all OLD avoids retrospectively choosing remembered examples or accidentally missing every acquired distinction. Analyze the initially-correct **OLD** subset as a conditional retention diagnostic; an empty subset means retention is unmeasurable for that start, not a measured preservation failure. Do not resample. Report NEW first acquisition and subsequent reversals separately from initially lucky NEW answers.

Start the live trajectory from each actual OLD_W checkpoint. Its gradual warmup has already occurred in V154; preserve n and all inherited state. This lane concerns later interference and NEW learning. It does **not** study birth-to-collapse dynamics or prove what happens during early warmup. Do not reset a trained counter, artificially saturate warmup, or call this a new from-scratch training comparison.

Use the exact N_2B command, `a=0.2 s(n) P Cᵀ(p−e_y)/4`, with `s(n)=1/16+(15/16)min(n/1024,1)`. q remains zero. Before every real target, predict, then reveal the actual expected byte/EOS. Model guesses are never external feedback. Keep the existing API bound; an invalid command fails the case instead of being clipped or retuned.

### Three matched forks per observed record

At actual parent S_t, construct:

- `S_t^a`: execute the full prompt/reply/EOS record with the unchanged native local teaching;
- `S_t^0`: execute identical bytes, timing, observations and counter advances with writes inhibited;
- `S_t^idle`: advance native time only by exactly the elapsed duration of that record, with no sensory observations or teaching.

Only `S_t^a` becomes S_(t+1). The other forks are single-record counterfactuals, not independent lives or persistent no-write histories. Idle state does not acquire observations or pretend its warmup counter advanced; n affects no read here. Use `FastMemory.rest(idle, actual_end.time - parent.time)` or a qualified equivalent for matched idle **seconds**: `Native.rest(steps)` already multiplies by DELTA, so passing seconds to it would double-convert time. The separate final delay is `Native.rest(128)`, meaning 128 byte steps. Keep that delay probe separate from matched event timing.

At every required correct prefix i on the fixed panel, save all 257 logits/log-probabilities, target, strongest rival, EOS contrast and clipping indicators. Use one fixed read function from a fresh clone, preserving native prompt preparation, fresh adaptation, rest by DELTA and independent own/teacher-forced continuations. No read may mutate its parent state.

Define `m_i(S)=z_y(S)−max_{k≠y} z_k(S)`. Then record:

`I_i = m_i(S_t^idle) − m_i(S_t)`

`O_i = m_i(S_t^0) − m_i(S_t^idle)`

`W_i = m_i(S_t^a) − m_i(S_t^0)`.

The identity `I_i+O_i+W_i=m_i(S_(t+1))−m_i(S_t)` telescopes exactly over the actual continuation. I is a matched idle counterfactual; O is the additional observed-event effect relative to that chosen idle fork; W is the full-record teaching effect. This attribution depends on the declared order and reference, includes interactions, and is not a unique decomposition of a biological mechanism. Report the arithmetic residual and uncertainty, not an outcome-selected fit.

Classify W as **same-record** or **other-record** teaching using raw record IDs, never answer equality, commutativity or arithmetic similarity. Full-record W contains all within-record updates and their interactions; it is not a single-synapse derivative. The signed store transition is affine in a coefficient at fixed state, but native expression clips and the strongest rival can switch. Therefore values, loss and margins need not be globally affine.

Report complete own-byte/EOS answers alongside the margins. Track first-payload, continuation and true-EOS errors, correct-to-incorrect crossings, recoveries, CAP and persistent loss. A correct first byte, a positive margin at one position or a better BPS cannot replace complete answers.

### Endpoint and shared-output diagnostics

The baseline queries on the four OLD_W states are reused for the continuation. Query the four archived final W states once on the same panel as a separate endpoint inventory; they are not endpoints of the new continuation. Compare saved outputs to V154 records to qualify unchanged state/read handling.

At verified q=0 states, form a **panel-dependent common logit vector** from the 80 first-answer-prefix contexts with equal record weights. Write each logit vector as common plus residual, and decompose each fixed target-versus-EOS contrast exactly. Also report every true EOS decision, so suppressing a common EOS component cannot masquerade as complete-answer recovery.

This measures shared output structure; it does not identify a literal learned prior parameter or its original time of acquisition. No common-vector subtraction is fed to the native policy, and no new ablated own-prefix rollouts are added. A prior-plus-residual candidate remains a future hypothesis, not the default remedy.
