# Generic byte input and output engineering acceptance

**Verdict: accept the bounded engineering IO baseline.** All payload bytes, variable-length stream admission, memory-driven autoregressive answers and model-selected EOS work in the complete verification set. The result is E0 plus E1 acquisition and retention, not rule generalisation, pretraining quality or Q&A competence.

## What changed

The interface has no `a+b=y` parser, restricted digit alphabet, newline reset or scalar-to-digit answer renderer. One fixed-size vector-valued plastic bank supplies probabilities over 256 bytes and a separate EOS. Its pre-arrival context contains ordered raw bytes and explicit sequence/reply framing. Actual observations supply learning targets. Own generated bytes advance working context without persistent updates.

The implementation is a new engineered IO reference. It does not claim an unchanged Full151 acquired these abilities or that the published addition learner has been converted into a general language learner. The existing addition sources and results retain their original scope.

## Complete test results

| Verification | Result |
| --- | --- |
| Unit tests | 15 passed |
| Independent adversarial checks | 10 passed |
| Fresh engineering fixtures | 8 groups, 256 distinct taught context-answer sequences |
| Initial OLD exact payload plus selected EOS | 128/128 |
| Retained OLD after idle, NEW learning and further idle | 128/128 |
| NEW exact payload plus selected EOS | 128/128 |
| Matched no-write OLD at final | 0/128 |
| Erased learned bank OLD at final | 0/128 |
| Total scored sequence episodes, including controls | 1024 |

Each group taught 16 OLD sequences, then 16 disjoint NEW sequences, at eight fixed exposures per cohort. Prompt lengths range from zero to 129 bytes; answer lengths range from zero to 256 bytes. Each cohort contains a complete 256-byte binary answer. Random answers include zero bytes, LF and arbitrary binary. Independent tests additionally include UTF-8 answers, empty answers, swapped-order contexts, identical final four bytes with different earlier bytes, learned stop at zero/exact caps, truncated continuation, context overflow, strided byte views and a cold-process checkpoint.

Testing receives only the prompt and the same explicit reply-start framing. Every answer byte and EOS comes from the core; the fixed generation cap is 512 for every fixture, without passing answer length. No inference learning occurs. Disabled-write histories see the same payloads and boundaries as writing histories. Erasure removes the learned weights before final retrieval. Inference and no-write learned-state checks passed.

The paired histories received 369,536 payload bytes and 373,632 observed byte/EOS targets. The writing histories performed 186,816 plastic updates; disabled histories performed zero. These are engineering exposure counts, not new independent scientific lives. The locked complete acceptance ran in 15.26 seconds on this host. Unit and independent test fixtures are separate from those eight groups.

## Scope and cost

The 4096-event rolling context accepts longer streams and explicitly records discarded-prefix events. The bank has 4096 cells, 16 active contacts and 257 output categories. Fixed arrays occupy 4,218,880 bytes, excluding Python object/metadata overhead. Production work is `O(C + kV)`: ordered context hashing plus active-row categorical reading/writing. Whole-bank digests and checkpoint copies are audit operations, not part of each event.

The two idle gaps are simulated 86,400-second advances. This engineered bank intentionally has no time decay; idle stability is not evidence of Full151 consolidation. The meaningful interference check is retention after actual NEW updates, which passed at this declared load. Capacity beyond the tested 32 sequences per group and generation beyond the demonstrated lengths remain unspecified.

An exact-context lookup countermodel can pass these taught sequences. The fixed hash is itself lookup-like and does not preserve semantic similarity by design. The result therefore completes the bounded IO engineering stage, without establishing E2/E3, natural-language understanding or unlimited memory. Previous arithmetic E3 cannot be attributed to this path without its own task test.
