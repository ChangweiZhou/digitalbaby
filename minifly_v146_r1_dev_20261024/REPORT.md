# V146-R1 three-cycle exercise

**Outcome: REFERENCE_PIPELINE_NOT_READY.** Three bounded development cycles were executed; the full 24-fit readiness menu failed its joint acquisition/held-output criterion. Quantity/counting map training therefore did not start. Main worlds and native integration were not run.

## What was executed

Cycle 1 implemented the generic SOM/association equations, separate identity/map traces, canonical PN/KC sparse expansion, nine opponent delta naming pairs and fixed-feedback feature writes. It verified all 256 identity-byte traces against the parent, top-k equality against the native selector, generic map recall, and positive-scaling invariance. Thirty-two synthetic map events and ten synthetic naming targets are technical fixtures, not trained quantity/counting experience.

Cycle 2 ran the complete declared readiness menu: D1/D2 × SYMBOL/ORACLE × two naming rates × three shrink settings, each through 1,024 passes. All retain the gradual 1/16-to-1 warmup; shrink starts after pass256 at five-pass intervals. There are no exact-gradient learners. ORACLE is an evaluator-only supplied prior, never a candidate. The surrogate naming store is not native Full151 memory.

Cycle 3 tested a fresh whole-pass checkpoint against an uninterrupted continuation, audited all saved own-byte/EOS outcomes, verified the source hashes and rejected five corrupted-result fixtures. It also repaired the readiness reducer to use nearest-neighbor controls under the actual augmented trace rather than the initial identity-only control. No trained histories were replayed for that correction. This is an author artifact audit, not independent scientific confirmation.

Each held score averages both orientations within each of 15 never-reinforced unordered relations. Success requires the entire generated payload plus the learner’s own EOS within eight decisions. Wrong, invalid and truncated generations fail. No expected prefix or answer length was supplied at evaluation.

No selected oracle setting passed >=90% taught accuracy and >=0.20 held advantage over the strongest actual-interface shortcut in both development worlds. That means this local combination/expansion/naming recipe was not sufficiently reliable to test learned grounding as specified. It does not show that generic map learning, all local rules or addition itself is impossible. A high held score with poor taught acquisition is not proof of a learned arithmetic procedure.

## Cost and scope

The run incurred **1,794,267 addition record applications and 4,411,932 observed answer/EOS target tokens**, including the three paid checkpoint-fixture passes. In addition, 32 generic map fixture events and ten naming fixture targets were executed. There were **zero Q/C curriculum records** and zero main scientific jobs.

The outer supervisor measured 699.203 child CPU-seconds including learner imports and 708.752 wall-seconds. The separate reduction measured 0.878 process CPU-seconds including its imports. Tool-driven source restoration, document preparation and supervisor self-overhead are not fully measured; this is not a complete project all-in efficiency figure. No sample/compute efficiency gain is claimed.

The readiness scalar rates were fixed before results. The machine MANIFEST is a later transcription of the already source-locked menu, not an independently precommitted manifest. Runtime source and the canonical graph asset were locked; this exercise does not certify the full production restoration/late-loaded asset closure. Main scheduling remains unqualified.

The checkpoint fixture covers learned state at a whole-pass boundary. It does not qualify cross-process recovery, every interrupted record cursor, or the full shrink/rest counter across the anchor. The ten-arm D4 rehearsal was not run because readiness failed. These limits must not be relabeled as main-run readiness.

## Revision and next decision

See REVISED_DESIGN.md. Stop the map/downscaling campaign here. If further development is authorized, first distinguish an unstable learned address from a weak naming update using a fresh bounded fixed-address/FROZEN-LAYER diagnostic already motivated by the design. Keep the output endpoint, local rules and warmup. Do not add arithmetic features, backprop, larger grids or another memory stack to rescue the same development result. The biological/grokking narrative remains an untested explanation.
