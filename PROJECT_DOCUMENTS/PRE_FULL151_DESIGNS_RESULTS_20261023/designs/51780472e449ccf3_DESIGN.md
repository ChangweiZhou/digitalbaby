# Step 11: single-store byte-input attribution

This is one bounded diagnostic of the byte encoder → Full151 value-memory interface. It does not test open-ended output, intelligence, or a new memory mechanism. The only manipulated component is the fixed 88-PN input front end: FE0 versus Step 6's FE0+fading-pair code. Both arms use the same V9.2 parent, one native Full151 value store, old/new byte streams, Boolean teaching, clocks, and read-only relative-value scoring. The engineered V9.2 next-byte predictor is retained but never supplies the scored value.

The task is the unchanged V9.8 E3 symbol-class generator. Each world has 12 old reinforced ordered cues on six symbols (144 records); six held-out ordered cues from three *never reinforced* cross-class edges; a day; 72 new records on disjoint symbols; another day. W and N see identical streams and teacher bits; only W's old native writes are enabled. Both write during the later cohort. A raw or canonicalized exact-pair table has no answer on the held-out edges. Symbol/position frequencies are balanced; a one-bit class assignment learned from the old records can solve the relation. Thus a positive result is limited within-family E3, not arithmetic, autonomous action, or general reasoning. The read-only scorer presents both orientations separately on copies and compares their native values; it is an evaluator, not a model-emitted choice.

Fresh, paired IDs are technical 12400, pilot 12401–12408, confirmation 12501–12532. No previous world is rerun. Source and configuration hashes are locked before technical execution. The pilot computes **only trained** old-pair scores; confirmation is permitted only if, in both encoder arms, mean W trained choice is at least 0.80 at old end and 0.70 at final, final W−N trained choice is at least 0.10, and W and N both reach 0.65 on new taught pairs at new end. The pilot is excluded from confirmation. If a gate fails, stop without examining pilot held-out values or changing the design.

The sole primary diagnostic is the mean over 32 worlds of

`D_s = (W−N final held-out choice)_PAIR − (W−N final held-out choice)_FE0`.

A two-sided 95% Student-t interval uses worlds, not the three pairs or bytes, as independent units. Report both encoder arms' W, N, W−N, old-end held-out, trained controls, and signed-margin contrasts descriptively. Positive `D` supports improved reuse by the pair code in this single-store interface; negative `D` supports loss of reuse; an interval crossing zero is unresolved. No post-hoc sample increase, architecture changes, alternative scoring, or optional stopping. This 32-world diagnostic does not replace the earlier 64-world V9.9A confirmation; its main role is paired attribution. There is no hard absolute-success gate for the new pair code.

The implementation must preserve the extra fading-pair trace during forks and read-only probes. The inherited V9.2 snapshot/restore and V9.8 query reconstruct FE0 and would silently erase the new front end. Technical checks compare the new FE0 query exactly against V9.8's existing query on the same loaded parent, check pair-front-end separation and clone independence, verify identical predictor states and W/N birth states, and verify read-only probes leave live states unchanged. Per-world receipts retain source digests, all pair margins, write counts, predictor equality, and clock checks. An independent reducer verifies receipts and summaries without rerunning learner trajectories.

The run stops on a technical or scientific execution error and records the failure; it does not generate replacement worlds. A scientific failure is a result, not a reason to retry. The full run is small (one technical world, eight pilot worlds, 32 paired confirmation worlds) and does not launch the parked factorial, role features, capacity curve, or evolution search.
