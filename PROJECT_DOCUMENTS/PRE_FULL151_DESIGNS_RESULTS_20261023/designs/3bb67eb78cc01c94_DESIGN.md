# Visible-context byte → Full151 bridge

This is an engineering bridge deliverable, not a mechanism-discovery stage. Its
single objective is reliable **E1 taught-byte recall and E2 changed-presentation
retrieval** from the model's own first output byte. It does not test arithmetic,
E3 transfer, teacher-free learning, or a persistent learning core.

## Candidate and fixed comparison

The unchanged Full151 checkpoint, four native fast/slow output stores, opponent
teaching, output argmax, record clock, 16 arbitrary-label `a+b=` facts, and 12
interleaved exposures per fact come from the audited learned-h v2 assay. The
new candidate replaces only the associative input address with a fixed,
label-free receptor sketch of the four most recent **non-space bytes on the
current line**. It is updated byte by byte and cleared by newline; the teacher
byte cannot enter the pending address used for teaching. No answer labels,
arithmetic, world identity, or test outcomes enter the receptor hash. FE0 and
the existing fading-pair route are concurrent same-world controls.

This is deliberately a strong, engineered content address. It makes the
canonical `a+b=`, the untaught `a +b=` spacing change, and the untaught fixed-Q
prefix share a four-visible-byte suffix by construction. Consequently even a
canonicalized exact-key table can solve these tasks: a pass means a bounded
byte-input/Full151/output bridge, **not** spontaneous abstraction or E3.

The scored response is emitted after `=` and before the answer byte arrives.
The W and N branches receive identical bytes, labels, schedules, and clocks;
only native Full151 plastic writes differ. The pair baseline uses the same
Full151 checkpoint and teaching policy. Pilot worlds and any subsequent
confirmation worlds must be disjoint from all earlier bridge worlds.

## Acceptance and stop rule

Technical integrity checks verify output-before-teacher ordering, equal W/N
sensory state, identical write and query address for an identically rendered
cue, unchanged Full151 birth state, exact no-write control, and a read-only
probe. They are implementation checks, never success endpoints. KC distances
are reported if useful but cannot authorize or reject behavioral claims.

An eight-world development trial checks executable behavior and runtime. If
the implementation is sound, the candidate and thresholds are frozen before
32 new confirmation worlds. The inherited v2 success rule is retained:

- Canonical E1 W accuracy at least 85%, with every cue at least 24/32.
- Each never-taught E2 form W accuracy at least 80%, with every cue at least
  24/32; each paired world-level W−N 95% interval has positive lower bound.
- Report the same-world fading-pair and FE0 results, all per-cue results,
  native channel values, and any failure without replacing worlds or changing
  thresholds.

An E1/E2 pass is the bounded bridge deliverable. It would not promote the
eventual project goal, which requires causally demonstrated E3 reuse after
delay and intervening learning. A failure is reported as a failed bridge
candidate; it does not become an address-only success.
