# Step 13: bounded 16-item byte-memory load test

## Question, scope, and evidence

Can the exact Step-6 FE0+fading-pair input, four native Full151 output stores, byte-derived teacher route, opponent writing rule, and V9.2 checkpoint still recall more than four directly taught byte strings? FE0 is a paired reference. This is an **E1 practical-load diagnostic**, not an E3 transfer test or a promotion to a persistent learning core. The one never-taught spacing form is a descriptive E2 probe only. No model, front-end parameter, teaching rule, or output policy may be tuned from pilot or confirmation outcomes.

The 16 canonical cues are `8 spaces || a+b=` for all ordered pairs `a,b in {0,1,2,3}`. The four answer bytes `0`–`3` are balanced at four cues per byte in each world. Nine assignments are fixed to embed the exact Step-6 A/B/H crowded patterns: `00→0, 01→1, 02→2, 12→3, 11→2, 21→3, 10→1, 20→2, 30→3`. The remaining seven receive a world-seeded shuffled multiset `0,0,0,1,1,2,3`. These labels are an arbitrary byte codebook; even when a few coincide with arithmetic, **this run does not test addition**. Each world uses 12 shuffled blocks containing each cue once: 192 teaching records, 12 exposures per cue, 165 seconds per record, four native writes per W record and zero per N record. The same schedule, labels, bytes, clocks, and teacher calls are used by FE0/PAIR and W/N. The answer byte arrives only *after* the model's choice at `=`.

The unchanged Step-6 spacing transform `7 spaces || a || space || +b=` is never taught. It is scored on a discarded clone at the end, before any variant feedback. A strict exact-key table can solve all canonical E1 items. A fixed whitespace canonicalizer plus an exact-key table could also solve this particular E2 form; neither can justify E3. Labels are balanced and vary across worlds, so an exposure-independent arithmetic, frequency, or answer-default shortcut cannot explain a large paired W−N canonical advantage.

## Locked execution and gates

Technical world **13000** is excluded. The feasibility pilot is exactly worlds **13001–13008**; confirmation, only if the pilot passes, is **13101–13132**. A world is the uncertainty unit. Technical qualification must establish source/checkpoint provenance, exact 16-cue/label/record fixtures, correct birth clones, sensory W/N equality, first choice before teacher, byte-derived teacher route, 768-versus-zero native writes, read-only probes, clock alignment, receipt schema and a noncollision KC census for different-label cues on PAIR at the actual response time. Any technical failure stops before science; any science exception commits a failure receipt and stops, without replacing or rerunning a world.

Pilot feasibility is deliberately coarse and **not included in confirmation**: PAIR W canonical end accuracy at least 75%, PAIR W−N at least +25 percentage points, and each of the four output labels at least 50% under PAIR W. A failed pilot is a reportable `PILOT_STOP`, not permission to revise thresholds or run more worlds.

The confirmation's primary practical-load gate, applied separately to FE0 and PAIR, requires all three: (1) W canonical accuracy at least **85%** over the 32 worlds × 16 cues; (2) every individual cue at least **24/32** correct under W; and (3) the two-sided 95% Student-*t* interval across 32 world-paired canonical W−N differences has lower bound above zero. Zero world variance makes the interval gate unresolved. The preferred sufficient input is FE0 if both routes pass, because it is simpler; PAIR if PAIR alone passes; neither if neither passes. A route's absolute accuracy, per-cue errors, per-label accuracy, W/N baselines, and paired PAIR-minus-FE0 contrast must all be reported regardless of the verdict. The spacing E2 result is **secondary descriptive** and cannot rescue a failed E1 gate.

The 16-item test intentionally increases total records, native writes, and learner time while holding *per-item* teaching dose fixed relative to Step 6. Passing establishes bounded load tolerance. Failing does not isolate address crowding from total-write/time effects. No dual bank, target-only teaching, parameter search, or new retention experiment is launched automatically from this result.
