# W3: causal byte-answer warmup before arithmetic evolution

**Status:** revised experimental protocol; no learner experiment or population run has started. This document replaces the proposed `DESIGN_NEXT.md` for future work. It does not alter V2's frozen search or results. The [hostile audit](../BYTE_ARITH_WARMUP_HOSTILE_AUDIT_20260926/REPORT.md) is the issue list this design must satisfy.

## Question and evidence boundary

Can a MiniFly-derived learner, given raw sequential ASCII questions and a short *post-choice* answer-revealing warmup, improve its **first responses to mathematically new expressions**, retain that improvement when answers stop, and then learn further from unsigned five-band consequences? The immediately runnable scope is the interface check and one-operator arithmetic. Longer two- and four-operation curricula are **separate, conditional designs** after the one-operator result; they cannot silently reuse this confirmation set or thresholds.

The interface check is E0, and its repeated-key teaching control is E1. A causal gain on pair-group-held-out arithmetic can support E3 **within this named one-operator fixture**. It is not yet a persistent-learning-core result: that requires delay, intervening learning, and a causal prior-teaching state control in a later locked experiment. A learned symmetry shortcut is legitimate narrow transfer but is not proof of four-operation competence. An exact-key cache is E1, regardless of its retention.

## Causal information contract

The training life is one serial byte stream. At the start of each question, the learner receives `b'\n' + expression_ascii + b'='` one byte at a time. In the baseline family, the visible newline clears **all** recurrent/sensory working state; only learned weights and optimizer state persist across questions. A proposed persistent slot is a separately named family with its own controls. At `=`, a new engineered decoder emits its **entire first answer** before any feedback. Allowed output is canonical signed ASCII decimal in −128…128, terminated by `;`; `-0`, leading zeros (except `0`), missing terminators, and out-of-range or otherwise invalid strings are errors. The output grammar may constrain syntax, but supplies no arithmetic operation.

Only during warmup, after the first response is logged, the environment sends `b'#' + correct_answer_ascii + b';'` byte by byte through the **same incremental sensory path**. `#` announces an answer span; `;` ends it. There is **no scalar grade in warmup**. This deliberately privileged warmup bootstraps the byte-teaching interface; it is not offered as a natural-fly training protocol. The learner's API receives raw teacher bytes, never `Task.answer`, parsed operands, an AST, a signed error, or a numerical target. The evaluator may read `Task.answer` only *after* the first response to construct the teacher bytes or score that response. A direct numerical-target supervised fit is a separately named privileged capacity control and cannot be counted as byte-teaching success.

For the primary engineered family, save the question representation **at `=` before choice**. The answer decoder's first teacher-token prediction uses exactly this saved state; later token predictions may use only the saved state and **preceding** teacher bytes. The `#` marker and current/future target bytes cannot enter the current prediction. It receives a single bounded update per warmup question from the sum of token cross-entropies, normalized by target length. The gradient updates the trainable byte encoder and the same decoder used for scored answers; the inherited Full151 sensory branch stays fixed. Use AdamW learning rate `0.001`, weight decay `0.0001`, gradient-norm cap `1`, and no more than one optimizer step per taught question for the fixed baseline; a later search may mutate learning rate within a prespecified range. The teacher span is also fed through the incremental sensory path, with the inherited Full151 plasticity frozen (`learn=False`). AdamW moments persist during warmup, then are frozen; grade-only learning uses the explicitly specified direct policy-gradient step on the **same trainable weights**, without a new optimizer or hidden moment reset. Both optimizer and trainable model state are in every checkpoint/clone. A separate oracle output head cannot take credit.

After warmup, 128 distinct questions provide **only** the locked V2 consequence, computed on the first complete response: exact `0`; absolute errors `1–8 → −1`, `9–24 → −2`, `25–48 → −3`, `49–96 → −4`, `≥97 → −5`; invalid output → `−5`. The evaluator supplies no answer bytes and no error direction. The initial grade-only learning rule is a bounded sequence-policy update on the log probability of the emitted answer bytes, multiplied by grade minus a pre-choice moving baseline (initialized to `−4`, EMA coefficient `0.9`, learning rate `0.0001`, gradient-norm cap `1`). Sample output at temperature `1` during graded training and use deterministic decoding for read-only tests. The baseline is updated **after** the weight step. This is a specified engineering rule, not a biological claim or a guarantee that five-band feedback suffices. Any replacement rule is a new arm with its own lock. Scored probes receive neither answer bytes nor grades.

The existing V2 `observe`/`choose`/`feedback` API cannot express this transcript; implement a new incremental `feed_byte`/`choose_answer`/`learn_from_teacher_bytes`/`learn_from_grade` interface rather than inserting a target into V2's old scalar feedback. Partition the full state explicitly into expression-local state (cleared by the visible newline) and cross-question state (decoder weights, optimizer moments, optional gated slots, clock policy, and RNG). The baseline has no persistent sensory/native or recurrent trace. All Full151 native plasticity is frozen in every arm. The Full151 FE0→PN→KC path remains available as a sensory arm; its native value writer is not the source of the new answer. Compare raw-byte-only, KC-only, and KC+raw-byte routes with matched trainable parameter budgets (within 5%) and identical visible histories. Report inherited fixed state separately. A combined-route benefit belongs to Full151 sensory structure only if KC removal at both training and readout materially reduces it; never attribute a new decoder to the native writer.

## Named fixture and non-recitation split

`W3-HARD1` is **new**, not the old V1/V2 Stage-1 generator. Each expression is `a op b` with decimal ASCII operands `a,b` in `0…63` and one ASCII operator from `{+, -, *, /}`; evaluation uses standard integer arithmetic, and division is exact with a quotient of at least two. Every result lies in `−128…128`, matching the response range. Spaces may occur between complete tokens, never inside a numeral; different whitespace renderings share one canonical expression identity. Within each operator, the unordered operand pair `{a,b}` is the exclusion unit across all phases, so neither `a op b` nor its reversal can be taught when that pair is scored. Use at most one orientation per pair in any life.

Reserve **globally**, before drawing training worlds, one hard qualification roster of 16 questions/operator and one hard final roster of 32/operator. “Hard” excludes zero answers, zero/equal operands, and operands `1` in multiplication or division. In each scored roster, no numerical answer occurs more than twice **within an operator**; subtraction is balanced by answer sign (8/8 in qualification, 16/16 in final). Freeze each scored item as an **ordered expression plus exact byte rendering and answer**; every evaluated life sees the same scored bytes. Reversing subtraction changes its answer, and reversing division can make the task invalid. Then, per life, draw 96 warmup, 32 grade-only, and 16 development questions/operator from remaining pair groups: **384 + 128 + 64 + 64 + 128 = 768** questions total per life. At least 64 of 96 multiplication and division warmup questions and 24 of their 32 grade-only questions must be hard; subtraction warmup and grade-only are each half positive and half negative. Randomize training as four-question blocks with one question of each operator, so every checkpoint has equal operator exposure. Only training/development spacing, orientation within a valid pair group, and group draws vary across worlds. Operand pairs may recur under a *different* operator; this is reported as an **operator–pair** holdout, not a wholly novel operand set.

The [support feasibility receipt](FIXTURE_FEASIBILITY.json) and [checker](fixture_feasibility.py) are illustrative, not the final sealed roster. For the widened result bound the unordered-pair supports are `+ 2080`, `− 2080`, `× 326`, `÷ 210`; hard supports are `1953`, `1953`, `189`, `148`. A single global hard qualification+final reserve plus eight development worlds can meet the quotas, but division remains the limiting finite family: after reserving 48 hard pair groups, only 100 hard division groups remain, and each life needs at least 88 of them in warmup plus grade-only training. New worlds and generations therefore resample a small distribution; they are not independent new arithmetic facts. Replicated lives on the *same* final 128 questions estimate learner variability, **not 8 independent sets of new mathematical facts**. A future final confirmation after this roster has been viewed requires a new task domain or a separately reserved, honestly limited roster. The original V2 generator remains a secondary named comparison; do not merge its scores with `W3-HARD1`.

Keep three evidence partitions: development questions may be scored repeatedly at warmup checkpoints `0, 32, 96, 192, 384` and after `0, 8, 32, 128` grade-only experiences; qualification is viewed once for a frozen proposed model, then becomes development evidence; final is used only by one frozen analysis job after architecture, genes, training rule, thresholds, and code are locked. The final job may score the **two preregistered post-warmup/post-grade checkpoints** on the same roster; this is one planned use, not two independent confirmations. For the primary score, clone the **entire life state separately for each held-out item**, feed one question, read the first answer, and discard the clone. Hash the live training state before and after the probe batch to prove that no probe altered it. A sequential no-feedback test stream is a separately reported context-sensitivity diagnostic. Before search, a fixture-lock process writes only a development allowlist and the hashes of separate qualification/final artifacts into search-visible inputs. The qualification/final seed and exact IDs are not passed to the search process; opening either artifact consumes its one-use status. Because arithmetic answers are computable, this is a procedural analysis firewall, not cryptographic secrecy. If final fails, report failure and do not repair against that roster.

## Mandatory controls and separate endpoints

At every claimed warmup gain, compare the same genome and life seed under: true answer bytes with plasticity; **identical** answer bytes/timing but all teacher-dependent **cross-question** writes off; answer bytes permuted among same-operator, same-byte-length warmup episodes with their histogram preserved and each assigned answer different from that question's true answer; and a zero-warmup/zero-shot state. The fixture-lock step must construct an explicit wrong-answer derangement for **every** warmup bucket or reject the seed. The no-write arm still processes each teacher byte transiently, but at the next newline its cross-question state must be invariant to a same-length substitution of those bytes. In the baseline this means decoder weights and optimizer moments are unchanged by teacher bytes and all recurrent/sensory state is cleared; in a gated-slot family the slot is also held fixed. Only target-independent event timing/RNG advance may remain. Assert this with a differential state test. All arms see matched question order and first-choice random streams. The zero-shot arm receives matched question exposure but no answer-revealing event. Grade-only continuation forks the *entire* post-warmup learner and sensory state into frozen-learning, true-grade, and grade-shuffled same-histogram arms; all three see identical grade-phase question bytes and outcome timing. The frozen arm receives its own grade but discards it without any cross-question write; the true-grade arm receives its own on-policy grade; the shuffled arm receives an exogenous yoke from the reference trajectory, not a grade secretly recomputed from its own answer. Action stochasticity and grade schedules are logged.

Score constant-zero, exact-string and whitespace-canonical caches, operator-frequency mode, mode-plus-pair-symmetry cache, operand-marginal and raw-byte nearest-neighbor controls trained only on the same warmup examples, and simple zero/identity rules. These **non-compositional shortcuts** define the shortcut threshold and their implementations must be frozen before qualification. A regression given parsed numeric operands and the symbolic parser are privileged comparison/task-validity controls, reported separately and **excluded** from that threshold. Report invalid-output rate, exact first-response accuracy, per-operator exact counts, mean and 90th-percentile absolute error; assign an invalid string a numeric absolute-error sentinel of `257` (larger than the maximum valid error `256`). Also report the warmup learning curve and earliest number of revealed answers achieving each discovery threshold. Every baseline is scored on the **same** hard rosters. Raw expression lists and per-seed trajectories are kept outside the compact result bundle.

Three endpoints must not be collapsed:

1. **Answer-warmup acquisition:** true-answer prior experience causally improves unseen *pair groups* over same-byte no-write, permuted answers, zero-shot, and the strongest registered shortcut. This is the possible E3 finding.
2. **Retention after answer withdrawal:** after the 128 grade-only questions, performance on the warmup-derived relation is compared with a frozen post-warmup clone on the same read-only probe set. A learner that ignores grades may retain; retention alone is not new learning.
3. **Grade-only incremental learning:** true-grade continuation improves on the *same previously unreinforced* probe set relative to both its frozen and grade-shuffled forks. An exact gain in this endpoint cannot be inferred from retaining the warmup score. Report per-operator harm even if total improves.

## Sequential gates; do not spend sealed data early

**Gate 0: interface and learnability.** Unit tests must prove stream-chunk parity, the first choice's invariance to any later teacher-byte substitution, a strictly pre-token teacher prediction, V2 grade boundary values, full-state clone/probe isolation (including sensor clock/native state, both optimizer states, and RNG), no test-side weight update, teacher-byte substitution invariance of *all* persistent state in the no-write arm, and deterministic resume. In each of five worlds draw 16 distinct three-letter ASCII keys independently of 16 distinct two-digit answer strings (`10…99`); the mapping is unavailable to the genotype. An online byte-recording table control must learn all 16 keys solely from the post-choice answer stream and score 16/16. With six answer-revealing exposures/key, the candidate teaching pathway must reach at least 12/16 on first no-feedback probes in 4 of 5 worlds and exceed both permuted-answer and same-byte no-write by at least 8/16. The permuted control uses one cyclic rotation of the 16 unique two-digit labels, fixed across all six exposures/key, so every wrong teacher has the same byte length and no key receives its true answer. This is **E1 interface evidence only**. If it fails, stop and repair the channel or update rule before arithmetic.

**Gate 1: developmental discovery.** Re-evaluate the single selected search leader on three fresh development lives, each with its own 64-question roster. By or before 384 answer revelations require median at least 24/64 exact, median at least 4/16 for **each** operator, median paired gain at least 8/64 over **each** matched no-write and permuted-answer arm, and a score above the strongest registered shortcut with median q90 absolute error no worse than that shortcut. These figures authorize a *single* qualification attempt, not a scientific success claim. Run the numerical-target privilege control alongside it to localize representation versus byte-teaching failure. This gate is checked **after the bounded development search**; if this one leader fails, stop without cycling through runner-up candidates on those worlds or spending qualification/final data.

**Gate 2: qualification.** Freeze one model family, architecture, genome and learning schedule selected only from development. On the separate 64-question qualification roster, evaluate five new life seeds and training rosters; require median 24/64 overall, median 4/16 for **each** operator, and median paired causal/control gain of at least 8/64. Inspect qualification once. If it fails, return to development under a newly named version; the viewed roster cannot later serve as sealed confirmation.

**Gate 3: one-use final confirmation.** On the global 128-question hard roster, test the frozen candidate across eight independent life seeds, including initial trainable weights, training rosters/order, and action RNG, with the **same final items**. Require median life accuracy at least 64/128, median accuracy for **each** operator at least 8/32, and median paired gain of at least 13/128 over each matched no-write, permuted-answer, and strongest nonsymbolic shortcut arm; median q90 absolute error must be at most 32. At least six of eight lives must individually reach 64/128. Evaluate each checkpoint and each counterfactual from full-state clones, keep the training path untouched, and inspect final metrics only after the entire frozen protocol finishes. Report item- and life-level uncertainty separately, without treating repeated lives as additional novel expressions. Passing this gate supports only bounded E3 warmup transfer.

**Grade-only tier.** Independently, after 128 consequence-only questions, require a median gain of at least 7/128 on the hard roster over **both** frozen and shuffled-grade forks, with no operator losing more than 3/32 correct relative to its own post-warmup checkpoint. If warmup passes but this tier fails, record a warmup-trained relation learner and a grade-only learning failure. Do not call that a persistent core or automatically advance to mixed expressions.

## Search, cost, and stopping

Start with the same temporal decoder in **three equal-search route families**: raw byte only, frozen Full151 KC only, and KC+raw byte. A gated-slot or changed-topology family is a **separately locked follow-up**, with the same trainable-parameter cap of 128,000 and explicit state accounting; it does not silently enter W3's confirmation. Gate 0 must pass before any arithmetic population search. Then microbenchmark 8–32 complete individuals for feasibility and run a bounded development search; Gate 1 is the **result** that determines whether qualification is justified, not a prerequisite that would make evolution pointless. Fix genome fields before search: bounded hidden sizes, bounded teacher and grade learning rates, and active-route gain. The genotype contains no scored-answer table or trainable-weight initialization seed. A fixed structural seed may specify inherited sensor wiring, while each life seed independently initializes trainable weights, training roster/order, and action RNG. Learned synaptic weights reset at the start of each life and are **not inherited**. If a later topology family is tried, its mutation must alter actual routing at fixed size, not just relabel neurons.

For any population run, use four workers only after measuring peak resident memory and full life time on this Mac. Lock the exact gene values/mutation kernel in a machine-readable config **after timing-only preflight and before viewing any arithmetic learning score**. Run 16 generations, two fresh matched development lives per candidate per generation, and allocate at most five of the eight hours to search; reserve the rest for controls, qualification, final, and checkpoint overhead. If `t` is measured p95 seconds per complete candidate-world **including its teaching controls**, `w≤4` is the memory-safe worker count, and `F=3` is the fixed number of W3 route families, use the largest `F`-multiple population `P≤2048` satisfying `16 × 2 × P × t / w ≤ 5 hours`; require at least eight candidates per family or stop and redesign a cheaper assay. Do not extrapolate from the standalone GRU probe. Within each family the top 25% on matched development worlds remain parents even below the absolute scientific gate; preserve the best 10% as unchanged elites, mutate/crossover only from those parents, and introduce **no random immigrants**. Re-evaluate parents and offspring on the same new development worlds each generation. Rank first by paired true-answer gain and worst-operator exact, then by total exact and area under the sample-efficiency curve, then by error tail. The absolute qualification threshold controls stage advancement, **not whether a relative-best parent exists**. If the time cap or progress gate fails, checkpoint and report that failure rather than reseeding or calling an unqualified lineage a success.

Archive only `REPORT.md`, aggregate metric and acceptance tables, model/config/source files, tests, a manifest of unchanged parent assets, and any small key figure; target under 10 MB. No datasets, prior archives, caches, or raw per-seed outputs are duplicated.
