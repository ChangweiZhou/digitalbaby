# 2. Why dual anchors are required

The fixed-HASH direct-sum architecture is the strongest current working architecture, but its routing evidence came from a post-FB1 extension rather than an untouched standalone confirmation panel.

A11 therefore freezes two **different kinds of anchors**:

\[
P_0=A11\_B,
\qquad
P_1=A11\_HASH8.
\]

`A11_B` is one deterministic frozen learner.

`A11_HASH8` is a **randomized-at-birth, fixed-for-life keyed learner family** using the exact accepted HASH8 routing/update semantics. This choice matches the historical HASH follow-up, where the address key varied across independent worlds. A11 does **not** reinterpret those prior results as evidence for one globally shared deployment key.

For each A11 organism/base seed, define exactly one router-key identity before any learner state is created. The key is generated by the exact historical key-generation helper under a frozen A11 key namespace; the helper is imported, never reimplemented. The key:

- is fixed for that organism's entire life;
- is identical across `R/P/N` and exception clones in A11-C;
- is identical across all nine \((K,L)\) cells generated by one A11-A base seed;
- is independent of science outcomes, branch, endpoint, grid cell and anchor behavior;
- differs across independent organism/base-seed units according to the frozen key manifest.

Thus the A11-HASH8 estimand averages over the declared birth-key distribution jointly with fresh worlds. It is **not** a certification of one globally fixed hash key. If a future deployment requires one globally shared key, that is a separate confirmation question and is not silently claimed here.

Freeze:

```text
A11_HASH8_KEY_CONTRACT.json
A11_HASH8_KEY_MANIFEST.json
```

The contract records the exact imported helper/source hash, key namespace, organism/base-seed ID, generated key digest, and all branch/grid reuse relationships.

Both anchors see identical exogenous A11 worlds. HASH8's key is learner initialization state, not part of the world and never enters B.

A11 asks whether the **composite HASH8 operation**—birth-keyed stable routing plus eight independent alpha stores plus native B/allocation/feedback dynamics—changes competence and scaling. It does not identify a unique capacity, isolation, load-balance, or routing contribution.

A11 is not required to force a unique overall winner.

# 10. A11-C exact 88-channel support layout

Each world has two categories:

```text
CATEGORY_C
CATEGORY_D
```

with three item cues each:

```text
C1 C2 C3
D1 D2 D3
```

`C3` and `D3` begin untrained.

For CATEGORY_C:

```text
shared support S_C = 2 channels
private P_C1       = 6
private P_C2       = 6
private P_C3       = 6
```

For CATEGORY_D:

```text
shared support S_D = 2 channels
private P_D1       = 6
private P_D2       = 6
private P_D3       = 6
```

All shared/private supports are disjoint across categories.

Each item therefore has:

\[
2+6=8
\]

active channels.

Same-category raw overlap:

\[
2/8=0.25.
\]

These six category cues use:

\[
2+3\cdot6+2+3\cdot6=40
\]

channels.

Create six reference cues:

```text
RC1 RC2 RC3
RD1 RD2 RD3
```

using six mutually disjoint 8-channel supports, also disjoint from the category supports.

They use:

\[
6\cdot8=48
\]

channels.

Total:

\[
40+48=88.
\]

Thus there is no accidental raw-PN overlap beyond the intended 2-channel same-category support.

# 15. Relational-transfer estimands — direction-aware and control-referenced

For held-out item \(j\in\{C3,D3\}\), anchor \(a\in\{B,HASH8\}\), branch \(b\in\{R,P,N\}\), let \(M\) be native actual signed margin, \(F\) fixed-reader signed margin, and \(I\in\{0,1\}\) the full native correctness indicator using the inherited **joint** actual/fixed-reader correctness rule.

No universal 0.50 chance level is assumed for \(I\). The source correctness rule is a compound gate, not a coin-flip label.

For \(X\in\{M,F,I\}\),

\[
\Delta X_j^{a,b}=X_{j,post}^{a,b}-X_{j,pre}^{a,b}.
\]

Define direction-specific effects

\[
T_{\rm abs,X,j}^{a}=\Delta X_j^{a,R}-\Delta X_j^{a,N},
\qquad
T_{\rm spec,X,j}^{a}=\Delta X_j^{a,R}-\Delta X_j^{a,P}.
\]

The pooled descriptive summaries are the averages over \(j\in\{C3,D3\}\). The old \(G_{\rm rel}\) name is retained only as \(G_{\rm rel}^{a}=T_{\rm spec,M}^{a}\).

A positive pooled \(G_{\rm rel}\) is only a pooled relation-specific margin effect. It is not evidence that both directions transfer and is not an absolute correctness certification.

For each direction report post-training native correctness under R, P and N, plus actual/fixed-reader margins. No 0.50 floor is applied.

Freeze `A11_C_NULL_BASELINE_PLAN.json`, declaring P and N as the two prespecified reference branches. No post-result baseline is selected.

All anchor interactions are componentwise comparisons of complete anchors, never pure direct-sum/isolation effects.

# 16. Exception phase and the distinction between item learning and relation revision

Use each anchor's `R` post-transfer state.

The exception item is:

```text
C3 on even world index
D3 on odd world index
```

Its category-consistent **old target** is the target implied by the preceding `R` relation. The exception teaching reverses that target to a **new target**.

The read-only probe already taken at the end of the transfer phase is now formally part of the exception analysis. For the exception item record, before any exception teaching:

```text
old-target actual signed margin
old-target fixed-reader signed margin
old-target native correctness
```

using the exact inherited native correctness rule. This is the shared prestate for `E_WRITE` and `E_NOWRITE`.

Clone:

```text
E_WRITE
E_NOWRITE
```

with byte-identical cue pairs, outcomes and timing, differing only by native plasticity enabled versus disabled.

Probe after 1, 2 and 4 exception-teaching exposures on:

- the exception item;
- two same-category trained siblings;
- two other-category trained items.

All post-exception margins on the exception item are re-signed to the **new target**.

This panel distinguishes two questions:

\[
\boxed{
\text{Can the learner learn the reversed item after relation training?}
}
\]

and the stronger question

\[
\boxed{
\text{Can the learner revise an old relational expectation that it actually expressed before reversal?}
}
\]

The first does not imply the second.

## 28.1 Meaning of K and L

Prior foreign cohorts retire at episode boundaries. A persists and is not re-taught merely because L increases.

```text

slot r, 1<=r<=K-1   = teach fresh F[e,r]
slot r, K<=r<=15    = matched rest
```

Active slots use exact inherited task-native teaching duration; inactive slots get one-for-one matched rest. Therefore K=16 fills all 16 episode-1 slots with A plus 15 F cohorts; D never competes for a slot.

## 38.5.2 Paired-binary feasibility — strict decimal rule

For

\[
D\in\{-1,0,1\},
\qquad
\delta=E[D]>0,
\qquad
d=P(D\ne0),
\]

the implied probabilities are

\[
p_+=(d+\delta)/2,\qquad
p_-=(d-\delta)/2,\qquad
p_0=1-d.
\]

The exact feasible region is

\[
\boxed{0<\delta\le d\le1.}
\]

To eliminate tolerance ambiguity, the C0 lock stores paired-binary `delta` and `d` as **decimal strings**. Qualification parses them with arbitrary-precision decimal arithmetic (minimum 50 decimal digits of working precision) and applies the feasible-region inequalities **strictly to the supplied decimal values**.

There is no tolerance-based rescue of an infeasible \((\delta,d)\) pair.

After strict feasibility passes, compute \(p_+,p_-,p_0\) from the validated decimal pair and require all three to lie in \([0,1]\) and sum exactly to 1 using exact decimal arithmetic at a precision sufficient for the full supplied strings. Compute \(d-\delta^2\) from those same decimal values. A valid positive decimal variance must never be reclassified as the exact zero-variance boundary because a later binary-float conversion rounds \(\delta\) to 1. If conversion cannot safely represent a positive variance, evaluate the non-binding approximate diagnostic with decimal arithmetic or record it as `NUMERICALLY_UNRESOLVED`; that diagnostic cannot affect C0 disposition.

Thus:

```text
delta="1.0000000000005", d="1"
    -> INVALID, because delta>d

delta="0.9999999999995", d="1"
    -> VALID, positive nonzero variance

delta="1", d="1"
    -> VALID exact zero-variance boundary
```

For a valid pair,

\[
\operatorname{Var}(D)=d-\delta^2.
\]

At the exact boundary \(\delta=d=1\), \(D=1\) almost surely and the approximate single-component diagnostic is defined to be 1 rather than dividing by zero.

Mandatory binary fixtures include:

```text
INVALID  delta=0.6, d=0.4
VALID    delta=0.10, d=0.25
VALID    delta=0.25, d=0.25
VALID    delta=0.9999999999995, d=1
INVALID  delta=1.0000000000005, d=1
BOUNDARY delta=1, d=1
VALID    delta=0.99999999999999999999999999999999999999999999999999, d=1
         (positive decimal variance even though float(delta)==1.0)
```

A decision is C-sensitive iff at least one C-conditioned action differs from `action_without_C`.

For each controlled resource \(r\), the lock contains:

```text
resource_id
unit
aggregation_semantics
estimate_lower
estimate_upper
cap
provenance
```

with finite numbers satisfying:

\[
0\le estimate\_lower\le estimate\_upper,
\qquad
cap\ge0.
\]

The **only** C0 comparison scalar is

\[
\boxed{
COST\_COMPARE_r := estimate\_upper_r.
}
\]

This is a deliberately conservative **resource policy**, not a proof that C is computationally infeasible.

Required aggregation semantics are fixed:

- `C1_CPU_HOURS`: sum of user+system CPU seconds over all C1 worker processes divided by 3600;
- `C1_WALL_HOURS`: elapsed monotone wall time from C1 start to completion/stop divided by 3600;
- `C1_AGG_RSS_GIB`: maximum over sampled times of the sum of RSS of the C1 process tree, divided by \(2^{30}\);
- `C1_DISK_GIB`: maximum incremental bytes attributable to C1 scratch+outputs relative to the frozen pre-C1 baseline, divided by \(2^{30}\);
- `C_SCIENCE_CPU_HOURS`: projected sum of user+system CPU hours for all C science trajectories;
- `C_SCIENCE_WALL_HOURS`: projected wall hours under the frozen worker count.

If a required cost interval/cap is missing, non-finite, negative where forbidden, has lower>upper, or lacks provenance, C0 returns `TRIAGE_INSUFFICIENT_EVIDENCE`.

For each resource:

```text
estimate_upper < cap  -> WITHIN_CAP
estimate_upper = cap  -> WITHIN_CAP
estimate_upper > cap  -> EXCEEDS_CAP
```

Therefore a range that straddles a cap is an `EXCEEDS_CAP` case because its frozen upper endpoint exceeds the cap.

Mandatory cost fixtures include:

```text
below:      interval [8,9],  cap 10 -> WITHIN_CAP
equal:      interval [8,10], cap 10 -> WITHIN_CAP
above:      interval [11,12],cap 10 -> EXCEEDS_CAP
straddling: interval [8,12], cap 10 -> EXCEEDS_CAP
missing estimate -> TRIAGE_INSUFFICIENT_EVIDENCE
invalid [12,8] -> TRIAGE_INSUFFICIENT_EVIDENCE
```

## 39.6 Whole-decision operating characteristics and Monte Carlo uncertainty

Before simulation freeze:

```text
N_SIM_PER_GATE_CELL >= 100000
MC_FAMILY_ALPHA = 0.05
```

where a **gate cell** is one primary-claim × sensitivity-setting probability that can determine confirmatory authorization.

Let:

\[
m_{\rm gate}
=
\text{number of gate cells entering the final confirmatory decision}.
\]

For gate cell \(g\), after \(N_g\) complete synthetic experiments with \(K_g\) successes, compute the one-sided **exact Clopper--Pearson** lower bound

\[
\boxed{
L_g^{MC}
=
\operatorname{Beta}^{-1}
\!\left(
\frac{0.05}{m_{\rm gate}};
K_g,\,
N_g-K_g+1
\right)
}
\]

for \(K_g>0\), and \(L_g^{MC}=0\) for \(K_g=0\).

The Bonferroni factor applies only to Monte Carlo estimation uncertainty over the gate cells; it is not a substitute for the science-analysis multiplicity procedure.

Also report:

\[
\hat p_g=K_g/N_g,
\qquad
SE_g^{MC}
=
\sqrt{\hat p_g(1-\hat p_g)/N_g}.
\]

No point estimate alone may authorize science.

At the minimum \(N_g=100000\), a value such as \(\hat p=0.8001\) will generally have an MC lower bound below 0.80 and therefore **does not pass**.

There is no adaptive gray-zone resimulation in v3.8. If more Monte Carlo precision is desired, the larger \(N_{\rm SIM}\) must be frozen before that C1 simulation batch and fit inside the existing C1 budget lock.

## 39.7 Confirmatory-power gate
