# Full151 bridge, step 3a: protected dual value route

The fresh-world gain-0.05 preservation gate failed. This technical prototype
changes the structure instead of searching another additive dose. One native
Full151 value circuit keeps exactly the inherited FE0 input, connections and
plasticity. A second, independent native Full151 value circuit receives the
V9.2 predictor bridge. Both see identical bytes, clocks and teaching bits.
The predictor state is currently duplicated for implementation simplicity and
must remain identical between circuits; only the native value states may
diverge. No temporal value is mixed into the protected FE0 circuit.

This phase is **E0 interface qualification only**. It supplies separate
`fe0_value` and `temporal_value` queries, not a combined answer policy. A
future output gate must be fixed and tested separately; simply adding a
second branch does not establish improved learning. The engineering world is
9399 and is excluded from any future behavioral estimate.

Technical acceptance requires: (1) after the complete 144-record V9.8 old
teaching schedule, the protected FE0 branch has a bit-identical full state
digest and immediate trained/held-out pair margins to a standalone FE0 model
under both native-write W and no-write N; (2) duplicated predictor weights
match after every record; (3) no read-only probe mutates live state; (4) native
clocks and teaching counts agree; and (5) the temporal branch yields distinct
KC codes on at least one tested cue, proving it remains accessible. A failure
halts this technical step; no science world is started.

The next gate requires a prospectively constructed byte-order relation in
which FE0's code demonstrably aliases task-relevant histories while the
temporal code separates them. Its teaching and never-reinforced test cases,
fixed task-independent routing rule, exact-key and shortcut countermodels,
and fresh-world preservation/benefit criteria must be frozen **before** any
behavioral run. Until then, the protected route is an implementation result,
not a fix for arithmetic, E3 transfer, or autonomous output.
