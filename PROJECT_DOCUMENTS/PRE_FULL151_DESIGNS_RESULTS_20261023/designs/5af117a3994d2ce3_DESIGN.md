# Step 15 — one fixed role-code component screen

## Decision and boundary

This is one prospective screen of a fixed, label-free byte input candidate. It asks whether a role-separated code can retain FE0's *limited* held-out relation signal while improving crowded, directly taught 16-cue byte recall. It does **not** test an integrated single architecture: the relation assay has one native Full151 value store and supplied two-option relative choice; the capacity assay has four copied native output stores and a prompted one-byte argmax. A pass in both is component evidence only. It cannot establish teacher-free learning, arithmetic, autonomous answer timing, a persistent learning core, or use of V9.2's learned predictor representation.

The role code is frozen before any technical or science world. It inherits FE0's 88-PN trace. For each adjacent pair of visible non-space bytes since newline, it adds eight fixed SHA256-seeded contacts for the older byte to an `EARLY` trace and eight independently seeded contacts for the newer byte to a `LATE` trace. Both decay with the Step-6 30-second time constant. The readout is `norm(FE0 + 0.5*EARLY + 0.5*LATE)`. The contact values use the Step-6 0.4–1.0 range. There is no label, cue-ID or learned front-end weight. The `0.5` per-role gain keeps the total nominal contact contribution comparable to one Step-6 pair event. No parameter search or post-pilot retuning is allowed.

## Two screens and exposure audit

**Relation screen, limited E3:** inherit Step 12's V9.8 source generator, single-store Full151 learner, 144 old teaching records, 24-hour gap, 72 disjoint new-cohort records, another 24-hour gap, and relative value scoring. FE0 and ROLE run on the same new world, bytes, labels, clock and native writes. W receives old native writes; N sees the same old bytes and teaching calls without those writes. Both W and N learn the new cohort. Six held-out ordered cues, representing three never-taught symbol pairs in both orientations, receive no feedback. Strict or whitespace-canonicalized pair-key recitation has no answer; frequencies and positions are balanced. A one-bit class rule learned from prior teaching can solve the narrow task. The scored relative choice comes from native Full151 values on read-only copies, not an emitted open-answer byte. The primary screen quantity is final held-out W−N by world; old-end held-out and taught-cue scores are positive/localization controls.

**Capacity screen, E1:** inherit Step 13's 16 `a+b=` byte cues, nine fixed and seven per-world shuffled balanced answer-byte labels, 12 interleaved exposures per cue, 192 records, 165-second record clock, four full native output stores, and byte-derived opponent teaching. FE0 and ROLE have paired worlds, identical bytes/labels/clocks and W/N write flags. The output is selected before the answer byte arrives. All 16 canonical cues are directly reinforced, so an exact-key table can pass; the result is not learned addition. The never-taught spacing form is descriptive E2 only; a whitespace canonicalizer plus lookup table can pass it. The primary screen quantity is ROLE's final canonical accuracy relative to FE0, with every cue and answer class reported.

The two screen families use different new identities and never reuse old trajectories. Technical worlds: relation 15000 and capacity 15200. Eight feasibility worlds each: relation 15001–15008 and capacity 15201–15208. Fresh confirmation worlds only if their corresponding pilot passes: relation 15101–15132 and capacity 15301–15332. Pilot worlds are never pooled into confirmation. Receipts are committed atomically; a scientific exception stops execution with a failure receipt and no replacement or automatic restart.

## Frozen gates

The technical gate checks source/checkpoint hashes, unchanged native birth state, all candidate feature vectors finite and 88-dimensional, order-sensitive sentinel codes, all 16 capacity codes distinct, no-answer-label leakage, W/N sensory parity, read-only probe purity, clock parity, exact native write counts, and an independent receipt audit.

The **relation pilot** computes *taught cues only* and proceeds if ROLE W old-end trained choice ≥0.75, ROLE W final trained choice ≥0.65, and ROLE old-end trained W−N ≥0.20. The **capacity pilot** proceeds if ROLE W canonical accuracy ≥0.60, ROLE W−N ≥0.25, and each output class has at least one correctly emitted cue. These are feasibility guards, not evidence claims. A failed pilot stops its screen.

The relation confirmation reports world-paired two-sided 95% Student-*t* intervals for FE0 and ROLE final held-out W−N and their difference. A **candidate preservation signal** requires ROLE final held-out W−N interval lower >0, ROLE W final old-trained choice ≥0.70, and ROLE−FE0 final held-out W−N point difference ≥−0.10. The last condition is a screening tolerance, **not** a statistical noninferiority claim. The capacity confirmation reports world-paired ROLE−FE0 canonical W accuracy and interval, all per-cue counts, class counts and E2 spacing. A **candidate separation signal** requires ROLE W canonical ≥0.70 and ROLE−FE0 paired interval lower >0. An overall `ROLE_COMPONENT_SCREEN_POSITIVE` requires both signals. Otherwise report which gate failed; never alter thresholds or reinterpret the two pipelines as one system.

World is the uncertainty unit, not cue or pair. Zero-variance intervals are unresolved. The per-cue Step-13 reliability gate (≥24/32 each and ≥85% overall) is reported but is **not** this screen's pass rule; this screen seeks a possible FE0–pair compromise, not a 16-cue certification. If the role candidate screens positive, the next *separate* program must put it into one frozen memory/output architecture and test delayed, previously unreinforced input with an emitted answer before feedback. If it fails, no two-bank or further parameter search begins automatically.

## Cost and controls

Use compact per-world receipts, not raw byte or event trajectories. The inherited Step-12 relation confirmation cost about 210 learner seconds for 32 worlds with two routes; Step-13 capacity about 715 seconds for 32 worlds with two routes. This new two-route candidate screen should remain in the same order of magnitude, but technical/pilot timings, not row counts, determine actual cost. Keep `caffeinate` attached to active learner runs. No current experiments are modified or restarted.

The longer-term no-external-teacher objective remains open. Here the relation task supplies a native reward bit and capacity supplies an answer byte during training; those scaffolds are explicitly admitted. A later ordinary-stream test must replace fixture teaching with a learner-internal signal and compare against predictor-only and Full151-write-lesion controls.
