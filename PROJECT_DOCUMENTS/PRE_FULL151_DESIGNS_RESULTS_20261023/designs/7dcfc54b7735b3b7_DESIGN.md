# Step 7: emitted-byte E3 bridge on the V9.9A relation

## Question and permitted claim

Can the fixed FE0-plus-fading-pair input route and two copied native Full151 value stores use earlier teaching to **emit** a binary answer byte for a never-reinforced relation instance after a day, disjoint intervening learning, and another day? This is a new E3 output assay, not a byte-for-byte rerun of V9.9A. A positive result permits only within-family, fixed-prompt, externally taught binary output. It is not addition, autonomous answer timing, byte-derived teaching, or a general persistent core.

## Frozen input, output and exposure

Use V9.8 `make_e3(world)` unchanged: three P and three N uppercase symbols, six taught P–N edges in both orientations (12 contexts, 144 old records), three never-taught edges in both orientations (six scored contexts), then a 72-record cohort on three disjoint symbols. Every old symbol is present in two taught edges and both positions. The fixed 12-byte cue and `!` outcome byte, newline, 165-second record schedule, 24-hour pauses, V9.2 checkpoint, native Full151 plasticity, and frozen predictor policy are inherited. The frontend is exactly Step 6's frozen fading-pair candidate. A newline breaks its pair chain.

Each branch has two native Full151 stores. At the end of one 12-byte cue, before `!` or feedback, both stores report native association value; argmax emits ASCII `0` or `1` (a tie emits `0`). The externally supplied original Boolean label routes teaching: the target output store receives native neutral (`r=0`), the other native aversive (`r=1`). The label is never added to the sensory byte stream. Both stores receive identical cue, `!`, newline and time. This is an external-teacher **output bridge**, deliberately retaining V9.9A's constant outcome byte; replacing `!` with the label byte would change the write-time sensory address and is a separate experiment. There are two native writes per old/new record when enabled, zero when disabled. Predictor weights do not update, as in Step 6; conclusions cannot be presented as reproduction of the V9.9A joint wrapper.

`W` and `N` start from identical checkpoint/native states and receive identical records and teaching calls. During the 144 old records only W writes; N has writing off. At old end, after one day, and after the 72 disjoint new records, probe trained and never-taught old contexts on discarded clones without any feedback. Both W and N write during the new cohort. Probe again after the final day. Also probe the disjoint new taught contexts before and after their training to check that the intervening task was actually learned. There is no R/S branch in this narrower assay. All scored choices are the emitted byte for a **single** cue; the evaluator never compares two opposite cues to construct one choice.

The exact-key and whitespace-canonicalized pair tables have no taught entries for the six held-out contexts. Each target byte occurs three times among the six held-out orientations, so the deterministic tie/default output is 50% there. Fixed symbol position or frequency has no universal class label across randomized worlds. A one-bit class *learned from teaching* can solve the task and is a valid but narrow E3 explanation. The scored held-out contexts receive no answer or feedback at any time.

## Roster, qualification and primary outcome

Engineering world: **11700**, excluded. Feasibility pilot: **11701–11708**, excluded from confirmation and never used to tune the model, relation, timing, or thresholds. Confirmation: exactly **11801–11864**, all fresh and disjoint from earlier science. A source lock and technical receipt are written before the pilot. The frozen pilot continuation gate is old-end W trained accuracy >= 0.70, old-end W−N trained accuracy >= 0.10, and new-end W and N new-cohort trained accuracies each >= 0.65. If it fails, stop and report bridge infeasibility; do not run confirmation or replace worlds. Pilot held-out outputs may be recorded for auditing but are not used for any decision.

For each confirmation world, final-day held-out accuracy averages the six independently emitted bytes. The **sole primary contrast** is world-paired `W−N` final held-out accuracy. A two-sided Student-t 95% interval across all 64 worlds must have lower endpoint > 0. The absolute final W accuracy must be >= 0.60. Interpretation additionally requires old-end W trained accuracy >= 0.70, final W trained accuracy >= 0.65, and new-end W and N new-cohort trained accuracy each >= 0.65. Only if all conditions hold is the verdict `LIMITED_E3_EMITTED_OUTPUT_SUPPORTED`; otherwise it is `NOT_DEMONSTRATED`, with the failed condition named. Zero world variance makes interval inference unresolved. Old-end, first-day, new-end, final trained and held-out accuracies and per-class counts are descriptive, not extra claims. V9.9A's old +17.19 pp evaluator-read effect is not a power estimate for this architecture.

## Technical checks, audit and cost boundary

Before any pilot world, verify source/checkpoint hashes, 144/72 record counts, exactly balanced old and held-out labels, no held-out exposure, exact W/N byte/time parity, identical sensory states across both stores and branches, read-only probe nonmutation, correct output-before-feedback order, deterministic tie handling, correct target/opponent teaching route and 2:0 old / 2:2 new writes, checkpoint clone equality, native clock alignment, and no invalid teacher label. The engineering world runs the complete timeline, but its behavior does not tune parameters. The pilot gates only feasibility as above.

Each pilot and confirmation world writes one atomic compact receipt. Completed receipts with a matching source lock are never rerun. A scientific exception writes `FAILURE.json` and stops; no automatic restart or replacement. An independent reducer checks the source lock, rosters, exposure hashes, times, class outputs, write counts, probe purity, per-world metrics, interval and verdict from receipts without rerunning trajectories. It must reject intentional changes to a cue, target, output, write count, source digest, or roster. No raw trajectories or checkpoint copies are packed. Actual runtime and disk are measured in engineering/pilot, not assumed from V9.9A.
