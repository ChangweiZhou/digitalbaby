# V40 — Utility Under Scarcity
## Which persistent memories deserve continued existence under a hard long-term budget?

**Status:** design / preregistration only. No V40 scientific outcomes have been observed.

**Proposed scientific seeds:** `40101`–`40108`  
**Independent streams:** 8  
**Primary substrate:** V39 `TRACE-CORR`, frozen  
**Primary scientific variable:** consolidated-slot replacement priority only  
**Hard capacities:** `T = 512` probationary exact traces; `C = 384` consolidated two-anchor slots  
**Total logical identities:** `N = 768` (2× consolidated-slot capacity)  
**Learned renderings per identity:** 2; third rendering remains read-only held-out  
**Primary candidate:** `UTILITY-RATE`  
**Decisive control:** `SHUFFLED-UTILITY`  
**No PBF as a load-bearing mechanism. No capacity sweep. No utility-temperature/decay sweep. No automatic follow-up.**

---

# 0. Decision in one sentence

V39 established that most one-shot experiences should not immediately consume expensive long-term object slots: a bounded probationary trace plus distinct-context predictive corroboration preserved almost all target behavior under heavy transient clutter while reducing incremental episodic state by roughly an order of magnitude.

V40 asks the next question, which V39 deliberately did not test:

\[
\boxed{
\text{What happens when the number of genuinely corroborated, reusable objects exceeds the slot budget?}
}
\]

The primary hypothesis is:

> **When long-term capacity is genuinely scarce, persistence should track the realized marginal predictive value of each memory, not merely its age, recurrence count, or arbitrary identity.**

The proposed replacement score is the memory's causal rate of bits saved relative to the shared base:

\[
\boxed{
U_j(t)
=
\frac{G_j(t)}
     {t-t_j^{\rm birth}+1},
\qquad
G_j(t)
=
\sum_{\tau\le t,\ \tau\in j}
\left[
\ell_B(\tau)-\ell_j(\tau)
\right].
}
\]

Here:

- \(\ell_B\) is the pre-update base-only log loss on the actually observed byte;
- \(\ell_j\) is the pre-update loss of the deployed memory prediction for slot \(j\);
- positive gain means the memory saved predictive bits;
- negative gain means the memory was actively harmful;
- dividing by slot age produces a parameter-free utility **rate** in bits saved per stream event.

When a new corroborated object must consolidate and all \(C=384\) slots are occupied, `UTILITY-RATE` evicts the slot with the lowest \(U_j\).

# 1. What V40 is — and is not

## 1.1 V40 is a genuine scarcity experiment

V39's main stressor was transient clutter. `TRACE-CORR` succeeded largely because most clutter never earned consolidation.

That was the correct first bounded-memory problem, but it did **not** answer the harder case in which:

\[
N_{\rm legitimate\ consolidated\ objects} > C.
\]

V40 therefore makes every competing identity capable of:

- one-shot exact memory;
- distinct-context corroboration;
- two-anchor consolidation;
- later recurrence;
- held-out alias transfer.

The learner cannot solve V40 simply by refusing to admit one-off noise.

## 1.2 V40 is not an eviction-rule zoo

Only replacement priority changes.

The following remain identical across all deployable bounded arms:

- byte-level causal next-byte prediction;
- shared base learner;
- lag96 address representation;
- \(\tau=0.85\);
- absolute local value semantics;
- pre-update predictive confirmation;
- V37 `CORR2` read authority;
- V39 probationary exact traces;
- V39 distinct-context promotion;
- V39 two-anchor consolidated slots;
- trace cap \(T=512\);
- slot cap \(C=384\);
- demotion semantics after slot eviction;
- no replay;
- no evaluator identity metadata;
- no task/wave/importance labels.

V40 does **not** compare new encoders, write rules, admission gates, confidence temperatures, trace sizes, slot sizes, or capacity levels.

## 1.3 V40 does not include the phase-stationarity closure

Claude's V39 reopened a separate representation question: high separation was confounded with nonstationary phase normalization.

That closure should be run separately as a tiny V39.2 experiment:

\[
\text{S2-lag-c12}
\quad\text{vs}\quad
\text{frozen-phase-c12}
\quad\text{vs}\quad
\text{live-phase-c12}.
\]

Its result may matter later for indexing or superposed overflow, but it is **not** a V40 variable.

# 2. Why raw LRU/LFU are insufficient hypotheses

Long-term memory capacity should not necessarily be spent on whatever was seen most recently or most frequently.

Consider two equally recurrent contexts:

- slot \(a\): the shared base already assigns the correct byte probability \(0.95\);
- slot \(b\): the shared base assigns \(0.02\), while the object memory assigns \(0.95\).

The recurrence count is the same, but their marginal episodic value is radically different.

The actual bit savings are approximately:

\[
r_a
=
-\log_2(0.95)+\log_2(0.95)
\approx0,
\]

while

\[
r_b
=
-\log_2(0.02)+\log_2(0.95)
\approx5.6\ {\rm bits}.
\]

A lifelong learner should prefer \(b\) even if \(a\) is marginally more recent.

This motivates the V40 distinction:

\[
\boxed{
\text{frequency of use}
\neq
\text{marginal value of remembering}.
}
\]

# 3. The learner-visible memory hierarchy

V40 inherits the V39 hierarchy exactly.

## 3.1 Shared predictive base

The base operates continuously and is never capacity-limited by V40.

Its pre-update distribution is always available as the counterfactual:

\[
p_B(y\mid c).
\]

The base does not receive information about memory priority, hidden recurrence class, or evaluator utility.

## 3.2 Probationary exact trace

A first surprising experience earns immediate exact memory but not reusable identity.

A trace stores the same compact state as V39:

- exact 12-byte context;
- absolute local value;
- exact-hit metadata;
- recency metadata.

Hard cap:

\[
T=512.
\]

Exact hit:

\[
p(y\mid c)=p_{\rm trace}(y).
\]

Similarity-only hit:

\[
p(y\mid c)=p_B(y\mid c).
\]

A support-1 trace may propose a candidate for post-outcome corroboration but has zero generalized authority.

## 3.3 Consolidated two-anchor slot

A second **distinct** context that:

1. similarity-matches the trace;
2. arrives while the base is wrong;
3. is correctly predicted pre-update by the trace value,

promotes the identity to one consolidated slot.

The slot contains:

- exactly two anchor contexts;
- one prototype accumulator / prototype;
- one absolute 256-way value;
- access metadata;
- replacement-policy metadata.

Hard cap:

\[
C=384.
\]

No additional permanent member table is allowed.

# 4. Common demotion semantics

V40 must distinguish:

\[
\text{loss of generalized ownership}
\]

from:

\[
\text{complete erasure of exact experience}.
\]

Therefore every bounded replacement policy uses the same deterministic demotion rule.

When consolidated slot \(j\) is evicted:

1. remove its similarity-addressable slot state;
2. copy its two exact anchors back into the probationary trace pool as two exact traces carrying the current absolute value;
3. if the trace pool exceeds \(T=512\), apply the unchanged V39 trace-LRU rule until the cap is restored;
4. destroy the evicted slot's replacement ledger;
5. retain no tombstone, historical score, hidden membership record, or replay state.

Thus an evicted memory degrades:

\[
\boxed{
\text{generalizable slot}
\rightarrow
\text{exact-only trace}
\rightarrow
\text{forgotten}.
}
\]

If two distinct traces for that logical identity later re-establish predictive corroboration, the object may consolidate again.

Re-consolidation starts a **fresh** replacement ledger. No old utility score survives eviction.

This common demotion mechanism is infrastructure, not a V40 scientific variable.

# 5. Causal utility measurement

## 5.1 Reward is computed only after the outcome is observed

For every event on which consolidated slot \(j\) supplied the deployed object-memory prediction, record from the frozen pre-update state:

\[
\ell_B
=
-\log_2 p_B(y\mid c),
\]

\[
\ell_j
=
-\log_2 p_j^{\rm deployed}(y\mid c),
\]

and

\[
\boxed{
r_j=\ell_B-\ell_j.
}
\]

Positive \(r_j\):

> retaining the slot saved predictive bits.

Negative \(r_j\):

> the slot hurt prediction relative to base-only.

No reward is available before observing \(y\).

The reward therefore contains no future information and no evaluator label.

## 5.2 Which events update the ledger?

Update the ledger only when the slot had actual deployed authority:

- exact anchor hit;
- confirmed CORR2 similarity retrieval from a consolidated slot.

Do not credit a slot for:

- merely being the nearest candidate while support/authority blocks its prediction;
- read-only evaluator probes;
- outcomes after the slot has already been evicted;
- hypothetical predictions never used by the learner.

This makes the ledger a record of **realized marginal deployed utility**, not a counterfactual fantasy about every nearby context.

## 5.3 Initial utility at consolidation

A newborn slot would otherwise have age \(1\) and zero reward.

At the E2 consolidation event, the first trace's pre-update prediction and the base prediction are both already available.

Seed the new slot's gain ledger with:

\[
G_j(t_{\rm birth})
=
\ell_B(E2)-\ell_{\rm trace}(E2).
\]

This is exactly the causal predictive-confirmation event that earned consolidation.

No arbitrary prior bonus is added.

## 5.4 Utility-rate score

At stream event \(t\):

\[
\boxed{
U_j(t)
=
\frac{G_j(t)}
     {t-t_j^{\rm birth}+1}.
}
\]

The denominator advances even when the slot is not accessed.

Consequences:

- useful but dormant memories gradually lose priority;
- repeatedly useful memories maintain a high rate;
- frequently accessed memories that add little beyond the base remain low-value;
- harmful memories can become negative;
- no exponential-decay coefficient or horizon is introduced.

Tie-breaking:

1. smaller \(U_j\);
2. older last use;
3. older allocation index.

All ties are deterministic.

# 6. V40 workload: rolling useful-memory overload

A naive experiment that first presents 768 identical-looking memories and only later reveals which 384 matter would be a clairvoyance test.

V40 instead makes usefulness observable **online before and during scarcity**.

## 6.1 Identity population

Generate:

\[
N=768
\]

unique logical identities.

Each identity has:

- learned rendering \(a_0\);
- learned rendering \(a_1\);
- never-trained held-out rendering \(a_2\);
- one arbitrary target byte from the same 24-byte target alphabet used in V38/V39.

Identities are divided evaluator-only into six introduction cohorts:

\[
K_1,\ldots,K_6,
\qquad
|K_k|=128.
\]

The cohort identifier is never exposed to the learner.

## 6.2 Admission pair for every identity

For each cohort:

1. present every \(a_0\) once in seed-shuffled order;
2. after an interleaving gap, present every \(a_1\) once;
3. require the ordinary TRACE-CORR mechanism to create traces and then consolidate identities.

No special admission path exists for V40.

Every identity is evaluator-intended to be capable of earning a slot from its two learned renderings.

## 6.3 Recurrence classes

At stream generation, identities are assigned evaluator-only recurrence schedules.

Use four equal classes:

- `HOT`: 192 identities;
- `WARM`: 192;
- `COOL`: 192;
- `FADING`: 192.

The class is never stored in the learner state.

The fixed service schedule is:

| Class | Service opportunities after introduction |
|---|---|
| HOT | 4 per service epoch |
| WARM | 2 per service epoch |
| COOL | 1 every second service epoch |
| FADING | 2 per epoch for the first two eligible epochs, then 0 |

Within each service epoch:

- recurrence rows are seed-shuffled;
- learned aliases \(a_0,a_1\) alternate;
- no \(a_2\) rendering is trained;
- no old item is replayed merely to protect it — recurrence is the workload itself.

This creates:

- high continuing demand;
- medium demand;
- sparse demand;
- memories whose usefulness genuinely expires.

## 6.4 Rolling schedule

The stream is:

\[
K_1
\rightarrow S_1
\rightarrow
K_2
\rightarrow S_2
\rightarrow
K_3
\rightarrow S_3
\rightarrow
V
\rightarrow
K_4
\rightarrow S_4
\rightarrow
K_5
\rightarrow S_5
\rightarrow
K_6
\rightarrow S_6
\rightarrow
S_7
\rightarrow
S_8.
\]

Here \(S_k\) is a recurrence/service epoch over all identities introduced so far.

After \(K_3\), exactly 384 identities have had the opportunity to consolidate, matching the slot cap.

Before \(K_4\) starts, run a **valuation pass** \(V\):

- one learned-rendering recurrence for every currently consolidated identity;
- identical exposure count across those identities;
- no new identities.

This guarantees that every incumbent slot has at least one post-consolidation causal utility observation before the first intended capacity-forced replacement.

The first genuine slot-scarcity event should therefore occur during \(K_4\), not before the learner has any evidence.

## 6.5 Why the recurrence schedule is not an importance label

The learner observes only ordinary byte events.

It is never told:

- recurrence class;
- future recurrence count;
- whether an object will fade;
- evaluator utility;
- whether the current slot is in the future top quartile.

Recurrence history becomes informative only because the environment actually recurs.

This is the causal information an online learner is allowed to exploit.

# 7. Task-validity screens

These gates are evaluated before replacement-policy claims.

If a screen fails, report the workload result but do not interpret policy rankings.

## P0 — consolidation validity

In the unbounded reference:

- at least **95%** of the 768 intended identities must consolidate by their E2 event;
- exact learned-rendering accuracy after consolidation \(\ge90\%\);
- held-out \(a_2\) accuracy after consolidation \(\ge90\%\).

Otherwise the workload is testing admission failure rather than scarcity.

## P1 — genuine capacity pressure

In every bounded arm:

- slot occupancy reaches exactly \(C=384\);
- at least **192 slot replacement events** occur after scarcity begins;
- no arm can avoid pressure merely by failing to acquire.

The unbounded reference must exceed:

\[
1.75C=672
\]

simultaneously resident consolidated identities at some point.

## P2 — pre-scarcity observability

Before the first intended replacement:

- every incumbent consolidated slot has at least one post-birth deployed-memory reward observation;
- no replacement policy has access to future recurrence information.

This gate prevents V40 from becoming a clairvoyance benchmark.

## P3 — utility heterogeneity exists

Using the **unbounded reference only** and evaluator-side post hoc summaries, compute each slot's realized future marginal bits saved from scarcity onset onward.

Require:

- 90th percentile future utility at least **2×** the median;
- interquartile range \(>0\);
- at least 20% of slots with positive future cumulative gain;
- at least 20% with future gain less than half the 80th-percentile value.

This gate says there is something meaningful for a replacement policy to discriminate.

It does **not** expose those future values to deployable learners.

# 8. Replacement policies

All bounded policies share the same admission, demotion, trace policy, base trajectory and capacities.

Only the victim-selection score changes.

## 8.1 `RANDOM`

At every forced slot replacement:

- choose a uniformly random resident consolidated slot;
- deterministic RNG seeded from science seed and replacement index.

Purpose:

- capacity floor / sanity control.

## 8.2 `LRU`

Evict the consolidated slot with the oldest last deployed use.

Tie-break by oldest allocation index.

Purpose:

- standard recency baseline.

## 8.3 `LFU-RATE`

Maintain deployed-use count \(H_j\).

Score:

\[
F_j(t)
=
\frac{H_j(t)}
     {t-t_j^{\rm birth}+1}.
\]

Evict the smallest \(F_j\).

This is frequency per unit stream time rather than raw cumulative count, so very old objects are not automatically immortal.

Purpose:

- strongest simple recurrence-only comparator.

## 8.4 `UTILITY-RATE` — primary V40 arm

Use:

\[
U_j(t)
=
\frac{\sum r_j}
     {t-t_j^{\rm birth}+1}.
\]

Evict the smallest \(U_j\).

Purpose:

- test whether **marginal predictive value** is a better persistence signal than recency or recurrence frequency.

## 8.5 `SHUFFLED-UTILITY` — decisive specificity control

This control computes the **same real per-slot utility ledgers** as `UTILITY-RATE`.

At every forced replacement event:

1. collect the current resident slots;
2. bin them by:
   - deployed-use count: `0–1`, `2–3`, `4–7`, `8+`;
   - age quartile within the current resident population;
3. within each non-singleton stratum, deterministically permute the current \(U_j\) scores among slot identities using a seed-specific shadow RNG;
4. singleton strata retain their own score only because no same-stratum alternative exists;
5. evict according to the **shuffled** score.

Thus the control preserves, as closely as possible:

- current score distribution;
- age distribution;
- frequency distribution;
- number and timing of replacement events;
- memory budget;
- score scale and dispersion.

It destroys:

\[
\boxed{\text{which slot earned which utility history}.}
\]

If `SHUFFLED-UTILITY` matches `UTILITY-RATE`, slot-specific realized utility has not earned its mechanistic interpretation.

This arm is evaluator-assisted and nondeployable.

## 8.6 `TRACE-U` — unbounded reference

Same TRACE-CORR admission/read/update semantics with no trace or slot capacity limit.

Purpose:

- regret reference;
- task-validity analysis;
- evaluator-only future-utility ceiling construction.

It is not a bounded competitor.

## 8.7 `ORACLE-FUTURE` — optional nondeployable ceiling

From the fully realized fixed stream and `TRACE-U` trajectory, an evaluator may compute each currently resident identity's **future** marginal bits saved.

At each replacement event, `ORACLE-FUTURE` evicts the slot with lowest realized remaining future value.

This arm is strictly descriptive:

- no qualification gate requires beating it;
- it cannot be called a learner;
- its only purpose is to estimate how much room remains above causal policies.

If implementing it complicates the runner materially, omit it.

# 9. Primary endpoint: predictive regret under scarcity

Once useful memories exceed capacity, 100% retention is impossible by construction.

The primary endpoint is therefore not raw accuracy.

Let scarcity begin at the first event where a new consolidated slot requires a victim.

For bounded policy \(m\):

\[
\boxed{
R_m
=
\sum_{t\ge t_{\rm scarcity}}
\left[
\ell_m(t)-\ell_U(t)
\right],
}
\]

where:

- \(\ell_m(t)\) is the policy's prequential log loss;
- \(\ell_U(t)\) is `TRACE-U` loss on the same byte event and same seed.

Report both:

\[
R_m^{\rm object}
\]

over object target bytes only, and

\[
R_m^{\rm whole}
\]

over the full byte stream.

Normalize for presentation as:

\[
\bar R_m
=
R_m / N_{\rm object\ events}
\]

in **excess bits per object event**.

The qualification endpoint is:

\[
\boxed{\bar R^{\rm object}.}
\]

Lower is better.

A negative value is allowed: a bounded policy may occasionally outperform the unbounded reference by avoiding harmful stale retrieval.

# 10. Secondary endpoints

## 10.1 Utility-decile survival

Using evaluator-only realized future utility from `TRACE-U`, divide logical identities into deciles.

At the final checkpoint report for every policy:

- fraction retaining a consolidated slot;
- fraction retaining at least one exact trace;
- learned-rendering accuracy;
- held-out alias accuracy.

This reveals whether a policy preferentially preserves the genuinely valuable tail.

## 10.2 Recurrence-class survival

For `HOT/WARM/COOL/FADING`, report:

- consolidated survival;
- exact-only survival;
- held-out \(a_2\) accuracy;
- regret contribution.

This is descriptive; recurrence class is never learner-visible.

## 10.3 Demotion and recovery

Track:

- slot \(\to\) trace demotions;
- trace evictions;
- re-consolidations;
- number of object events needed to regain held-out transfer after re-consolidation.

All replacement policies share the same recovery machinery.

## 10.4 Ordinary collateral utility

Report:

- nontarget bpb;
- whole-stream bpb;
- candidate-hit rate on nontarget contexts.

A replacement policy may not improve target regret by causing widespread false memory authority.

## 10.5 Final held-out return

After \(S_8\), perform read-only probes for all 768 identities:

- \(a_0\);
- \(a_1\);
- never-trained \(a_2\).

Do not learn from these probes.

Report exact and held-out accuracy by future-utility decile and recurrence class.

# 11. Qualification gates

All thresholds are locked before V40 science outcomes are observed.

## Q0 — V39 substrate invariants

On two full engineering seeds before science:

- TRACE-CORR predictions and consolidation transitions reproduce the locked V39 implementation;
- hard capacities and canonical semantic-state accounting match;
- probes are read-only;
- branch policies share identical base state.

Failure stops V40.

## Q1 — task-validity screens

P0–P3 in Section 7 all pass.

Failure yields:

\[
\texttt{task\_invalid}
\]

and replacement-policy gates are not interpreted.

## Q2 — literal boundedness

For every event and every bounded arm:

\[
\text{traces}\le512,
\qquad
\text{slots}\le384,
\qquad
\text{anchors}\le768.
\]

No hidden tombstones, unbounded eligibility tables, replay logs, future-value tables or historical member lists may affect deployable predictions.

Failure voids V40 regardless of accuracy.

## Q3 — acquisition remains valid

Across all 768 intended identities:

- \(\ge90\%\) mean exact learned-rendering accuracy after consolidation opportunity;
- every seed \(\ge80\%\).

Replacement cannot win by failing to learn newcomers.

## Q4 — UTILITY-RATE beats LRU on object regret

Define:

\[
\Delta_{U-LRU}
=
\bar R_U^{\rm object}
-
\bar R_{LRU}^{\rm object}.
\]

Required:

- paired mean \(\le -0.05\) bits/object-event;
- paired 95% upper bound \(<0\).

## Q5 — UTILITY-RATE beats LFU-RATE

Same requirement:

\[
\Delta_{U-LFU}\le -0.05
\]

mean and paired upper interval \(<0\).

If LFU-RATE matches UTILITY-RATE, the extra base-relative utility ledger has not earned its complexity.

## Q6 — slot-specific utility beats shuffled utility

Primary specificity veto:

\[
\Delta_{U-SHUFFLED}
=
\bar R_U^{\rm object}
-
\bar R_{SHUFFLED}^{\rm object}.
\]

Required:

- paired mean \(\le -0.05\) bits/object-event;
- paired 95% upper bound \(<0\).

If Q6 fails:

\[
\boxed{\text{the slot-specific utility mechanism is not established}.}
\]

Even if UTILITY-RATE has the best raw score, the mechanistic claim is rejected.

## Q7 — high-value survival advantage

On evaluator-only top-quartile future-utility identities:

UTILITY-RATE must beat both LRU and LFU-RATE on final held-out \(a_2\) accuracy by:

- mean advantage \(\ge10\) percentage points against at least one comparator;
- paired 95% lower interval \(>0\).

This is an interpretability gate: lower regret should correspond to keeping valuable generalized memories, not merely shifting errors elsewhere.

## Q8 — whole-stream collateral noninferiority

Relative to the best of LRU/LFU-RATE:

- whole-stream bpb no worse by more than **0.05**;
- nontarget bpb no worse by more than **0.05**.

UTILITY-RATE cannot qualify by improving object-memory regret while degrading ordinary prediction.

## Q9 — graceful degradation survives

Among objects whose consolidated slot was evicted:

- exact learned-rendering accuracy from the demoted trace tier must remain \(\ge70\%\) at the first read-only post-eviction probe before trace eviction;
- held-out alias accuracy should drop materially relative to exact accuracy.

The second condition is descriptive and verifies that demotion really means:

\[
\text{generalization lost before exact memory}.
\]

## Q10 — recovery is functional

For evicted identities that subsequently receive two distinct learned-rendering events and re-consolidate:

- held-out \(a_2\) accuracy after re-consolidation \(\ge90\%\) mean;
- no evaluator identity metadata is used.

This ensures replacement does not irreversibly destroy the V39 identity mechanism.

# 12. Decision logic

## Outcome A — utility-based persistence established

Requirements:

- Q0–Q10 pass;
- especially Q4, Q5 and Q6.

Conclusion:

> Realized marginal predictive value is a causally supported persistence signal under genuine memory scarcity.

Carry `UTILITY-RATE` forward as the default consolidated-slot replacement rule.

## Outcome B — recurrence is enough

Pattern:

- LFU-RATE matches UTILITY-RATE;
- shuffled utility may also match.

Conclusion:

> The environment's value structure is adequately captured by recurrence rate; base-relative utility accounting is unnecessary.

Adopt the simpler LFU-RATE rule.

## Outcome C — recency is enough

LRU matches or beats utility/frequency.

Conclusion:

> Under this workload, recent use dominates long-run utility accounting.

Do not add a utility ledger.

## Outcome D — utility appears best but fails shuffled specificity

UTILITY-RATE has the best raw regret but Q6 fails.

Conclusion:

> Adaptive score dispersion may help, but the claim that each slot's own causal utility history deserves retention is not established.

Do not make slot-specific utility load-bearing.

## Outcome E — no causal policy approaches the oracle

If the optional oracle is dramatically better while all causal policies cluster together:

> The workload contains value that becomes knowable too late for the tested local statistics.

The next question becomes richer predictive survival models, not another threshold sweep.

## Outcome F — task invalid

If P0–P3 fail, redesign the scarcity stream before interpreting replacement rules.

No mechanism search is allowed on an invalid scarcity task.

- post-hoc threshold tuning.

# 14. Compute plan

The expensive shared base trajectory is generated once per seed.

Within a seed:

1. construct the fixed V40 stream;
2. run the shared base once;
3. branch auxiliary memory policies from identical initial state;
4. use the same byte events and same base predictions for:
   - RANDOM;
   - LRU;
   - LFU-RATE;
   - UTILITY-RATE;
   - SHUFFLED-UTILITY;
   - TRACE-U reference.

Thus:

\[
8\text{ base streams}
\]

and at most:

\[
8\times6=48
\]

memory-policy branches.

No separate large grid.

If runtime is materially larger than V39, first run:

- two engineering seeds;
- then four science seeds as a completion checkpoint;
- then all eight without changing any thresholds.

Partial science results must not alter the protocol.

# 16. Interpretation limits

Even a successful V40 would establish only:

- one synthetic byte-stream scarcity regime;
- one specific TRACE-CORR object-memory substrate;
- one hard capacity point;
- one family of causal replacement statistics.

It would **not** establish:

- optimal human-like forgetting;
- optimal capacity scaling;
- natural-language long-term memory;
- biological equivalence;
- that utility rate is universally optimal;
- that the fly uses such a ledger.

The scientific claim is deliberately narrower:

\[
\boxed{
\text{Under genuine online memory scarcity, does a memory's realized marginal predictive value causally improve which persistent objects survive?}
}
\]

# 17. If V40 succeeds

The most interesting V41 would then be architectural rather than another replacement-policy tournament:

\[
\boxed{
\text{precise utility-managed slots}
+
\text{bounded superposed overflow for the evicted long tail}.
}
\]

That would finally merge the two positive V39 branches:

- TRACE-CORR / earned explicit ownership;
- bounded superposed memory.

The hypothesis would be:

> high-value identities retain precise slots; lower-value evicted identities decay into a fixed-size distributed long-tail store rather than disappearing entirely.

But V40 must first establish what deserves the precise tier.


# Frozen implementation resolutions
- Stream time is the observed byte count, including nontarget bytes.
- Each cohort has 32 identities of each class (2 in smoke), randomly assigned.
  COOL receives one service on its 2nd, 4th, ... eligible epoch. FADING's
  first two eligible epochs each have two services. Recurrence aliases alternate
  independently of admission, starting at a0; valuation also advances this counter.
- The interleaving gap is one shuffled service epoch for already introduced
  identities, using the current epoch schedule. K1 uses one newline as its gap.
  Gap services count as actual workload services but not a new eligible epoch.
- V is one recurrence for ALL first 384 introduced identities, in fixed shuffled
  order. Conditioning the shared input on branch-specific residency would leak
  memory policy into the workload. P2 still checks every actual incumbent.
- The common scarcity onset for paired regret is the first replacement in ANY
  bounded branch. Whole and object excess loss use that same byte boundary.
- E2 gain seeds G from the frozen trace and base; H starts at zero, since the
  support-1 trace did not deploy generalized authority on E2. Postbirth H counts
  all deployed uses, even harmful ones. E2 credit is not counted again.
- Demoted anchors get fresh trace insertion ids, last=now, hits=1, equal copies
  of the slot value. Old ledger is destroyed. Promotion removes both anchors
  from the trace pool if a demotion recreated the current context mid-allocation.
- V39 exact-trace hits remain exact-only: two demoted exact anchors do NOT
  automatically re-consolidate. Recovery is measured when ordinary inherited
  corroboration occurs; an empty recovery sample is not a pass for Q10.
- Independent eviction causes divergent residency, admission and replacement
  schedules. SHUFFLED-UTILITY permutes its OWN current ledger within strata;
  its score multiset is preserved exactly. Cross-arm counts/timing/multisets
  are audited, not forced. If these fail, the design's strict matched-control
  audit is unmet and mechanistic qualification is withheld. No shadow admission.
- Quartiles are stable rank quartiles of age, ties by allocation id. Permutations
  may include fixed points. Substantial reassignment means >=50% of slots in
  nonsingleton strata change score-source identity, pooled over evictions.
- P0/P1/P2/P3 are required per seed. P0's resident count counts intended identities
  with both learned anchors in the same slot, not incidental nontarget slots.
- Future utility is accumulated in TRACE-U after common scarcity onset. For
  a slot with multiple intended identities among anchors, credit is divided
  equally among them; nontarget-only slots are excluded from identity deciles.
  Decile/top-quartile ties use identity index, evaluator only.
- Q7 requires positive paired mean against BOTH comparators, with >=10pp and
  positive lower 95% bound against at least one. Q8 uses the better comparator
  separately for each aggregate loss. Q9/Q10 require nonempty per-seed samples.
- All CIs are two-sided paired Student-t intervals across eight seeds. No
  partial or smoke results can qualify. No optional future oracle is included.
- Q0 verifies two full historical V39 streams under a compatibility replacement
  mode; V40 demotion/utility changes are tested separately with forced overflow.
  That mode is used only by engineering checks, never scientific branches.
- Resume is at completed-seed boundaries; an interrupted seed restarts. Scientific
  seeds are fixed, with no sweep or automatic second experiment.
