# Byte encoder → FULL_151 bridge, v1 (frozen before confirmation)

## Question and evidence level

Can the already trained V9.2 byte-context predictor causally drive the inherited FULL_151 PN→KC **value** path? This is an E0 access and interface experiment. It does not test autonomous answers, reward-free learning, memory improvement, E2 presentation transfer, or E3 reuse. The old V9.2 predictor checkpoint is an input artifact; all probe contexts below are new and no old trajectory is rerun.

## Architecture

Load the frozen V9.2 text checkpoint. During this experiment its predictor weights and bias are frozen. At each native PN read, compute the V9.2 next-byte distribution `q` from previously arrived bytes only. Project to the 88 existing receptor channels using the fixed receptor table: `z = normalize_max(q @ R_TABLE)`. The Full151 value path reads `normalize_max(FE0.read() + g*z)` with `g=0.5`. No teacher bit is part of this feedforward mapping. The existing FULL_151 connection, KC encoder, fast/slow learning rule, and `teach()` remain unchanged. The new front-end read is used both when `pending_x` is captured for a native write and when `association_value` is queried. This intentionally changes the sensory input to Full151; it is a structural integration, not a claim that Full151 itself was previously tested with this input.

Controls: `g=0` must be bitwise identical to V9.2's FE0 path; `lesion` replaces context-dependent predictor logits with the learned bias only while preserving FE0 state and bridge gain. A fixed permutation of the 256 output bins is a projection-alignment diagnostic, not an inferential comparator.

## Pilot, confirmation, and stopping

Engineering pilot: 16 generated four-byte context pairs, distinct from confirmation, for code-path and runtime checks only. No gain search after the pilot. Confirmation: 128 newly generated pairs of four distinct printable ASCII letters, each pair formed by swapping the first two letters while preserving the final two. Each pair is evaluated at the same fixed FE0 receptor state, byte time, native fly state, and current byte. This isolates learned historical information from FE0 recency; it is a causal *clamp assay*, not an end-to-end behavior test. Pair generation uses a committed PRNG seed and rejects duplicate contexts. All predictor updates are disabled.

The primary endpoint is the fraction of confirmation pairs with different FULL_151 native KC codes in the intact bridge, under the FE0 clamp. The gate is >=0.90, with FE0 and predictor-lesion controls both exactly zero. Secondary diagnostics are KC Hamming distance, PN distance, and direct native read/write-route checks. Pair is the unit of analysis; no KC or event is counted as an independent replicate. No result-dependent expansion or retuning is allowed. If the gate fails, report failure and stop; do not search mechanisms in this experiment.

## Exposure and countermodels

The pre-existing text checkpoint was trained on a natural text stream, not on reward labels for these pairs. This test provides no reward, target label, or answer byte. Exact-key or canonicalized-key tables cannot explain a *learned predictor lesion effect* under identical FE0 state, but the observed distinction may come from the engineered V9.2 predictor and does not prove native learning or generalization. The output is an evaluator-observed KC code, not a self-generated action.

## Acceptance and cost

Before confirmation, tests must pass for FE0 parity, causal pre-byte timing, clone purity, frozen predictor digest, native PN/KC difference, `pending_x` provenance, and deterministic resume. Confirmation writes one compact JSON row per pair in its phase receipt; it does not write full event ledgers. Independent audit recomputes counts and source/checkpoint hashes from receipts and verifies controls. `caffeinate` stays attached to the confirmation runner until it exits. A scientific failure is reported as failure, without automatic redesign or restart.
