# Step 7: Read-only access census before any E2 training

Step 6 showed that Full151 can learn directly taught order cues when fed
stable V9.2 depth-four feature identities. It did not show retrieval from a
changed presentation. H4 is a hash of the recent four bytes, so a superficial
prefix edit could leave its key unchanged and an exact canonicalized-key
table could pass. This census tests that boundary *without teaching labels*.

Use the unchanged V9.2 checkpoint and unchanged Step 6 FE0, Q and H4 routes.
For 24 fresh fixed worlds **9701–9724**, draw three uppercase symbols by the
source V9.3 rule, enumerate all six ordered pairs, and probe every cue from
the same prestates on read-only clones. No labels or reward bits are passed
to the models or used in scoring. The canonical 12-byte cue is eight spaces,
the ordered pair, and two spaces. Three label-preserving 12-byte variants are:

* `PREFIX`: replace the first eight spaces with `......  `, leaving the final
  four bytes unchanged. This is a deliberately trivial exact-H4-key control;
  its success cannot qualify an E2 test.
* `SHIFT_RIGHT` (primary): nine spaces, the ordered pair, one space. Both
  ordered bytes remain in the final four, but the H4 key changes.
* `SHIFT_LEFT` (negative access control): seven spaces, the ordered pair,
  three spaces. The first ordered byte leaves H4's four-byte window.

For each route and variant, compare the variant's KC code with all six
canonical codes in the same world. Record exact code match, same H4 row IDs,
Hamming distance to its own canonical cue, distance to its reversal, and a
tie-aware six-way nearest-prototype score (1/k if the own cue is among k
equally closest candidates, otherwise 0). The world, not the cue, is the
summary unit. Report per-world means, 95% Student-t intervals, and FE0/Q/H4
side by side. Do not use any world labels in the analysis.

A credible H4 access gate for a later *new-world* E2 test requires the
`SHIFT_RIGHT` six-way own-prototype mean to be at least 0.75 and its
world-level two-sided 95% lower bound above 0.5. If all 24 world scores are
exactly 1, use the two-sided exact binomial lower bound for 24/24 world-level
perfect outcomes instead of a zero-width Student-t interval; any other
zero-variance case is unresolved. It also requires that H4
feature IDs differ from canonical on every `SHIFT_RIGHT` cue; otherwise the
form merely preserves the exact key. If the gate fails, no E2 run follows
automatically. This threshold is operational feasibility, not a claim about
learning. `PREFIX` is never eligible regardless of its score. If it passes,
the E2 design still needs a fresh roster and a no-prior-teaching control.

This is **E0 only**: sensory accessibility, not E1 learning or E2 retrieval.
The exact-key and canonicalized-key countermodels are stated above; there
are no trained cues, changed-feedback encounters, or selected science
worlds. A technical fixture must verify cue lengths, semantic ordered pairs,
nonmutation, FE0 parity and feature-window expectations before the full
census. Source hashes, world roster and arithmetic receive a separate audit.
