# V35 — Shared Solver and Local Ownership Isolate
## Refined preregistration v2 — Codex-ready

## Status

**Design only. No V35 scientific outcomes have been observed.**

This document supersedes both the first `V35_design.md` draft and the intermediate `V35_design_refined.md` draft.

The refinement is based on the full V24–V34 trajectory, with particular weight on the completed V33 and V34 multi-wave results. It preserves the useful two-stage fork from the first draft but removes several confounds from Stage II.

V35 is deliberately narrow:

1. **Stage I:** determine whether the remaining failure of shared parametric memory is mainly an online-solver failure by replacing the greedy directional writer with exact cumulative recursive ridge / RLS.
2. **Stage II, conditional:** if Stage I does not qualify, isolate whether **item-local ownership of state** prevents overwrite. Stage II does **not** yet test bounded capacity, approximate retrieval, learned aliases, eviction, or a new fly-inspired routing system.

Maximum scientific workload:

\[
\boxed{64\text{ trajectories}}
\]

with 32 guaranteed Stage-I trajectories and at most 32 conditional Stage-II trajectories.

There is no automatic Stage III.

# 1. What prior rounds have already settled

V35 must not reopen mechanisms that the preceding program has already tested adequately.

## 1.1 Representation and task validity

V27 showed that apparent continual-learning improvements are uninterpretable when:

- the frozen model has no adaptation headroom; or
- “old memory” probes measure generic transfer instead of exact learned dependence.

V28 therefore established the requirement for exact arbitrary old bindings, no old replay, and genuine new-learning headroom.

V33 later established that **byte identity must remain bound to temporal position**. The exact lag96 code substantially improved same-key alias geometry and cross-rendering revision, but representation repair alone did not preserve old facts.

Therefore V35 keeps:

\[
\boxed{\text{exact lag96 for the shared-storage isolate}}
\]

and does not reopen encoder search in Stage I.

## 1.2 Shared coefficient overwrite is real

V29 isolated within-bank coefficient overwrite as the dominant storage damage in the overlap condition.

V30 showed that full historical coactivation geometry can reduce that damage:

\[
P=(I+\sum zz^\top)^{-1},
\qquad
q_P=\frac{Pz}{z^\top Pz}.
\]

Diagonal activity histories did not reproduce the effect.

V31 then transferred the full-covariance mechanism to a genuinely causal no-label byte stream.

Therefore:

\[
\boxed{\text{historical coactivation geometry is a validated interference-reduction primitive}}
\]

but not yet a persistent-memory solution.

## 1.3 Global familiarity / error gating stays retired

The autonomous V31 familiarity+error rule opened more often on:

- novel first-time contexts;
- one-off noise;

than on genuine revisions, and a simpler error-only control largely matched it.

V35 therefore contains **no global revision detector** and makes no claim that surprise/error itself identifies a revision.

## 1.4 MESU / diagonal uncertainty stays parked

The MESU experiment established genuine metaplastic dynamics but largely moved along the stability–plasticity frontier. Infinite horizon reproduced catastrophic remembering.

V35 therefore does not add a MESU arm or per-coordinate uncertainty mechanism.

## 1.5 V33 separated representation from memory

On the same paired V32 streams:

- lag ordinary retained only about 5.5% of untouched A after D;
- lag full covariance retained about 21.9%;
- full minus ordinary was about +16.4 percentage points;
- current D remained 100%;
- covariance reduced accumulated old-score disturbance;
- alias revision improved mainly because of the lag representation, not because of covariance.

Thus:

\[
\boxed{
\text{representation collision and shared-write interference are independent problems}
}
\]

and alias/generalization must remain separate from strict persistence.

## 1.6 V34 largely falsified the “bad geometry / cap” explanation

V34 introduced:

- fixed 768-unit expansion;
- sparse activation;
- one versus four local compartments;
- local block covariance.

The strongest C4-P arm improved the diagnostics that had looked pathological:

- effective rank increased strongly;
- covariance cap engagement fell from near-universal to only a few percent;
- requested directional amplification fell;
- same-key contexts had measurably greater overlap than different-key contexts.

Yet untouched A still collapsed to about 3%.

The especially important temporal pattern was:

\[
100\%\rightarrow76.6\%\rightarrow7.0\%\rightarrow3.1\%.
\]

Therefore sparse expansion and compartment wiring can produce impressive **one-wave delay** without durable persistence.

V35 consequently treats the following as demoted hypotheses:

\[
\cancel{\text{low effective rank is the main cause}}
\]

\[
\cancel{\text{direction-cap saturation is the main cause}}
\]

\[
\cancel{\text{static sparse compartment wiring alone is sufficient}}
\]

## 1.7 The exact dictionary remains a structural clue, not the answer

Across V32–V34, exact-context dictionary storage retained untouched exact contexts essentially perfectly while shared neural coefficients collapsed.

Its cumulative-count update revised poorly because historical counts dominated the later changed labels.

That establishes neither that dictionaries are a final architecture nor that explicit memory cannot revise.

The useful distinction is:

\[
\boxed{
\text{shared coefficients are repeatedly rewritten;}
\quad
\text{item-local state has ownership.}
}
\]

V35 is designed to determine whether this distinction is actually causal after the remaining shared-solver confound is removed.

### Strict-retention routing clarification

The V33 same-key bank-agreement statistics for different aliases do **not** impose a ceiling on the primary strict-retention endpoint.

Untouched-A retention is probed on the same two exact trained renderings that originally wrote the memory. Routing is deterministic for an exact context, so each strict probe returns to the same bank used by that rendering during acquisition.

Therefore Stage I does **not** add a single-bank live arm.

Bank mismatch remains relevant for:

- known-alias transfer;
- held-out-alias transfer;
- cross-rendering revision.

Those endpoints must be reported both overall and conditioned on whether the probe routes to a bank that was written by either trained rendering of that logical key.

# 9. Exact H-RLS definition

For each bank \(b\), maintain:

\[
W_b\in\mathbb R^{96\times256},
\qquad
P_b\in\mathbb R^{96\times96}.
\]

Initialize:

\[
W_b=0,
\qquad
P_b=I.
\]

For current normalized code \(z\), routed to bank \(b\), and observed one-hot next-byte vector \(y\):

\[
g
=
\frac{P_bz}{1+z^\top P_bz},
\]

\[
W_b^+
=
W_b
+
g
\left(y-W_b^\top z\right)^\top,
\]

\[
P_b^+
=
P_b
-
\frac{P_bzz^\top P_b}
{1+z^\top P_bz}.
\]

This corresponds to the exact cumulative ridge objective:

\[
W_t
=
\arg\min_W
\left[
\sum_{\tau\le t}
\|y_\tau-W^\top z_\tau\|_2^2
+
\|W\|_F^2
\right]
\]

within each routed bank.

There is:

- no 0.6 correction factor in H-RLS;
- no directional cap;
- no forgetting factor;
- no finite horizon;
- no replay;
- no phase-dependent weighting;
- no special treatment of targets, revisions, or noise.

Reported predictive probabilities use the same historical temperature:

\[
T=0.1.
\]

The RLS regression target is the one-hot **score vector**, consistent with the existing raw-score writers.

### Why there is no forgetting-factor RLS arm

V35 intentionally tests the exact all-history shared optimum first.

Exponentially weighted RLS would answer a different question:

\[
\text{where should the solver sit on a recency/stability frontier?}
\]

The program already has repeated evidence that finite horizons can trade retention against new learning. V35 therefore does not add an EW-RLS arm.

If exact H-RLS retains but fails revision while O2/O3 show that the current revised facts are jointly representable, classify the result as **catastrophic remembering / stale-history weighting** rather than as evidence that shared linear capacity is impossible.

# 10. Mandatory numerical verification for H-RLS

Scientific execution is blocked unless all deterministic RLS tests pass.

For several fixed random and adversarial sequences, compare online H-RLS against direct batch ridge:

\[
W_{\mathrm{RLS}}
\approx
(Z^\top Z+I)^{-1}Z^\top Y.
\]

Test:

- random full-rank streams;
- repeated identical \(z\);
- orthogonal \(z\);
- nearly collinear \(z\);
- repeated labels;
- contradictory labels on the same \(z\);
- multiple output dimensions;
- bank separation.

Require strict float64 agreement.

Also verify:

- \(P=P^\top\) numerically;
- \(P\) remains positive definite;
- direct solve and RLS scores agree;
- pause/resume is bit-stable where expected;
- evaluator probes do not modify \(W\) or \(P\).

# 11. Stage-I evaluator-only solvability oracles

A negative H-RLS result is otherwise ambiguous.

Therefore V35 adds **read-only, noncausal diagnostic fits**. They never produce live predictions and never change any learner.

These oracles are essential to distinguish optimization failure, stale-history weighting, and representational capacity.

## 11.1 Oracle O0 — all-history direct ridge

At each major checkpoint, reconstruct the sufficient statistics for **all byte events** observed by H-RLS and solve the exact batch ridge problem directly.

This must match H-RLS.

Purpose:

\[
\boxed{\text{implementation verification}}
\]

not a separate scientific arm.

Any material discrepancy invalidates H-RLS.

## 11.2 Oracle O1 — target-history ridge

Evaluator-only, use only target-position events accumulated so far:

\[
(Z_T,Y_T).
\]

Fit per routed bank:

\[
W_T=(Z_T^\top Z_T+I)^{-1}Z_T^\top Y_T.
\]

This oracle uses evaluator knowledge of target positions and is therefore **not deployable**.

Purpose:

> Determine whether the thousands of ordinary syntax/non-target byte constraints are crowding the arbitrary target associations in the all-byte shared objective.

Interpretation:

- H-RLS poor, O1 strong → ordinary stream objective crowding is important.
- H-RLS and O1 both poor → target facts themselves are mutually difficult under this shared linear substrate or stale target history.

## 11.3 Oracle O2 — current-fact ridge

At each after-wave checkpoint construct **one evaluator copy of every currently valid trained target rendering**.

For each context, pair its lag96 code with the target that is currently intended:

- original targets for ordinary untouched facts;
- new targets for genuinely revised facts after revision;
- one-off corrupt outcomes do **not** redefine the intended current fact.

Fit per bank:

\[
W_{\mathrm{current},1}
=
(Z_C^\top Z_C+I)^{-1}Z_C^\top Y_C.
\]

This removes stale-history weighting and repeated-presentation imbalance.

Purpose:

\[
\boxed{\text{Can the current facts coexist under the same lag96 + hard-bank linear substrate?}}
\]

## 11.4 Oracle O3 — current-fact minimum-norm fit

Using the same current-fact set, compute the Moore–Penrose least-squares / minimum-norm solution with fixed numerical tolerance.

No tuning from outcomes.

This is a pure representability diagnostic.

If O3 cannot score the current trained target contexts highly, then no online solver can make this exact fixed linear substrate satisfy them all simultaneously.

If O3 is near-perfect while H-RLS fails, the problem is **objective/history/solver dynamics**, not static linear representability.

- a surprise threshold;
- support counters;
- deterministic eviction;

A failure would not reveal whether the culprit was:

- ownership;

- allocation;

Therefore all approximate/bounded resource-management machinery is **deferred to V36**.

# 18. A second flaw in the old Stage-II design: residual state can become stale

Suppose a local memory stores an additive residual:

\[
s=s_B+r_c.
\]

Even if \(r_c\) is never touched by an unrelated example, the shared base score \(s_B\) can drift.

Then the final prediction for context \(c\) can change despite the local memory being perfectly preserved.

Therefore failure of an additive exact-context residual does **not** prove local ownership failed.

V35 v2 explicitly separates:

- **local residual ownership** (`LOCAL-R`);
- **local absolute ownership** (`LOCAL-V`).

This is one of the principal refinements.

# 23. Common error-triggered eligibility schedule

V35 Stage II needs a causal way to decide when local exception state exists, without smuggling in a task-position flag.

The rule is parameter-free.

At prediction time compute the **base-only** top-1 prediction:

\[
\hat y_B=\arg\max_j s_{B,j}.
\]

After the true byte \(y\) arrives:

- if \(\hat y_B\ne y\), mark exact context \(c_t\) **eligible forever**;
- otherwise do not newly activate it.

A newly eligible context may receive its first auxiliary-memory update immediately after the outcome that activated it.

Once eligible, it remains eligible.

Critically:

- the schedule depends only on the source-locked base and observed byte;
- it is identical for all four arms;
- it is **not** interpreted as a revision detector;
- V35 makes no claim that error-triggered allocation is biologically special.

This avoids repeating the V26/V31 mistake of praising a gate without matched controls.

`BASE` computes and records the same eligibility schedule evaluator-side but has no auxiliary memory.

For every seed, the eligibility-set hash must match exactly across all four arms.

---

# 24. Eligibility-coverage safeguard

Because eligibility is not the mechanism under test, a negative ownership result is interpretable only if the relevant facts actually became eligible.

Report, by first/second/fourth/eighth/terminal acquisition:

- fraction of trained target renderings eligible;
- fraction of untouched-A trained renderings eligible;
- fraction of all distinct exact contexts eligible;
- total eligible-context count.

If fewer than:

\[
\boxed{90\%}
\]

of untouched-A trained renderings are eligible by the end of A acquisition, then a failure of LOCAL-R/LOCAL-V on strict A retention is classified as:

\[
\boxed{\text{eligibility inadequate; ownership not falsified}}
\]

rather than evidence against item-local state.

A positive result remains valid even if coverage is lower, provided absolute retention is reported honestly.

# 25. Stage-II arm BASE

Prediction:

\[
s=s_B.
\]

No auxiliary memory.

The base still computes the common eligibility schedule for matching and diagnostics.

Purpose:

\[
\boxed{\text{shared statistical predictor reference}}
\]

# 26. Stage-II arm SHARED-R

Purpose:

> Test whether adding a separate residual pathway helps even when that residual state is still globally shared.

Maintain one matrix:

\[
R\in\mathbb R^{96\times256},
\qquad
R_0=0.
\]

If exact context \(c_t\) was already eligible before prediction:

\[
s=s_B+R^\top k_t.
\]

Otherwise:

\[
s=s_B.
\]

After observing \(y\):

1. update the base independently using \(s_B\);
2. apply the common eligibility rule;
3. if \(c_t\) is eligible after this event, update \(R\) from the raw score actually used for the auxiliary prediction:

\[
e=y-s_{\mathrm{used}},
\]

\[
q_0=\frac{k_t}{k_t^\top k_t},
\]

\[
R^+
=
R+0.6\,q_0e^\top.
\]

No covariance, no cap, no separate router.

This arm still has shared residual coefficients and can therefore suffer interference.

---

# 27. Stage-II arm LOCAL-R

Purpose:

\[
\boxed{\text{isolate item-local coefficients while retaining additive residual semantics}}
\]

For each eligible exact context \(c\), store:

\[
r_c\in\mathbb R^{256}.
\]

Initial:

\[
r_c=0.
\]

If \(c_t\) was already eligible before prediction:

\[
s=s_B+r_{c_t}.
\]

Otherwise:

\[
s=s_B.
\]

After outcome:

1. update base independently;
2. apply common eligibility;
3. if context is eligible, update only its local vector:

\[
r_c^+
=
r_c+
0.6\left(y-s_{\mathrm{used}}\right).
\]

No other context's local vector changes.

This gives exact coefficient ownership but remains vulnerable to later drift of the shared base \(s_B\).

That vulnerability is intentional and measured.

---

# 28. Stage-II arm LOCAL-V

Purpose:

\[
\boxed{\text{test absolute item-local ownership, immune to later base drift}}
\]

For each eligible exact context \(c\), store an absolute local score vector:

\[
v_c\in\mathbb R^{256}.
\]

Initial:

\[
v_c=0.
\]

If context \(c_t\) was already eligible before prediction, its local predictor **overrides** the shared base:

\[
s=v_{c_t}.
\]

If it was not yet eligible:

\[
s=s_B.
\]

After the observed byte:

1. update the base independently from \(s_B\);
2. apply the common eligibility rule;
3. if \(c_t\) is eligible, update only:

\[
\boxed{
v_c^+
=
0.4v_c+0.6y
}
\]

where \(y\) denotes the one-hot score vector.

Equivalently:

\[
v_c^+=v_c+0.6(y-v_c).
\]

This reuses the historical 0.6 immediate-correction scale without tuning.

Unrelated contexts cannot alter \(v_c\).

Later drift of \(s_B\) cannot alter the prediction whenever \(c\) retrieves its local value.

This is the cleanest ownership isolate in V35.

---

# 29. Stage-II prediction and loss convention

All reported probabilities use:

\[
p=\operatorname{softmax}(s/0.1).
\]

All auxiliary updates use **raw score errors**, consistent with V32/V33/V34.

Do not replace the historical score update with probability-gradient residuals.

For newly activated contexts, the prediction for the activation event was still the base prediction; the auxiliary state learns only after the byte is observed.

This preserves causality.

---

# 30. Why Stage II does not use approximate alias retrieval

V33 and V34 already demonstrated that:

- exact persistence;
- alias generalization;
- revision transfer across aliases;

are different capabilities.

V35 Stage II isolates exact ownership.

Therefore:

- no cosine threshold;
- no top-k slot retrieval;
- no key-centroid learning;
- no alias pooling;
- no learned identity;
- no semantic key.

Known-alias and held-out-alias probes remain visible diagnostics but **do not gate ownership qualification**.

If LOCAL-V preserves exact trained contexts but does not revise another alias, that is not a failure of the ownership hypothesis.

It means addressing/invariance remains the next problem.

---

# 31. Why Stage II is intentionally unbounded

The first V35 draft mixed ownership with a 256-slot capacity limit and eviction policy.

That was premature.

`LOCAL-R` and `LOCAL-V` therefore store every eligible exact context for this diagnostic workload.

State growth must be reported honestly:

- number of eligible contexts;
- key bytes;
- local vector bytes;
- Python/object overhead estimate;
- total resident state.

A success does **not** qualify a bounded lifelong learner.

It establishes only:

\[
\boxed{\text{item-local ownership is a useful missing primitive}}
\]

and licenses a later bounded-capacity experiment.

Bounded slots, eviction, approximate addressing, and consolidation belong to V36 if warranted.

# 33. Stage-II acquisition validity

For each live arm report:

- A after A;
- D-current;
- first target occurrence;
- second logical occurrence;
- first exact-rendering repeat.

A candidate cannot establish persistence through refusal to learn.

For ownership qualification, LOCAL-V must satisfy:

1. mean A after A \(\ge90\%\);
2. minimum seed A after A \(\ge75\%\);
3. mean D-current \(\ge90\%\).

Because exact aliases have distinct local addresses, second logical-key occurrence is not an exact-repeat measure. The first exact-rendering repeat is the more relevant local-memory sample-efficiency diagnostic.

# 34. Stage-II ownership qualification

A strong LOCAL-V ownership result requires all L1–L6 below.

## L1 — eligibility coverage

At least 90% of untouched-A trained renderings eligible by end of A acquisition.

If this fails, a negative ownership result is inconclusive.

## L2 — acquisition validity

LOCAL-V passes Section 33.

## L3 — absolute persistence

\[
\boxed{
\operatorname{mean}(A_{\text{after D}}^{LOCAL-V})\ge90\%
}
\]

on untouched A.

The threshold is deliberately higher than the historical 75% “promising” level because exact item-local ownership should nearly eliminate unrelated overwrite if the hypothesis is correct.

Also report the historical 75% threshold for continuity.

## L4 — ownership advantage

\[
\operatorname{mean}
(A_{\text{after D}}^{LOCAL-V}
-
A_{\text{after D}}^{SHARED-R})
\ge20\text{ pp}
\]

with paired 95% lower bound \(>0\).

Also report LOCAL-R−SHARED-R and LOCAL-V−LOCAL-R.

## L5 — fast exact revision

For rendering 0 of genuinely revised A:

- mean prequential accuracy on the **second changed occurrence** \(\ge75\%\);
- exact revised-rendering probe after four changed outcomes \(\ge90\%\);
- obsolete-old-target probability after eight changed outcomes \(\le0.10\).

This prevents “perfect memory” from becoming catastrophic remembering.

Known and held-out aliases are reported but not gated.

## L6 — whole-stream noninferiority

Mean:

\[
H_{\mathrm{LOCAL-V}}
-
H_{\mathrm{BASE}}
\le0.10\text{ bits/byte}.
\]

Report paired 95% interval.

An auxiliary memory that preserves facts while seriously degrading ordinary byte prediction is not a satisfactory two-system candidate.

# 36. Noise is diagnostic, not a V35 gate

A one-off corruption and a genuine revision are observationally similar at the instant of contradiction.

Fast local revision can therefore increase vulnerability to one-off local noise.

V35 does not introduce a noise/revision classifier.

Report for the one-off corruption cohort:

- pre-corruption exact accuracy;
- immediate post-corruption accuracy;
- old-target probability;
- wrong-target probability;
- whether the exact context was already eligible;
- local-state norm/change.

Crucially also report unrelated-A damage.

For LOCAL-V, unrelated local contexts should remain bit-for-bit unchanged.

Do **not** fail ownership qualification merely because one erroneous outcome damages the exact corrupted item. That is the separate future problem of distinguishing transient noise from persistent change.

# 37. Stage-II immutability / locality tests

# 39. Stage-II interpretation tree

## Case A — SHARED-R already solves persistence

If SHARED-R reaches high long-horizon retention while BASE does not:

\[
\boxed{\text{early statistical/residual separation was the missing architecture}}
\]

Item-local state may be unnecessary at this scale.

Do not complicate further before confirmation.

## Case B — LOCAL-R strongly beats SHARED-R and remains high

Then:

\[
\boxed{\text{item-local coefficient ownership matters}}
\]

and additive residual semantics are sufficient on this workload.

V36 should tackle bounded addressing/capacity.

## Case C — LOCAL-R fails but LOCAL-V succeeds

Then:

\[
\boxed{\text{item-local state must be anchored absolutely; additive residuals become stale as the base drifts}}
\]

This is a particularly informative outcome.

## Case D — LOCAL-V retains exact contexts but cannot revise exact context

Then local ownership is too rigid or the update is wrong.

Audit before adding any global gate.

## Case E — LOCAL-V succeeds exact persistence/revision but aliases fail

Expected interpretation:

\[
\boxed{\text{storage ownership solved locally; alias/addressing remains separate}}
\]

V36 should test approximate/bounded addressing one mechanism at a time.

## Case F — LOCAL-V fails and eligibility coverage is high

Then exact local ownership under this score update is not sufficient; audit the exact-context implementation and whether the probe really retrieves the same causal context.

Do not jump directly to another fly mechanism.

## Case G — LOCAL-V fails but eligibility coverage is low

Verdict:

\[
\boxed{\text{ownership untested because causal allocation failed}}
\]

The next experiment should isolate allocation, not storage.

# 43. Statistical reporting

Eight scientific seeds per stage are the independent units.

Use complete paired two-sided 95% Student-\(t\) intervals.

Do not use byte events as independent replicates.

Always show:

- raw accuracy;
- raw bits/byte;
- sample size;
- per-seed values;
- paired differences.

Normalized retention fractions may be reported only beside absolute acquisition and retention levels, using the same historical denominator guards.

No post-hoc multiple-arm winner selection.

The design has prespecified causal contrasts rather than a tournament.

## 43.1 Graded verdict taxonomy

Every prespecified causal contrast must receive both a **statistical-effect verdict** and, separately, an **architectural-qualification verdict**.

Use the following fixed vocabulary.

### `qualified`

All preregistered architectural gates for the relevant mechanism pass.

### `supported_below_qualification`

The primary paired causal contrast is directionally established:

\[
95\%\ \text{lower bound}>0
\]

but one or more absolute or minimum-effect qualification thresholds are missed.

Example: H-RLS improves A-after-D by +15 pp with CI entirely above zero but misses the +20 pp S3 requirement or the 75% S2 absolute threshold.

### `favorable_unresolved_precision`

The point estimate favors the candidate, but the 95% interval includes zero.

### `no_mean_advantage`

The paired mean effect is \(\le0\) and the interval does not establish a positive effect.

### `adverse`

The 95% upper bound is \(<0\), establishing a negative effect relative to the comparator.

### `invalid_acquisition`

The relevant acquisition-validity gate fails, so retention cannot be interpreted as persistence.

### `ownership_unresolved_due_to_eligibility`

Stage-II LOCAL-R/LOCAL-V fails while the L1 eligibility-coverage safeguard is not met.

These categories must appear in `SUMMARY.md`, not only in machine-readable detail.

A mechanism can therefore be scientifically supported without being promoted to the architectural mainline.

Historical context only; H-P is the continuity control.

Supported if H-RLS materially exceeds H-P in retention while remaining plastic.

Supported by high O2/O3 current-fact oracle performance.

Supported only if H-RLS passes **all S1–S6**.

Supported if LOCAL-R materially exceeds SHARED-R at matched base and eligibility.

**V35 cannot support this claim.**

# 46. Expected scientific value of each possible result

V35 is useful even if every candidate fails.

### If H-RLS retains and revises

We discover that previous “memory substrate” failures were largely solver failures.

### If H-RLS retains but cannot revise

We isolate catastrophic remembering from infinite historical weighting.

### If H-RLS fails while O3 is excellent

We know the facts can coexist statically, but the cumulative objective/history dynamics are wrong.

### If O3 itself fails

We have direct evidence that this fixed shared linear substrate lacks simultaneous representational capacity for the current fact set.

### If LOCAL-R succeeds

Shared base drift was tolerable; local coefficient ownership is the missing primitive.

### If only LOCAL-V succeeds

We learn something sharper:

> a persistent fact needs a prediction state whose meaning does not depend on a continually drifting shared predictor.

### If even exact LOCAL-V fails

The result points to an implementation/context-retrieval problem, not another generic anti-forgetting trick.

# 47. Central V35 falsifiable fork

The refined round is centered on:

\[
\boxed{
\begin{array}{c}
\textbf{Can a correct cumulative shared solver jointly preserve and revise the facts?}\\[2mm]
\textbf{If not, does exact item-local ownership prevent unrelated overwrite?}
\end{array}
}
\]

This is intentionally narrower than the first V35 draft.

If local ownership succeeds, the next round should ask:

\[
\boxed{
\text{How can that ownership be made bounded, approximate, alias-aware, and resource-managed?}

# 48. Evidence basis for this refinement

The design is grounded in the supplied project artifacts:

- `v32_results_and_verification.md`
- `v33_results_and_verification.md`
- `v34_scientific_results_audit.md`
- `v34_protocol.md`
- the BANC-derived learning-core and architecture-distillation reports
- the older Liquid Baby / ELM cumulative-readout results

Key prior empirical facts motivating the changes include:

1. V33 full covariance gave a real retention gain over ordinary writing but only about 22% absolute A retention after D.
2. V33 improved alias geometry and revision through the lag representation, while whole-stream prediction favored the older temporal current-code representation.
3. V34 reduced covariance cap pathology and increased effective rank dramatically without preserving old A.
4. V34 sparse/compartment mechanisms looked strong after one interference wave and collapsed after the next.
5. Exact context storage retained old exact facts, while its count semantics—not explicit storage in general—caused slow revision.
6. The earlier Liquid Baby lineage repeatedly favored cumulative sufficient-statistic readouts, motivating the exact RLS isolate.

These are treated as empirical constraints on V35, not as proofs of the eventual architecture.

# 49. Codex implementation notes added in v2

This Codex-ready revision makes the following final protocol decisions explicit:

1. **No single-bank live RLS arm.** V33 alias bank-agreement values do not cap exact untouched-A retention because exact renderings deterministically return to their training banks.
2. **No route-free global oracle is added.** A naive one-global-matrix fit changes the parameterization and would not cleanly isolate routing relative to eight independent bank matrices. Route-conditioned diagnostics are used only for alias/revision endpoints where routing mismatch is actually relevant.
3. **No forgetting-factor RLS arm.** Exact all-history RLS is the intended mathematical isolate; stale-history rigidity is diagnosed by revision gates plus O2/O3.
4. **Stage-I bpb is diagnostic, not a skip/run gate.** The fixed historical temperature is retained for comparability, but no scientific-data calibration is fitted.
5. **C0 explicitly tracks covariance replication across V33, V34, and V35.**
6. **Graded verdicts are mandatory.** Missing an architectural threshold does not erase a statistically supported sub-threshold mechanism effect.
7. **Stage-II approximate/bounded episodic machinery remains deferred.** V35 tests exact ownership first.
