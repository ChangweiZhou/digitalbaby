## 2. Stream and worlds

**World generator.** The frozen `bytecore.create_world(ns, block, index, "R2", "massed")` is used unchanged.
- Seeds are `BYTE-CORE-1|<ns>|<block>|<index>`.
- Each world is checked by the frozen `audit_world`.
- Keys are audited disjoint across all FEAS-1 namespaces and all BYTE-CORE-1 namespaces (Q9).

| Namespace | Block | Indices | Use |
|---|---|---|---|
| `FEAS1-ENG` | `Q` | 0–1 | Technical fixtures only |
| `FEAS1-CAL` | `K` | 0–7 | Readout and NLMS-rate fitting |
| `FEAS1-DEV` | `D` | 0–15, plus 16–31 for the extension | Development (selection) |
| `FEAS1-CON` | `V` | 0 … n_V − 1 | Confirmation. Generated only after `CONFIRM_PLAN.json` is hashed |

**Format.** F3 only, with the frozen `render_record`:
- 14 bytes: `~|~|` + header[w] + key with XOR mask[w] on key bytes 0–1 + separator[w] + consequence + newline;
- the wrapper alternates per presentation of a cue (w = presentations mod 2);
- byte spacing is 30/14 s.

F3 records are 14 bytes, so no 12-byte window reaches the previous record (erratum §10).

**Probes** (frozen `run_life`, read-only):
- immediate, day, final (7-day), reactivation and revision-curve probes;
- F4 probes (wrapper 2) at day checkpoints.

**Life (every world).**
- 3,648 scored consequence events, in 1,824 trials of 2 records each.
- 13 day checkpoints. 12 of them carry relevant-pair probes, 320 probes per life.
- In-stream events between consecutive day checkpoints, windows W1–W13: 576, 288, 288, 288, 288, 288, 144, 336, 144, 360, 144, 360, 144.

## 3. Learner and adapter (frozen)

**FULL_151.**
- Genome and all locked objects are as in BYTE-CORE-1 §4.2: the PN→KC matrix B and reader Q are installed explicitly, not redrawn.
- Mutable learner state is 165,664 bytes.

**Adapter `S0-EPISODE`** (frozen `F151Learner.present`, episode mode, write on, US route on). For each record:
1. The front end is fed the context bytes at their times.
2. Immediately before the consequence byte, the front end is read. Its output is encoded live with `encode_sparse`, and the read-only reader-relative response v (Hz) is recorded. That is the prediction.
3. The innate detector reads the consequence byte: 0xF1 → punishment 1, 0xF0 → 0. The learner receives one 30 s event with that code and punishment, then the 135 s gap.

Only the innate detector sets the read moment. It sees a reserved byte, and it is not a record-boundary label.

## 4. Front ends

Every front end:
- receives only (byte, time);
- keeps all state in counted arrays;
- has no learned parameters;
- is identical across worlds.

The shared receptor table **R** ∈ ℝ^{256×88} is frozen: for each byte, 6 channels without replacement, amplitudes U[0.4, 1.0], seed `BYTE-CORE-1|RECEPTOR|v1`.

| Arm | Status | Definition | State | Basis (evidence label) |
|---|---|---|---:|---|
| **FE0** | Reference; frozen `bytecore.FE0` | p ← p·e^(−Δt/10 s) + R[b] per byte. Read: p/max p | 88 floats | Receptor code and PN integration (Hallem & Carlson 2006, R) |
| **FE1** | Candidate; frozen `bytecore.FE1` | Input R[b]⊙(1 − h). Per byte: h ← clip(h + 0.3·(1 − h)⊙R[b], 0, 1). Between bytes: h decays with τh = 1,800 s. p as FE0 | 176 floats | Odorant-selective habituation via glomerulus-selective potentiated inhibition (Das et al. 2011, C+) |
| **FE-NI** | Candidate; new | FE0 integration, plus a negative image m of the sampled pattern (below) | 176 floats | Das et al. 2011 (C+); negative-image proposal (Ramaswami 2014, T) |
| **FE1-NI** | Candidate; new | FE1 integration, plus the same negative image | 264 floats | As its two parents |
| **FE-LAG** | Engineering baseline; frozen `bytecore.FELAG`; never selectable | V51 lag code of the last 12 bytes, random signed 8-contact adaptor into 88 channels, tanh, rectified, normalized | 12 bytes | Delay lines; not claimed biological |

### 4.1 FE-NI, exactly (FE1-NI identical, with FE1's p)

- **State:** p ∈ ℝ^88 (as FE0) and m ∈ ℝ^88 with m₀ = 0.
- **feed / advance:** exactly as FE0 (as FE1 for FE1-NI). **m never changes in feed or advance**, so there is no decay in silence.
- **read** (called by the learner once per record, at the read moment):
  1. p̂ = p / max p (the zero vector if p = 0).
  2. o = max(p̂ − m, 0) elementwise.
  3. Output = o / max o. If max o = 0, the output is the zero vector: `encode_sparse` then returns an empty KC code and no write occurs. Such reads are counted.
  4. **After** the output is formed: m ← m + (p̂ − m)/128.
- **Probes** read a clone (frozen `probe` clones the front end), so the live m never changes during a probe (Q4).
- **What m sees:** only pre-consequence samples. The read precedes the consequence byte's feed (Q3).
- **Parameters, derived rather than tuned** (Appendix A):
  - **N_m = 128.** Massed acquisition gives the same two cues 12 consecutive samples, which then make up ≤ 9% of m. m reaches 95% of a constant component after 382 samples, inside block 0 (576 samples).
  - **Subtraction weight 1.** This tests the common-component hypothesis at full strength.
- **Modelling choices, disclosed:**
  - the update is locked to the read moment, which is set by the innate detector the learner already uses;
  - the subtraction is full and input-driven. The more faithful output-driven form, which cancels only part of a constant component, is deferred;
  - m does not decay. Long-term olfactory habituation lasts more than 24 h (Roselli et al. 2024, protocol citing prior work).

**Not in this round:** FE-SURP (dropped as defined), the output-driven negative image, a sparser receptor table, and kernels tied to slot geometry (roadmap §3.3).

## 5. Declared readout

For every arm, and on its own CAL lives:

1. **Score.** s_e = −v_e for each scored event e (FULL_151's sign convention: the punished cue responds lower).
2. **Model.** p_e(aversive) = σ(a·s_e + c).
3. **Data.** All scored events of the 8 `FEAS1-CAL` lives are pooled. Every life has 3,648 events, so worlds are weighted equally.
4. **Fit.** Maximize the mean Bernoulli log-likelihood (natural log) against the **delivered** byte.
   - The problem is convex in (a, c). It is solved by Newton's method (IRLS) from (0, 0), stopping when max |gradient| < 10⁻¹⁰.
   - Probabilities are clipped to [10⁻¹², 1 − 10⁻¹²] inside the objective only.
   - One function, with one call signature, serves every arm.
5. **Freeze.** (a, c) per arm is written to `READOUT.json` and hashed **before** any `FEAS1-DEV` world is generated. The UNPAIRED control inherits its parent candidate's readout.
6. **Use.** Every later η uses the frozen (a, c), with the BYTE-CORE-1 clip ε = 10⁻³. Day probes, the final probe and every window use the same (a, c); nothing is recalibrated.
7. **No online correction.** If the frozen readout becomes less usable as the learner changes, that is a property of the tested strategy.

The CODE-NLMS learning rate (reference only) is chosen in the same phase by maximum η on CAL over the frozen grid {0.1, 0.3, 1, 2}.

## 6. Outcomes

### 6.1 Primary

**In-stream η (BYTE-CORE-1 §5.2), per world.**
- For each scored event, p̃_e(y_e) = clip(p_e if y_e is aversive, else 1 − p_e; ε, 1 − ε).
- Bits saved: s_e = log₂ p̃_e(y_e) + 1. Relevant information fed: i_e = log₂ 2 = 1.
- η = Σ s_e / Σ i_e over the life's 3,648 events.
- Truth is the **delivered** byte, anomalies included.

**Primary contrast.** Δη = η(candidate) − η(FE0), per world, on identical worlds.

**Units.** Δη = 0.02 means 2 bits saved per 100 bits of relevant consequence information fed. It is not 2 percentage points of accuracy.

### 6.2 Reported with it

A quantity decides nothing unless §8 names it.

| ID | Quantity | Definition |
|---|---|---|
| R1 | In-stream AUC | P(score of an aversive event > score of a neutral event); ties count ½. Measures discrimination, not calibration; pooled AUC can still move with time-varying offsets |
| R2 | Native paired accuracy | Per trial: side-0 vs side-1 response; the lower one is predicted punished; ties count ½ |
| **R3** | **Day-probe η** | Relevant-pair probes at the 12 day checkpoints that have them (320 per life). Frozen readout; scored against committed truth (frozen `TruthTimeline`), because probes have no delivered byte. **Used in §8** |
| R4 | Day-probe AUC | Same probes |
| R5 | Final 7-day probe η and AUC | Descriptive |
| R6 | Window and checkpoint calibration summaries | For W1–W13 and for each day checkpoint's probes: η, observed aversive frequency, **unconditional mean of p_t**, AUC, n. Comparable with prevalence only as a mean-calibration check; it does not diagnose calibration across the score range |
| R7 | Offset | Share of scored events whose baseline-relative response (learned minus no-learning copy, frozen `raw_actual`) is below 0; mean per window |
| **R8** | **Cross-record diagnostic** | AUC over first presentations of side-1 cues, where nothing cue-specific can yet be known. **Flagged if the arm's own 95% CI lies above 0.5.** It is not a difference vs FE0: generalization from the partner cue taught just before pushes this AUC below 0.5 by an amount that depends on code overlap (FE0 0.486, FE-ID 0.494; erratum §10), so a difference would false-alarm for lower-overlap front ends. The absolute test cannot false-alarm this way. It can miss a small cue masked by that generalization, which condition S2 (§8.1) covers. **Used in §8** |
| R9 | CODE-NLMS reference | Online logistic regression with bias, on the same KC codes: η and AUC. One reference learner; not a measure of information content |
| R10 | Live interface statistics | Per read: active KCs; Jaccard with the same cue's previous code; Jaccard between the two cues of a trial; empty reads |
| R11 | Resources | Front-end state bytes; learner mutable bytes; wall time |
| R12 | F4 (held-out wrapper) day probes | η and AUC, descriptive |

## 8. Decision rules

**Statistics.**
- The unit is the world. Arms are paired on identical worlds.
- Per-world differences vs FE0: mean, SD, and a 95% two-sided t interval with df = n − 1.
- Development is selection: no multiplicity adjustment. Confirmation is one pre-specified contrast.

### 8.1 Development at n = 16

For each candidate c ∈ {FE1, FE-NI, FE1-NI}:

| Status | Condition |
|---|---|
| **SELECTABLE** | All three: (S1) mean Δη ≥ 0.02 **and** CI lower bound > 0; (S2) day-probe η mean(c) ≥ mean(FE0); (S3) if R8 flags c, its day-probe Δη CI lower bound > 0 |
| **FUTILE** | CI upper bound of Δη < 0.02 |
| **INCONCLUSIVE** | Neither |

FE-LAG is evaluated and reported on the same terms, but is never selectable.

### 8.2 Extension (development, not confirmation)

The extension runs **only if** no candidate is SELECTABLE at n = 16 **and** at least one is INCONCLUSIVE.
- It runs FE0 and every INCONCLUSIVE candidate on `FEAS1-DEV` 16–31.
- §8.1 is re-applied at n = 32. Anything not SELECTABLE is then **NOT_SELECTED**.
- There is no second extension. Looking twice is accepted **because this is selection**; the untouched confirmation carries the inference.

### 8.3 Selection

- Among SELECTABLE candidates, the one with the **largest lower 95% bound of Δη** is chosen. A tie goes to the smaller front-end state.
- **Wording:** "positive gain supported; estimated gain meets the materiality threshold". Never "a gain of at least 0.02 established".
- `SELECTION.json` (the decision plus the n = 16 record, and the n = 32 record if extended) is written and hashed before anything else happens.
- **If none is selected:** `NO_CANDIDATE_SELECTED`. The round stops after reporting.

### 8.4 Confirmation plan (fixed before worlds exist)

- n_V = max(32, ⌈(t·SD_D / (Δ̂_D/2))²⌉). Here SD_D and Δ̂_D are the selected candidate's per-world Δη SD and mean at its final development n, and t is the 0.975 t quantile at df = n_V − 1, solved by iteration.
- If n_V > 64: `NOT_CONFIRMABLE_THIS_ROUND`, and nothing is run.
- `CONFIRM_PLAN.json` (candidate, n_V, frozen readout hash, and the arms: candidate, candidate-UNPAIRED, FE0) is written and hashed. **Only then** are `FEAS1-CON` worlds generated.
- n_V is computed from the selected estimate, which is biased upward by selection. That is why confirmation uses untouched worlds.

### 8.5 Confirmation claims

| Claim | Conditions, all on `FEAS1-CON` |
|---|---|
| **"Positive gain confirmed; estimate meets materiality"** | CI lower bound of Δη > 0 **and** mean Δη ≥ 0.02. Day-probe mean Δη ≥ 0. Pairing check: AUC(candidate) − AUC(candidate-UNPAIRED) has CI lower bound > 0 |
| **"Gain ≥ 0.02 confirmed"** | All of the above, **and** CI lower bound of Δη > 0.02 |

The pairing check uses AUC because a parent's readout makes control arms confidently wrong, so their η is not comparable (erratum §2 caveat).

### 8.6 Outcome labels

| Label | Meaning | Next (roadmap) |
|---|---|---|
| `FRONT_END_IMPROVES_OVER_FE0` | §8.5 first row met | The byte line adopts it; the S2 bridge (§3.2 b) uses it. **Not** S2 readiness |

## 12. What results can and cannot claim

- **Complete strategies.** A win means the front end + frozen learner + declared readout beats FE0 + frozen learner + the same readout procedure. It says nothing on its own about code information.
- **Scope.** R2/F3, FULL_151 frozen, this world family. There is no claim about other rungs, formats, V50, or general raw-byte learning.
- **Not S2 readiness.** S2 changes the stream (0xF2 marker) and the teaching interface. Readiness is decided by the S2 bridge (roadmap §3.2 b).
- **Mechanism readings are observations.** A win for FE-NI does not by itself establish that the offset caused FE0's loss. FE-NI also changes code sparsity and overlap. The factorial and NLMS contrasts are descriptive.
- **Calibration summaries (R6) are descriptive.** A changing intercept bias is a property of the tested strategy, not a defect to correct.
- **Frozen oracle and no-learning numbers** appear in the report as context only.

## Appendix A — FE-NI parameters

**Self-cancellation.** In massed acquisition, a pair is taught for 6 trials, which is 12 consecutive reads of the same two cues. Their share of m after those reads is 1 − (1 − 1/N_m)¹². With N_m = 128 this is 1 − (127/128)¹² = 0.090, about 4.5% per cue.

**Convergence.** A constant component reaches 95% of its value in m after ln(0.05)/ln(127/128) = 382 reads. Block 0 has 48 pairs × 12 reads = 576 reads.

**Subtraction weight.** Full subtraction tests the hypothesis at its strongest. A weaker, output-driven form leaves a residual of c/(1 + w) for a constant component c.
