# MiniFly byte arithmetic evolution — prospective design

## Question and evidence boundary

Can an individual with a bounded, fly-derived sensory substrate learn to answer **new** arithmetic expressions from sequential ASCII bytes, using few examples and only the consequence of its own answer? This is an engineering stress test for online compositional learning. Arithmetic is harder than ordinary fly memory; failure here does **not** disprove a biological persistent-learning core. Success without an individual-level learning gain is evolved calculation, not lifetime learning. This v1 uses a new action head with 257 integer actions; it is an exploratory architecture, not an assertion that the inherited mushroom-body memory alone can compute arithmetic.

The user's current instruction supersedes the attached memo's recommendation to stop mechanism search. This study does not change frozen V50–V9.10 results. The base sensory route is the unchanged V9.2/FULL_151 FE0→PN→KC circuit. Its next-byte predictor and inherited value writer remain distinct. A new, explicitly charged answer/action and negative-feedback learning head is required; the V9.2 next-byte score must not be counted as arithmetic output.

## Information protocol

An expression is delivered one byte at a time as ASCII, ending in `=`. Optional 0–2 visible ASCII spaces vary timing/placement. The individual receives no operand array, operator ID, abstract syntax tree, pair ID, hidden answer, correct output digits, signed numerical error, or teacher-forced retry. It emits one integer action; the wrapper serializes that action to signed decimal ASCII for exact-answer scoring. **This first version tests byte input and numeric action selection, not autonomous multi-byte answer generation.** After the complete answer, the evaluator emits only a direction-free severity grade: `0` if exact, `-1` for absolute error 1, `-2` for 2–3, `-3` for 4–7, `-4` for 8–15, and `-5` for 16 or more. The correct answer and whether to move up or down are never given. The learner can infer a symmetric interval of candidate outputs from its own action and the grade; that inference occurs inside the model. All scored novel queries are read-only and precede feedback.

Every genome is assessed in multiple independent lifetimes. The genotype, fixed encoder, and innate initialization persist between generations; learned weights do not. Train and test expression strings within a lifetime are disjoint. Development worlds vary each generation. A sealed confirmation roster is not used for parent selection or hyperparameter choice. Every reported result includes the same genome at training sample budgets 0, 32, 128, and 512; optional 2,048 is a later costed stage, never silently added after seeing a failure. Matched plasticity-off and feedback-shuffled/no-feedback arms see the same bytes and clocks.

## Staged tasks

| Stage | Input and target | Promotion question |
|---|---|---|
| 0 — interface | one observed digit followed by `=`; output that digit | Can the byte/action/feedback pipeline work at all? This is not arithmetic. |
| 1 — operations | one- or two-digit `a op b =`, each of `+ - * /`; division is exact, divisor nonzero and nontrivial where feasible | Does feedback improve **unseen operand combinations** for every operation? |
| 2 — mixed | `a op b op c =`, two distinct operators and standard precedence | Does the same learner handle new operand triples and operator orders, including `a+b*c` versus `a*b+c`? |
| 3 — four-operation | expressions containing `+ - * /` at least once, exact integer divisions, signed bounded result | Does the frozen genome answer new mixed expressions rather than only single-op or memorized templates? |
| 4 — persistence | additional unrelated arithmetic episodes and time gaps after Stage 2/3 learning | Does earlier unseen-query competence survive while new problems are learned? |

The primary accuracy is exact signed-decimal answer equality on first responses. Report per-operation and per-template accuracy, answer range, exact expression duplicates, and sample-to-threshold curve. The initial useful-competence gate is at least 50% overall on a balanced 64-query unseen Stage 1 panel, at least 25% in every operation stratum, and a paired improvement of at least 10 percentage points over both the same-genome zero-feedback and plasticity-off controls on independent lifetimes. These are **engineering promotion thresholds**, not a claim of general arithmetic mastery. For Stages 2–3, prespecified held-out operator-order templates and exact-query exclusion are necessary. A genotype is promoted only after an untouched confirmation panel; developmental accuracy alone cannot promote it.

The Stage 1 operand bound is 63 rather than 9. The one-digit nontrivial exact-division pool contains only 14 canonical expressions, so it cannot supply hundreds of distinct training questions and a balanced untouched test. The revised finite support is audited by `benchmark.support_counts`; the expression generator raises on exhaustion rather than recycling a taught expression as a supposedly new problem.

Wrong answers on unseen problems lower fitness and unqualified individuals are removed from parent selection. The fly-swat criterion is the 90th percentile of absolute error on a fixed-size, novel, first-answer panel. A candidate is eliminated if that value **exceeds** the phase's error threshold. This interpretation follows the requested tightening threshold: poorer answers die. A literal one-error-kills rule on a stochastic 64-question panel would extinguish useful partial lineages. The threshold tightens from 128 to 64 to 32 on single-operation problems, then to 16 for two-operator expressions and 8 for four-operator expressions; exact accuracy is a separate required gate so a near-miss specialist cannot be called a calculator. Fitness is graded among surviving candidates, and a stage is not promoted until its qualification gate passes. If no candidates qualify within the budget, record extinction or a failed stage rather than lowering the threshold after seeing scores. The final champion must meet the gate on untouched lifetimes. Best-of-generation scores are never themselves the confirmatory result.

## Mechanism grammar and controls

The 50-plus mechanism catalog is pruned to **computational families** rather than 56 independent genes. Relevant mutable choices are: causal temporal trace/eligibility; sparse KC and short byte-history feature balance; feedback-gated local write; fast versus slow persistent state; output/readout gain and exploration. The first bounded search includes two teaching topologies: suppress the punished action, or add internally inferred symmetric candidate-output rings based on the severity grade. Dynamic rewiring, molecular-specific Orb2/Rac1 implementations, sleep, and extra episodic banks are conditional later branches, not automatically installed. Evolution may change local update parameters and this teaching topology within the declared family; each added state is accounted for. Candidate arithmetic success must be compared to an exact-expression cache, a zero-shot genome, plasticity-disabled and shuffled-penalty controls, and an explicitly labeled symbolic arithmetic upper bound. The symbolic bound is **not** a fly candidate and cannot establish within-life learning.

An evolved genotype may genetically encode arithmetic or exploit fixed ASCII ordering. Therefore zero-shot performance and randomized-life controls are essential: if trained and untrained copies perform equally, call the result evolved computation. If a new problem was answered after its own answer had appeared, it is not held out. Fresh random seeds alone do not turn recitation into E3. The intended positive claim is E3 reuse within the tested arithmetic family after causal teaching; natural-stream/E4 competence remains untested.

## Execution and stopping

Preflight must check byte order, expression semantics, division, feedback isolation, output scoring, clone/no-write parity, train/test exclusion, deterministic world generation, and exact source hashes. The first pilot determines whether this declared architecture has a useful learning signal at all; a failed pilot is reported, not disguised by a long search. Freeze source, genome space, fitness, phase thresholds and confirmation roster before any large search. The Mac runner uses four workers with single-threaded BLAS, resumable generation receipts, a wall-time cap, and compact per-genome metrics. It retains no raw per-question trajectories or source-dataset copies. If no Stage 1 candidate passes its development gate within the search budget, report that bounded negative result and stop; do not quietly lower the gate or pretend Stage 2/3 were tested. Longer expressions test **within-expression working state**; separate retention tests are needed before claiming persistent across-episode memory.
