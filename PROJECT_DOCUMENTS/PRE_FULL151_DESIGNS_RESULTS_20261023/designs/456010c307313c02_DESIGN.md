# Step 14: target-channel-only plastic teaching at 16-item load

## Question and evidence boundary

Step 13's frozen FE0+fading-pair front end and four native Full151 output stores achieved 90.04% aggregate E1 recall on 16 directly taught byte strings, but failed its per-cue gate: `1+1=` was correct in 12/32 worlds and usually emitted byte `3` rather than its taught byte `2`. This experiment changes **only the plastic-write routing policy**. Can writing to the arriving answer byte's own output store, while suppressing plastic writes in the three nontarget stores, produce uniformly reliable recall on the same 16-item task? The result is a bounded **E1 policy comparison**, not learned addition, E3 transfer, or proof that negative updates alone caused Step 13's error.

The input remains Step 6's fixed FE0+fading-pair 88-PN route. The parent checkpoint, four copied native Full151 stores, `a+b=` cues, per-world balanced arbitrary byte labels, 12 exposures per cue, 192 records, 165-second record clock, answer-byte decoding, and fixed `=` output rule remain Step 13's. All policy arms receive identical cue bytes, answer bytes, labels, timing, and teacher calls. The model chooses before the teacher byte arrives. Every output store senses that byte and receives a native `teach` call at the same time in every policy arm. The only intervention is each `teach` call's plastic `write` flag:

| Policy | Target store | Three nontarget stores | Plastic writes per life |
|---|---|---|---:|
| `OPP` (Step 13) | `teach(0, write=True)` | `teach(1, write=True)` | 768 |
| `TARGET` | `teach(0, write=True)` | `teach(1, write=False)` | 192 |
| `N` | `teach(0, write=False)` | `teach(1, write=False)` | 0 |

Thus all stores still receive the answer byte and have 192 teaching calls and the same learner clock. Plastic event count changes fourfold. Even a rescue attributes benefit to this **policy as a whole**—removing nontarget plastic writes and lowering total plastic dose are not separately identified.

All 16 canonical cues are directly reinforced, and an exact-key codebook can solve the primary endpoint. The Step-13 spacing variant (`7 spaces || a || space || +b=`) is never taught and is a descriptive E2 check only. A fixed whitespace canonicalizer plus exact-key memory could solve it. The nine fixed cue labels and seven per-world shuffled labels remain those of Step 13; no arithmetic rule explains the full balanced answer assignment.

## Frozen execution and decisions

Technical world **14000** is excluded. The pilot uses exactly **14001–14008**; confirmation, only if pilot passes, uses **14101–14132**. All are fresh and disjoint from Step 13. No earlier trajectory is rerun or pooled into a new interval. A technical gate checks parent/source hashes, exact fixtures, cloned birth state, all 16 pair KC codes distinct, output-before-teacher ordering, identical sensory and clock histories across arms, byte-derived routes, exact per-class plastic flags and write counts, read-only probes, and independently validated receipts. A science exception stops with a failure receipt; worlds are never replaced.

The pilot is feasibility only and is not included in confirmation. Proceed if `TARGET` W canonical accuracy is at least **65%**, `OPP` W canonical accuracy at least **75%**, `TARGET−N` canonical difference at least **25 percentage points**, and all four answer classes are represented correctly at least once under `TARGET`. Failing this coarse gate yields `PILOT_STOP` and no confirmation.

The confirmation's conjunctive **policy rescue** rule requires:

1. `TARGET` W canonical accuracy at least **85%** over 32 worlds × 16 cues;
2. `TARGET` W correct on **every** cue in at least **24/32** worlds;
3. the 32-world paired `TARGET−N` canonical difference has a two-sided 95% Student-*t* interval with lower bound above zero; and
4. the 32-world paired `TARGET−OPP` correct-choice difference **on the prespecified focal cue `1+1=`** has a two-sided 95% Student-*t* interval with lower bound above zero.

If conditions 1–3 pass but 4 does not, report `TARGET_SUFFICIENT_NOT_ATTRIBUTED`; if any of 1–3 fails, report `TARGET_POLICY_RESCUE_NOT_DEMONSTRATED`. Zero world variance makes any interval-based condition unresolved. Also report the Step-13-style sufficiency gates for `OPP`, every cue and answer class, the overall `TARGET−OPP` paired contrast, both W−N effects, and the spacing-variant results regardless of verdict. The primary uncertainty unit is the paired world. No gate is changed after pilot or confirmation outcomes are inspected.

Increasing from four to 16 cues still changes total records and simulated learner time relative to Step 6; this experiment holds those fixed *between policies*. It tests whether a practical teaching policy can repair the existing 16-item failure. It cannot alone distinguish nontarget punishment from total-write dose, establish E3 reuse, or certify a unified generalizing system. No role-code, dual-bank, or search round starts automatically.

## Integrity and cost

Before technical execution, hash this design, runner, independent auditor, inherited Step-13 and earlier sources, and Step-13 result provenance. Atomically commit compact per-world receipts rather than raw trajectories. The independent auditor regenerates byte streams without importing the new learner runner; checks all labels, probes, four-value argmax outputs, write-flag sequences, times, and published reductions; and rejects deliberate receipt tampering. Run the technical audit before pilot and the pilot audit before confirmation. Keep `caffeinate` attached to active learner runs only.
