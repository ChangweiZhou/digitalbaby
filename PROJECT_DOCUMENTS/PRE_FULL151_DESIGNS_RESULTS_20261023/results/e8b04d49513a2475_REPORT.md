## Interpretation and accounting

- During-learning accuracy uses predictions made before the corresponding teaching outcome. The next-recurrence endpoint uses the first return after one prior presentation; inspect task-specific counts and revision conditions.
- A broad read of saved supervised state is a second evaluation view, not another trained trajectory or additional external experience. Missing online values remain n/a.
- Screen and confirmation cohorts have distinct full configuration identities and are never silently pooled. The confirmation roster was fixed before results.
- SUMMARY_BY_SEED.csv and SUMMARY.csv preserve every numeric terminal endpoint. PAIRED_BY_SEED.csv and PAIRED_SUMMARY.csv retain all declared matching-seed contrasts, including sample efficiency and resource deltas.
- Confidence intervals are descriptive two-sided Student intervals across independent seeds, without multiplicity adjustment. Single-seed uncertainty is undefined. A missing or incomplete comparison is inconclusive.
- Gates apply only to their explicitly declared endpoints. Retention and late plasticity cannot substitute for good first-example learning, structured transfer, or the value of encoder adaptation.
- COSTS.csv keeps reported numeric learner state, teaching state, temporary arrays, simulation work, development and evaluator costs separately. Numeric bytes exclude Python object overhead.
- Development exposures are separate from online experience. Shared outcome-independent feature computations do not create new sensory examples or make the simulated learner computation free.
- No configuration is declared a winning biological model by these mechanism tasks. ELM, simpler cells and local learning rules must be judged by the tested behavior.
- The ZIP contains compact tables, manifest, design policy, executing source, source identity and verification. Raw completed-job records remain on disk for resume. The shared sensory cache is bounded in memory and regenerated when needed; no persistent feature cache is saved.

See DESIGN_POLICY.json for the preregistered roster rationale, MANIFEST.json for exact configurations, RUN_STATUS.json for scope, COMPATIBILITY_GATES.csv for joint adaptation requirements, DECISION_GATES.csv for other declared margins, and MISSING_PAIRS.csv for absent controls.
