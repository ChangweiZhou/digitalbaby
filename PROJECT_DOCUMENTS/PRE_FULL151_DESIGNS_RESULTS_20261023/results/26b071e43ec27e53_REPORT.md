# Step 15 — fixed role-code component screen

**Outcome: the role input code did not pass the prespecified two-part screen.** It improved limited held-out relation choice in the one-store assay, but directly taught 16-cue recall in the four-output-store assay reached only **340/512 (66.4%)**, below the frozen 70% candidate threshold. This is evidence against using this particular fixed role code as the single input route for the next bridge experiment. No parameter retuning or follow-up architecture was launched.

## What was frozen and run

The [design](DESIGN.md) fixed one label-free 88-PN code before new worlds: FE0 plus decaying earlier-byte and later-byte traces from fixed contacts. The FE0 control and ROLE candidate received the same bytes, labels, clocks and native Full151 write flags within each world. Technical worlds 15000 and 15200 and eight pilot worlds per assay were excluded from confirmation. The taught-only relation pilot and directly taught capacity pilot both passed their feasibility guards. Exactly 32 new confirmation worlds per assay then completed, with no replacement or earlier trajectory rerun. The source lock is in [SOURCE_LOCK.json](results/SOURCE_LOCK.json); no failure receipt exists.

The **relation assay** uses one native Full151 value store. It supplies two alternative cues and scores their relative native values on read-only copies. The learner does not emit an open answer. Twelve old ordered cues are reinforced; six held-out ordered cues, representing three new symbol pairs in both orientations, receive no teaching. A later disjoint cohort and two day-long gaps test the signal at the final probe. This is a narrowly synthetic limited E3 screen: an inferred one-bit class rule can solve it.

The **capacity assay** uses four copied native Full151 output stores. Sixteen byte expressions are each taught 12 times; nine labels are fixed and seven are shuffled into balanced answer-byte classes. The learner chooses `0`–`3` at `=` before the next answer byte teaches its channel. Thus an exact-key table can solve the E1 endpoint, and these results do not demonstrate addition. An untaught spacing form is a descriptive E2 check; whitespace normalization plus lookup could solve it.

## Fresh confirmation results

| Relation assay, final held-out relative choice, 32 paired worlds | FE0 | ROLE |
|---|---:|---:|
| Old-writing effect W−N | +17.7 pp [95% CI +6.3, +29.1] | **+34.4 pp [ +21.3, +47.5]** |
| No-old-write baseline, N | 49.0% | 44.8% |

The paired ROLE-minus-FE0 old-writing effect was **+16.7 pp [ +2.3, +31.0]**. ROLE's final old-taught choice was **93.2%**, and its held-out effect was already present at old-teaching end (**+39.6 pp**). It therefore met the frozen *candidate preservation* signal. This does not show that a four-output-store model can emit the held-out answer, nor that the learner has inferred an open-ended relation.

| Capacity assay, final probe, 32 paired worlds | FE0 | ROLE |
|---|---:|---:|
| Directly taught canonical cues, writing on | 257/512 (**50.2%**) | **340/512 (66.4%)** |
| ROLE writing off | — | 128/512 (25.0%) |
| Never-taught spacing form, ROLE writing on | — | 303/512 (59.2%) |

ROLE exceeded FE0 by **+16.2 pp [ +10.5, +21.9]** on paired-world canonical recall, but failed its frozen **70%** candidate threshold and the earlier Step-13 uniform-recall benchmark. The per-cue pattern is uneven: `1+1=` was correct in **8/32** worlds, `2+3=` in **4/32**, `3+1=` in **5/32**, and `3+2=` in **9/32**. Several other cues were 32/32. This is a genuine partial gain, not reliable 16-item memory. The earlier fixed fading-pair route scored 461/512 (90.0%) on its own fresh Step-13 worlds, yet it also failed its per-cue reliability gate and lacked Step-12 held-out relation choice; the comparison across those separate experiments is contextual, not a paired Step-15 contrast.

## Integrity and meaning

The independent [auditor](audit_step15.py) did not import the Step-15 runner or execute learners. It checked the source lock, world rosters, regenerated capacity labels and byte streams and relation fixtures, verified native write-flag digests, output-before-teacher readouts, clock and sensory parity, probe rows, margin arithmetic, and four deliberate receipt corruptions. It recomputed the world-paired intervals and gate verdict from all 64 confirmation receipts in [CONFIRM_AUDIT.json](results/CONFIRM_AUDIT.json). Confirmed learner runtime summed to about **235 s** for relation and **737 s** for capacity; compact results occupy about **2.6 MB**.

This result rules out the fixed role code **as a ready single-route compromise at the tested load**. It does not rule out all role features, separate pathways, or Full151 itself. The strongest immediate engineering evidence remains: fading pairs support substantial directly taught byte-output recall, while shared FE0/role features support a limited held-out relation signal in a different interface. Combining these by post-hoc score summation or calling the two assays one integrated system would overstate the evidence. The next bounded bridge should use one architecture and one declared primary capability, as specified in [NEXT_BRIDGE_NOTE.md](NEXT_BRIDGE_NOTE.md).
