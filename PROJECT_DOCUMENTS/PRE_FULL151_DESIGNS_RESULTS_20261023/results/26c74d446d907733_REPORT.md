# Hostile audit: the byte-arithmetic evolution program (V2 → W3 → V3 …)

**Date:** 2026-09-26. **Auditor:** Claude, read-only. No design, code or result was changed, and nothing was run.

**Audited:**
- `BYTE_ARITH_EVOLUTION_V1` and `V2` (designs, code, `runs/full_v2`);
- `BYTE_ARITH_WARMUP_PREFLIGHT_20260926`;
- `BYTE_ARITH_WARMUP_HOSTILE_AUDIT_20260926`;
- `BYTE_ARITH_WARMUP_REVISED_20260926` (W3 `DESIGN.md`, `AUDIT_RESOLUTION.md`);
- `MINIFLY_OBJECTIVE_CONTRACT.md` and `AGENTS.md`.

## Verdict

**NO-GO for implementing W3's population search, and NO-GO for planning further evolution versions.**

W3 competently repairs the four blocking defects of the first warmup design: the teacher channel, the shortcut-passable gate, reuse of the "sealed" set, and the grade bands. The problem is one level up. Even if every gate passes, the program cannot deliver what the project needs. The evidence already in hand says the gates are unreachable by the searched learner class. And the one route that could make a success belong to MiniFly is configured with two information losses this project has already measured.

## P0 — program level

**1. Even full success does not advance the stated goal.** By W3's own text:
- a pass is "bounded E3 warmup transfer" within a synthetic one-operator fixture;
- there is no delay or intervening-learning probe;
- **all Full151 native plasticity is frozen in every arm**;
- the scored answer comes from a new engineered decoder trained with AdamW;
- one searched route (raw-byte only) contains no fly component at all.

The best achievable deliverable is "a small trainable sequence model learns some one-operator arithmetic from 384 revealed answers". That is an ML result with no MiniFly attribution and no persistence. It also inverts the order prescribed by `MINIFLY_OBJECTIVE_CONTRACT.md`: unseen-input gates on the learning core first, mechanism search after. And `AGENTS.md` requires reading V9.9A/B before another byte-value architecture decision; the arithmetic line does not engage with those results.

**2. No learner in the searched class is shown able to reach the gates.**

| Evidence (one-operator, unseen expressions) | Exact |
|---|---:|
| V2 full run, learned, after 512 graded examples | 1.3% (below its own no-write arm, 7.7%) |
| Privileged ridge readout on fixed V2 features, 512 labels | ≤ 11% (Stage 1: 1/128) |
| Supervised raw-byte GRU, 512 **answer labels** | 5.5–10.9% (about constant zero; MAE about 4) |
| Answer classification | 9.4–14.8% (largely an answer-frequency shortcut) |
| **W3 Gate 1** (≤ 384 answers) / **final** | **37.5% / 50%**, with per-operator floors |

The gates sit 3–7 times above what *fully supervised* training reached at a similar sample size. W3's search varies only hidden sizes, learning rates and route gain. A hyperparameter search cannot be expected to close a gap that direct supervision did not. W3 runs its privileged numeric-target control *alongside Gate 1, after the search*, which is too late.

**Required before any search:** some learner, privileged if necessary, must reach Gate-1 levels at 384 examples on development data. If none does, the search's outcome is known in advance. Then change the task (range, digits, curriculum, sample count), not the population size.

**3. The only MiniFly route is structurally handicapped by bottlenecks already measured.** V2's `Full151ByteSensor` (`BYTE_ARITH_EVOLUTION_V2/model.py`, lines 141–200), which W3 inherits unless it says otherwise:
- **Byte clock of 1 s.** FE0 runs with τ = 10 s, so its state is a slowly fading mixture of about the last 10 bytes. This is also inconsistent with the project's 30/14 s byte-time convention.
- **Pooling.** The 5,177 KCs are hash-pooled into **128 bins** with fixed lognormal gains.

The project's own byte-order experiments measured exactly these losses:
- **FE0 loses order.** It keeps the byte two back at 0.22 decodability (`BYTE_READ_ORDER_FLYROUTE_20260925`).
- **Pooling collapses the native arm.** Under 128-bin pooling, V9's native arm scored at chance on the identity task.
- **The losses are fixable.** An order-preserving input organ (LAT4) feeding **all** KCs passed the ORDER gate in 3 of 3 worlds (`BYTE_READ_ORDER_ITER2_20260925`).

W3 specifies neither the byte clock nor pooled-versus-full KCs. As written, a "KC-only < raw-byte" or "KC+raw ≈ raw" outcome would be an artifact of sensor configuration, and would wrongly read as "the fly contributes nothing". **Fix:** 30/14 s byte clock, all 5,177 KCs, and an order-preserving front-end arm. Otherwise, state that the result cannot bear on MiniFly.

**4. "Evolution" here is a noisy hyperparameter search, and V2 failed by selecting on noise.** In V2:
- 325 family extinctions;
- 0 survivors in the final generation;
- the selected learners were *worse* after learning than their own no-write arms.

W3 removes immigrants and reseeding. It keeps fitness from 2 lives × 64 questions per candidate. Near 10% accuracy, the binomial SD is about 4 points per life and about 3 for the two-life mean. Near the floor, truncation selection mainly selects lucky draws. The genome is a few continuous hyperparameters per family. A replicated grid or Bayesian search would be cheaper and interpretable; evolution adds no mechanism discovery.

**Required before any evolution:** show that fitness is repeatable. Its correlation between independent development lives of the same genome must be clearly positive.

**5. Forking paths across versions, in a small fact universe.**
- **Division is the bottleneck.** It has 210 pair groups, of which 148 are hard. W3 reserves 48 hard groups for qualification and final. Each life then needs 88 of the remaining 100 for training, so every life trains on about 88% of all remaining hard division facts. Generations, and any later version on the same operators, resample essentially the same facts.
- **A fresh hard-division final set for V3 is impossible.** "One-use final" holds only inside W3.
- **Gates and fixtures have been redesigned after each viewed result** (V1 → V2 bands; V2 → W3 fixture). Without a version-level ledger of what was viewed and what changed, per-version "confirmations" are not independent evidence for the program.

## P1 — design level (blocking for evolution, not for a Gate-0 interface test)

**6. The grade-only tier is predictably null.**
- The rule is a REINFORCE update on the whole emitted answer string, with learning rate 1e-4.
- It gets 128 samples of 5-band grades, mostly −2 to −5.
- It samples at temperature 1 during graded training, which itself lowers accuracy.

The expected finding is "grade-only failure" whatever the learner's quality. Check this rule on Gate 0's key→answer task with grades only before carrying it into arithmetic.

**7. Standing-constraint conflict.** The warmup is supervised AdamW training, backpropagating through time on revealed answers. If the owner's earlier constraints (no backprop, no labels, biologically inspired) still apply, W3 violates them. If they were relaxed for this line, the design should say so and label any success as an engineered-model result.

**8. Test-time cues remain throughout, and nothing removes them.**
- a newline triggers a reset;
- a `=` prompt;
- a grammar-constrained decoder with a `;` terminator;
- evaluator-built questions.

W3 is an improvement over V2 because the learner emits its own answer bytes. But the owner's end state ("output without human help, no cues") is not on this program's path.

## What W3 gets right

- the Gate-0 online key→answer control, including teacher-byte invariance and differential no-write state tests;
- the operator–pair holdout, hard rosters, answer-frequency caps and derangement controls;
- three separated endpoints (acquisition, retention, grade-only learning);
- clone-per-item probes;
- the one-use final.

These are sound and reusable in any future assay.

## Minimum conditions to proceed with arithmetic at all

1. Run **Gate 0 only**. It is cheap, and it validates the teacher channel.
2. On development data, show that **any** learner reaches Gate-1 levels at 384 examples, and use that as the positive control.
3. Reconfigure the sensory route (30/14 s clock, full KCs, LAT4 arm), so the fly is tested fairly.
4. Replace evolution with a replicated hyperparameter sweep **unless** fitness proves repeatable.

## Alternative more aligned with the objective

Return to the contract's order:
- **the open native E3 threads:** why the shared head transfers rank order but not cycles; delay and intervening-learning tests for that head;
- **or a recurrence-savings assay:** bits saved on later recurrences of earlier content, against a twin stream without the earlier mention, scored on the learner's own predictions with no probes or reward at test time. That measures persistent, cue-free use of earlier byte information directly.

*Evidence level of this audit: E0 design and code review.*
