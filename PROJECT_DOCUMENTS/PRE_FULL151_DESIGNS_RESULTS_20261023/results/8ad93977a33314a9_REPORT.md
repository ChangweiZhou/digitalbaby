# MiniFly V9.8: small unseen-input trial

**Outcome:** REF shows a promising, causally attributable signal on **never-reinforced combinations** of previously taught byte features. HASH8 keeps high accuracy on taught pairs but does not show that transfer in this trial. Neither model is promoted to a persistent learning core: this is one engineered relation family, 12 worlds, and the delayed/interference evidence is imprecise.

## What was tested

The frozen V9.2 checkpoint was run with the unchanged V9.7 `REF` and `HASH8` value-memory implementations on worlds 1201–1212. In each task, a write-enabled `W` branch and a write-disabled-during-old-teaching `N` branch saw identical 14-byte records, labels, timing, and later new learning. The engineered byte predictor remained exactly matched. All scored held-out choices preceded feedback on those inputs. The E2 task withheld one irrelevant-prefix rendering of already taught ordered pairs; the E3 task withheld three combinations of six symbols whose two classes were taught through six other pairings. The latter can be solved by learning a simple per-symbol class rule, but not by a table of exact taught pairs. [DESIGN.md](DESIGN.md) specifies the full exposure and control ledger.

## Main results

Choice is the fraction of aversive-versus-neutral pair comparisons with the correct sign; 0.5 is tie/chance. `N` is the matched branch without earlier native teaching. Values are means across 12 worlds. The interval is a descriptive world bootstrap for `W−N`, not a confirmatory test.

| Task / arm / probe | W held-out | N held-out | W−N [descriptive 95% interval] | W trained |
|---|---:|---:|---:|---:|
| E2 REF, immediate | 77.8% | 38.9% | +38.9 pp [+22.2, +55.6] | 66.7% |
| E2 REF, after new learning + day | 63.9% | 50.0% | +13.9 pp [+2.8, +27.8] | 61.1% |
| E2 HASH8, immediate | 63.9% | 38.9% | +25.0 pp [+5.6, +47.2] | 72.2% |
| E2 HASH8, after new learning + day | 50.0% | 52.8% | −2.8 pp [−13.9, +8.3] | 72.2% |
| E3 REF, immediate | 80.6% | 52.8% | +27.8 pp [+8.3, +47.2] | 93.1% |
| E3 REF, after new learning + day | 69.4% | 55.6% | +13.9 pp [approximately 0, +27.8] | 86.1% |
| E3 HASH8, immediate | 44.4% | 52.8% | −8.3 pp [−33.3, +19.4] | 87.5% |
| E3 HASH8, after new learning + day | 44.4% | 63.9% | −19.4 pp [−36.1, −2.8] | 81.9% |

All four probe times and pair margins are in [RESULTS.csv](results/RESULTS.csv); [SUMMARY.json](results/SUMMARY.json) and the independent [AUDIT.json](results/AUDIT.json) reproduce the paired means. The negative HASH8 E3 differences should not be interpreted as a precisely estimated harm effect: this trial has only 12 worlds, multiple descriptive cells, and no confirmatory error control.

The E2 rendering almost always changed the full KC code: exact equality was **1/72 cue-world comparisons** (1.39%), although mean active-support Jaccard was **0.956**. HASH8 sent the withheld rendering to the same bank as **trained prefix 0** in **12/72** comparisons (16.7%). This is an address-opportunity diagnostic, not a causal lesion: REF and HASH8 also differ in banked storage. A postrun replay of all four trained prefixes, described below, substantially narrows what 12/72 means.

## Interpretation and limits

The E3 REF result is the first result in this byte-value line that cannot be explained by an exact *pair* lookup: three tested pairs were never rewarded, every symbol appeared in two taught pairings and equally often in both byte positions, and omitting earlier value writes reduced immediate held-out choice from 80.6% to 52.8%. This supports **limited feature reuse** on the synthetic class task. It does not show transfer to a different task family or establish a biological mechanism. A learner could store one class bit per symbol and pass; that is useful abstraction relative to exact-pair recitation, but still a very small rule.

After 24 hours and an unrelated taught cohort, REF retains a positive mean E3 W−N difference of 13.9 points, but only 5/12 worlds have W>N at that final probe and the descriptive interval reaches zero. Persistence is therefore unresolved. HASH8's strong exact-pair scores alongside weak held-out scores show why V9.7's higher taught-pair accuracy cannot serve as the project's core criterion. E2 shows a separate vulnerability: a near-preserved sparse support does not guarantee a stable exact float64 hash address.

**Postrun clarification, 26 September:** The 12/72 E2 address comparison used only prefix 0, while each ordered pair was taught under **four** prefixes. In a read-only replay of the original teaching schedule, **42/72** withheld cues routed to a bank that received at least one actual write for that same pair; **19/72** routed to that pair's modal write bank. Each pair's 12 teaching events occupied one, two, three or four banks in **5, 21, 32 and 14** cue-world cases respectively. [ADDRESS_POSTHOC.json](results/ADDRESS_POSTHOC.json) and [address_posthoc.py](address_posthoc.py) preserve the exact calculation. Thus the 12/72 figure must not be described as the probability of accessing *any* relevant taught state, and a forced-prefix-0 read is a weak negative test of the address hypothesis. These are posthoc descriptive counts, not evidence that shared-bank writes caused a particular choice. For REF E3, the final **signed margin W−N is positive in all 12 worlds**, even though choice W−N is positive in only 5/12; the learned analog signal and the behavioral threshold must remain separate outcomes.

The no-write `N` branch controls prior native value teaching while preserving sensory exposure, outcome bytes, time, and predictor learning. It does not remove every possible developmental bias in the frozen parent, but world-randomized symbol classes and paired W−N differences reduce that concern. The E3 generator itself supplies an easy compositional rule; a stronger follow-up must test additional relation families and alternative shortcuts. The E2 prefix result excludes raw 12-byte memorization for that probe, but a canonicalized ordered-pair table could still pass it. Neither task uses natural-language semantics.

## Audit and disposition

An initial launch was blocked by a source-lock JSON tuple/list mismatch **before any trial world ran**. The runner was corrected and engineering world 9901 was rerun; its 20 preflight checks passed. Only then were the fixed 12 worlds evaluated. The trial took 151.5 seconds; 768 final metric rows were produced. A separate stdlib reducer checked every row's margin-to-choice conversion, roster, finiteness and code discrimination, then recomputed all 16 paired cells. A postrun [probe-parity check](results/PROBE_PARITY.json) reproduced held-out choice and every pair margin with the inherited V9.4 probe in all four engineering cells. [ACCEPTANCE_CHECKS.json](results/ACCEPTANCE_CHECKS.json) records the runtime checks. No source dataset or checkpoint was duplicated; the directory is under 1 MB.

**Next decision:** retain REF and HASH8 as diagnostic comparators. Do not enlarge HASH8 or launch a broad evolution search on taught-pair accuracy. The next bounded test should verify the REF E3 signal on untouched worlds with a prespecified primary delayed/interference endpoint, and include a second relation family or a task that cannot be solved solely by one stored class bit per symbol. In parallel, an evaluator-only address intervention can test whether HASH8's poor held-out retrieval is caused by its exact-code route; that intervention must not be described as a new trained learner unless it is implemented causally. No architecture is promoted from this trial.
