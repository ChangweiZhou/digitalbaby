# W4 first implementation and development pilot

**Result (26 September 2026): the byte/feedback/native-write interface runs, but this learner has not acquired useful four-operation transfer.** The small development pilots showed strong re-answering of explicitly taught expressions and a coarse reduction in numerical error. On never-taught operand pairs, exact accuracy was 0/32, 1/32 and 2/64 in three independent lives; the native-write lesion had exactly the same count in every life. A simple frequency shortcut scored 2/32, 2/32 and 5/64. These are development diagnostics, not a sealed test or an evolution result.

## What was actually run

The [W4 design](DESIGN.md) corrected W3's mistaken freeze of Full151 plasticity. Its pre-run status text is retained as a frozen design record; this report documents the subsequent pilot. This first implementation added a deterministic global-pair-disjoint arithmetic fixture, a byte transcript, a new action-conditioned read/write adapter to inherited Full151, and a raw-byte online answer learner as an **engineering benchmark**. The benchmark sees `\n<expression>=` one byte per interval and emits its own signed decimal answer before feedback. It directly decodes the visible `#<correct answer>;` bytes into a target during warmup. Its 7,619,076 new mutable bytes are separate from inherited Full151 state. No KC teacher decoder or KC-local answer plasticity has yet been implemented; therefore even a successful benchmark would not certify a fly-derived arithmetic core.

The native adapter scores all 513 syntactically valid answer strings from −256 to 256 at one same-time native state. Its fixed, arithmetic-free encoder combines the question KC activity with the candidate's own answer bytes. Only the chosen code receives one binary native event after the full `!d;` grade transcript, using the inherited `fly.event` substrate. A writer-off replay sees the reference action, grade, teacher bytes and clock but disables only native writing; an all-prior-write-off replay disables both native and engineered updates. These replays are **off-policy** when their own preferred answer differs. An independent raw-only arm chooses autonomously. Every held-out item is probed from its own state clone with no feedback, and the live training-state hashes are checked unchanged.

All questions use operands 2–99 and the four operators. Every scored unordered operand pair is absent from warmup and grade-only training under **every** operator; the pair sets are unique across all phases within each life. The two small lives each used 32 answer-revealing warmup questions, 16 grade-only questions and 32 held-out questions. A larger development life used 128, 32 and 64 respectively. The held-out answer is never shown or graded. Five-band punishment is visible after the first response; the inherited writer uses one binary error event in this pilot. Every post-question history spends five output, three grade and six answer-or-silent slots at 30/14 simulated seconds each.

## Observed outcomes

All values below are exact first answers on *never-taught pairs after grade-only continuation*. `Native off` and `all writes off` are fixed-history replays; raw-only is a separate autonomous life. The strongest shown shortcut is the larger of global-answer mode and operator-answer mode for that life, not a symbolic solver.

| Development seed | Exposures: answer / grade | Held-out | Raw + native | Native off | All prior writes off | Raw-only | Strongest frequency shortcut |
|---|---:|---:|---:|---:|---:|---:|---:|
| 20260926 | 32 / 16 | 32 | 0 | 0 | 0 | 0 | 2 |
| 20260927 | 32 / 16 | 32 | 1 | 1 | 1 | 1 | 2 |
| 20260928 | 128 / 32 | 64 | 2 | 2 | 0 | 2 | 5 |

At the last checkpoint of the larger life, raw + native answered **0/16 addition, 0/16 subtraction, 0/16 multiplication and 2/16 division** questions exactly. Its mean absolute error was 55.3 versus 56.3 with native writing off and 71.3 with all prior writing off. The raw-only arm's mean absolute error was 56.3. This suggests some coarse information from **direct-answer engineered training**, but exact transfer was below the shortcut. The eight sampled *taught* expressions were re-answered correctly 8/8 in each small life and 7/8 in the larger life with the raw-only arm, versus 0/8 after training in the all-write-off replay. That is E1 recitation evidence, not E3 arithmetic-rule evidence. Grade-only changes from the after-warmup checkpoint were 0→0, 1→1 and 1→2 exact for raw + native; these counts cannot establish a grade-learning effect.

The native read/write interface passed six focused tests, including legacy event parity on an unmodified KC code, no write before the terminal grade byte, equal clocks/adaptation for writer-on/off, clone purity and a constructed readout-dependent choice. **Its credit sign is not robust:** in a separate after-implementation diagnostic on 32 non-arithmetic prefixes, correct `p=0` events favored the selected answer in 32/32 cases, while error `p=1` events suppressed it in 27/32 and favored it in 5/32. The arbitrary hashed action contacts therefore do not provide guaranteed directional punishment. This is a mechanistic obstacle before evolution, even though the code path is live.

## Evidence and stopping decision

The byte interaction, timing and read/write path have **E0 interface evidence**. Direct-answer engineered teaching gives an **E1 taught-expression result**. The prespecified E3-family probe on unseen operand pairs did **not** support transferable four-operation learning: three development lives are too few for a precise effect estimate, the candidate did not beat the simple shortcut, and native writing added zero exact answers over its lesion. No persistence, mixed-expression, qualification, final-roster or population-search claim is made. The outcome does not rule out arithmetic learning after more examples or a different credit/topology mechanism; it shows that this first integrated route is not ready for the planned costly search.

The next bounded decision is to repair and test the action-credit direction on **disjoint** byte prefixes and implement a genuine KC-observed answer route, then repeat a small held-out causal pilot. A raw-label learner should remain an engineering benchmark. If those interfaces still do not yield a held-out effect beyond shortcuts, expanding the genome or population will mainly search a broken update interface. The three lives took 68.8 s combined for the two small fixtures and 78.9 s for the larger fixture on one V88 Python process; this is not a four-worker RAM or thermal certificate.
