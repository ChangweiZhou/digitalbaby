## Top lessons for skills
- Lessons must become executable artifacts, not prose. Every failure class here recurred because its fix lived in one file or one document. Turn each audit finding into (a) a regression test or fixture that every new runner must pass and (b) an entry in an inherited-findings ledger that every new design must import and mark RESOLVED, OPEN or ACCEPTED (FC08, FC12; earliest 7 Sep V26 audit loss; the zero-variance rule was lost within 7 days).
- Control-liveness before interpretation. No causal contrast is interpretable until its control has passed four checks: (1) a literal per-branch write matrix built from an independent table; (2) a planted-defect mutation test that must be rejected; (3) a positive-control fixture with nonzero W−N; (4) a not-identical-to-parent detector. Any zero-width interval or bit-identical arm on a primary contrast is INTEGRITY_ALARM, never a null (FC01, FC02; V20/V23 on 6 Sep to the three-mechanism round on 28 Sep).
- Degenerate-learner panel for every promotion gate. Before freezing, score stop-learning, frozen-layer, exact-key, canonical-key, hash, mode, one-bit class, scalar potential, constant and cross-record-leak learners against the gate. If any passes, cap the claim at that E-level. Pair every retention endpoint with a current-acquisition gate, and put any diagnostic arm that beats the candidate in the headline. This is the main defence against specification gaming (FC06; V40 HYBRID-FROZEN wall 1.000, BYTE_ARITH countermodel +11.2 pp).
- Separate the judge from the optimized object. Hash every scoring-path array and require equality across arms. Confirm in a deployment-parity panel (an uninterrupted life with experienced delays), not on clone-branched diagnostics (FC06; V81E/V82E observer coupling, V83/V86 champions worse than REF).
- Verdicts are append-only. A post-outcome change to gate code, arm, endpoint, loads, threshold or seeds requires an erratum file attached to the original, with the old and new verdict, a diff, BUG_FIX or POST_HOC classification and an independent sign-off. POST_HOC never upgrades a verdict, index titles must differ, and downstream documents cite the erratum ID. Apply the same standard to your own and peer failures. Failed gates are final; follow-ups use fresh seeds and a new preregistration (FC03; V39 REPORT_CORRECTED, V27/V39/V40 reinterpretations, CORE_RECOVERY gate re-tally).
- Objective and standing-constraint ledger with diff. Each design restates the canonical contract objective and E-level verbatim and lists constraints as RETAINED, RELAXED (with a dated owner quote) or NEW, and a tool diffs this against the contract and the predecessor. A gate that has rejected a candidate cannot be demoted to 'not an objective' without an owner-signed OBJECTIVE_CHANGE, and it stays a co-primary. Track rounds since the last target-level (E3) test, and force one after K rounds (FC04; V47 -> V48 pivot, V88 collateral removal, about 30 E1-only MiniFly versions).
- Evidence-level tagging everywhere, with generated labels. Every endpoint, sentence and summary row carries an E0-E4 tag, its metric definition and denominator, its preregistered verdict, and any post-hoc flag, pulled from machine-readable decision files. Words like 'core', 'established', 'generalization', 'validated', 'adopted' and 'solved' are generated only when the contract level is met. For E2 probes, check that variant and canonical inputs have different internal addresses (FC05, FC15, FC16; V50, V75, OMNIBUS10, CONTENT E2).
- Guard power precheck. Compute minimum detectable effect, half-width, floor and ceiling at the planned n before science. A guard that cannot fail is NOT_ASSESSABLE and cannot license advancement. Materiality must be smaller than the plausible effect. 'No confirmed harm', 'not confirmed' and 'CI includes chance' never become 'safe' or 'absent'. Report the count of units that lost (FC10; V27 −5 pp margin, BYTE_CORE_1 δ > η, FB1 ±38 pp, V88 42/48).
- Adoption requires a pass. Before citing any prior candidate as working, anchor, default or validated, load its decision file and quote its status. Use SCREENED -> CONFIRMED -> TRANSFERRED status. A capability claim names one frozen configuration that passed all named tasks in the same trial, with an attribution ledger (native-route lesion, resource ratio) (FC14; V84E 28/77 -> 'works'; V27 contrast default; V9.2 engineered predictor at 17.4x).
- Cross-lineage unit-fact and capability-baseline registry. Store negative facts (exact or hash addressing gives E1 but no E3; alpha feedback about 1e-9; FE0 loses byte order; encode-once harness) and positive baselines (native E3 V9.9A/B, V9.10C, Z0 +38 pp, all one-bit-scoped). Every design runs a conflict query and compares against the baselines on the same assay (FC13; the hash fact was re-derived across three lineages, alpha feedback five times).
- Causal-time firewall. Run a future-mutation test, a read-purity digest test, a zero-old-training-after-transition assertion and a first-presentation AUC at chance for every learner, calibration and probe. 'Label-free' is not 'causal' (FC07; V26 shift stream, V39 PhaseFront, the Huang source model, FE-NI read(), the BYTE_CORE_1 cross-record leak).
- Single imported semantics library for truth, exposure, cohort and population. Cohorts are derived by set algebra from the generator with disjointness and size tests. Validation anchors must exercise the edge case (FC08; change_truth reintroduced three times; V51 'untouched' = revised + noisy).
- Realized-quantity matching and absolute-vs-incremental decomposition. Matched controls declare the realized quantity and tolerance from logs. Protection claims report absolute, prechallenge and own-state W−N DiD, and decompose any narrowing contrast by arm (FC09; V54-V69 dose chain, V9.6 birth advantage, V9.5 'rest recovery').
- Audit independence levels. L0 re-read, L1 recompute with separate code, L2 independent-implementation replay, L3 tamper battery including self-consistent joint tampering. Promotion and E3 claims require L2 or higher, and implementer-only audits are labelled and cannot promote. The auditor never imports runner helpers (the review practices that changed verdicts vs failed).
- Claim-reproduction ledger for cross-agent inputs. Re-derive every cited number from a named table or tag it UNVERIFIED. Strip numeric progress scores. Flag stale proposals. Tag QA with an execution level. Echo back any narrowing of the user's explicit request (FC19).
- Feasibility and value of information before expensive runs. Require a privileged positive control that reaches the gate, a feasibility witness for absolute thresholds, fitness repeatability before evolutionary search, disjoint pilot and confirmation rosters, and a churn bound on protocol revisions (FC18; V36 gate, 3,072 floor lives, BYTE_ARITH V2, FEAS v1 -> v6.1, A11 v3.8).
- Lineage-complete reading for any archive analysis or summarization skill. Group design -> run -> report -> audit -> erratum -> next recommendation by folder and date, never by regex over version tokens or catalog era, and quarantine fixtures by namespace and kind. Verify reader-level claims against primary files before encoding them in skills: about a fifth of the checked reader claims in this merge needed correction (FC15; CATALOG splits; FB1-followup fixture with opposite sign and identical title).
- Provenance before execution. Commit designs (including chat-derived ones), runner source, environment lock and raw per-record primitives sufficient for offline rescoring before science. Assert executed hash = locked hash. No destructive cleanup without a manifest. Check in CI that every referenced governance document exists. The V88_TO_V9_7 drift audit, which the contract relies on, is missing (FC17, decision patterns).
