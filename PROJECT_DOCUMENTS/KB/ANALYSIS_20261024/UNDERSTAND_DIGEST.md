## Failure-mode taxonomy (30 classes)

### FM-01 Common-mode auditor (verification shares code or semantics with the system under test)
- Definition: An auditor, reducer or 'independent' check imports, copies or rebuilds its expectations from the same functions or manifests the executor uses. Any defect in that shared semantics then passes both the run and its audit.
- Recurrence: At least 4 deliveries (Package B, v5.1, V6-R1, STOP-ONLY). native_next's design adopted the rule ('Do not accept only agreement between two reducers importing the same decoder', minifly_native_next_design_v1_20261023/DESIGN.md:76) only after the fact.
- Originates: refine_audit; should be caught: refine_audit (before the first technical roster)
- Mechanical check: (1) An AST scan rejects auditor modules that import executor modules or contain token-hash clones of executor functions above a size threshold. (2) Expected ledgers and endpoints are derived only from SPEC.json fields. (3) Before any roster, the auditor must catch 100% of a planted-bug corpus run against mutated executors: branch-name mismatch, flipped teaching sign, held item injected into a teaching stream, control arm identical to W. A single miss fails closed.
- Judgment check: The reviewer names the shared helper on which the verdict depends and asks which check would notice if that helper were wrong. At least one expectation must have been derived from the protocol text by an agent who did not write the executor.
- Instances:
  - minifly_b/REPORT.md:12-26 (SPOT-CHECKED): branch_allows compared 'N_old_relation' against branch names 'N_old_rel'. W, N_old_rel and N_new_rel end states were identical in 832/832 receipts, so E3 was 0 by construction. 'The receipt auditor did not catch this because it derives the expected write ledger from the same branch_allows'.
  - minifly_stop_only_confirm_v1_20261023/audit.py:9-20 vs decode_saved.py:8-20: the metric is transcribed between the two files. FINAL_AUDIT.json says 'independent_process_not_independent_reviewer'.
  - minifly_v6_r1_dev_20261023/audit_results.py:9-19 vs v6_data.py:24-34: countermodels are nearly copied. audit_results.py:21-29,56,66 rebuild exposures with the same manifest logic that run.py:40 uses to feed the learner.
  - minifly_v5_1_dev_20261020/FINAL_AUDIT.json: 'Independent artifact reduction, no learner execution' accepted a port gate that could not fail (see FM-04).

### FM-03 Confounded intervention (control cuts the wrong path, or several factors change at once)

### FM-04 Non-discriminating gate (a check that cannot fail)
- Definition: The gate, control or test passes by construction, at ceiling, or by tautology, so a pass carries no information.
- Recurrence: More than 8 instances across at least 7 deliveries. A rule that every check needs a negative control that must fail already existed (PROJECT_DOCUMENTS/PRE_FULL151_DESIGNS_RESULTS_20261023/designs/2a54ffdef3862514_DESIGN.md:534) but was not carried forward.
- Originates: design; should be caught: refine_audit (before cycle 3 and again before the official run)
- Mechanical check: Gate mutation suite (MUTATION_SCORE.json). Every gate must return False on its declared negative fixtures: no-write, shuffled labels agreeing with truth at about 50%, constant or mode output, overlapping patterns at the real activity density, decay-on. It must return True on an oracle or positive control. Fixture parameters are machine-diffed against the locked spec. Any arm scoring at least 95% (or every arm at most 5%) marks the endpoint non-discriminating. Effects below a numerical-noise floor, or on declared invariants, may not be significance-tested. A gate with no demonstrated FAIL is labelled 'sanity' and excluded from verdicts.
- Judgment check: The reviewer must name a plausible wrong learner that this gate rejects, and must have seen it rejected.

### FM-05 Untestable testbed or unreachable gate (a check that cannot pass)
- Definition: No known-capable learner could pass the primary gate at this split, input code and data budget, or the decision rule has near-zero power at the target effect. A negative result is therefore uninformative about the mechanism.
- Recurrence: At least 5 deliveries.
- Originates: design; should be caught: cycle 0 (before the design is frozen)
- Mechanical check: Cycle-0 admissibility table, run on the exact split and budget. A ceiling learner (BP or oracle features) must pass the primary gate. A frozen or random floor must fail it. The candidate rule in a calibrated surrogate must be able to pass. Then an operating-characteristic simulation of the full decision rule over a grid of standard deviations: require P(pass | target) >= 0.8, otherwise label the run 'precision-limited screen' with no adoption authority. Ratio-of-differences endpoints are banned as hard gates. Within a single conjunction, intersection-union applies without Bonferroni.
- Judgment check: If this run comes out null, what will we have learned about the mechanism, as opposed to the harness?
- Instances:
  - git show origin/charming-head:minifly_learned_bank_v1_20261024/cycles/CYCLE2.md:10-36 (SPOT-CHECKED): T-MOD is not learnable from 74 prompts even by exact BP (held 0.00/0.11). CARRY and CMP are solved by FROZEN random features.
  - addition_core_lineage_comparison_dev_v1_20261015/REPORT.md:20-21: backprop KEEP/G62 reach 100% taught but 0-5% held, yet native candidates were judged in similar harnesses (native_context_binding_dev_v2_1_20261017/results/REPORT.md:9-20; minifly_v6_r1_dev_20261023/REPORT.md:9-18).
  - arithmetic_model_feedback_dev_v1_20261014/ops/cycle2_gate_review/ISSUE.json: requiring a strict improvement over exact taught-key lookup is impossible.
  - persistent_core_v2_trial/results/SUMMARY.json (SPOT-CHECKED): ERROR passed all 7 guards and 6 of 7 bounds (revision_gain 0.559, lower 0.515) but failed capability_per_compute_gain (mean 1.34, sd 18.9, lower -4.24) at alpha .05/21. Verdict RETAIN_V1.

### FM-06 Weak comparator, missing trivial baseline, or weak guard
- Definition: A gain is measured against a structurally weak reference (one that scores zero or below chance, or a never-taught arm), and the strongest cheap policy is omitted. Trivial strategies can then pass or nearly pass.
- Recurrence: At least 4 deliveries. Most expensive instance: an official 225,792-record confirmation.
- Originates: design; should be caught: design review, plus a dev-data baseline sweep before any confirmation
- Mechanical check: A shared countermodel library runs on saved outputs: constant, mode, fixed length 0..8, position-only, exact and canonical lookup, frequency, length-frequency, suffix0..k, copy-operand, digitwise no-carry, nearest neighbour, FROZEN, SHUF, foreign input. The gate contrast is computed against max(chance, all baselines, all controls), with an absolute floor. A guard linter rejects comparator arms that never received the relevant teaching; protection is measured as own OLD_END minus own FINAL. Held items are stratified at manifest time (zero/identity operand, no-carry, carry, length change) and reported per stratum.
- Judgment check: Is the comparator the strongest policy available without memory? Does the claim name only the strata that pass?
- Instances:

## Top design principles
- 1. Convert prose rules into fail-closed machine gates. Every incident class gets an executable check before its incident is closed. A skill's output is an artifact a validator can refuse (missing BEHAVIORAL_ADMISSION, mutation score below 100%, lock not an ancestor of results), never a reminder. The contract and the retrospective's seven rules already existed as prose and drift recurred anyway.
- 2. Separate duties and code paths. The agent that writes the evaluator, countermodels and reducer is not the agent that writes the learner. The auditor derives expectations from SPEC text and imports nothing from the executor. The learner runs in its own process and sees only bytes. Reviewer identity is recorded, and reviewer == author blocks science, confirmation and adoption.
- 3. Test the tests before trusting them. Every gate must be shown to FAIL on known-bad learners and planted bugs, and to PASS on a positive control or ceiling learner at the same split and budget. Run the trivial-baseline ladder on saved outputs and compare against max(chance, baselines, controls). Simulate the decision rule's operating characteristics. A gate with no demonstrated failure is a sanity check, not evidence.
- 4. Run the cheapest falsifier first (cycle 0). Before freezing a design, in seconds to minutes: testbed admissibility (BP/oracle passes, frozen fails), E0 input-vs-noise contrast, birth-state determination, E1 taught acquisition, and a whole-chain smoke test with an oracle upstream for the next stage. These checks may stop or escalate a run and may never tune it. Their outcome is CANNOT_TEST_CLAIM_AS_SPECIFIED, which is a first-class, unpenalized verdict.
- 5. Lock what decides the verdict, and prove when it was locked. Endpoint, metric (numerator and denominator), comparator set, verdict code and the runtime import closure are hashed and pushed to the remote before the first scored value. Confirmation seeds come from a commit-reveal step. Anything added later is auto-tagged POSTHOC: it may inform, never decide.
- 6. Type the cycle and budget the forking. Each cycle declares its kind, visible data, readable metrics, allowed revision class, attempt and compute caps, and a researcher-level prediction. Revisions are tagged by category and by whether an outcome informed them. Outcome-informed scientific revisions increment 'best of k', mark held sets as spent and force fresh worlds. Exercises end on a decision, not a count.
- 7. Keep the objective attached to every number. Every PASS, pointer and summary carries the unconditional objective metric (exact own-EOS unseen addition with OLD protected, per sample and per counted compute), its gate type and its objective distance. Count deliveries since the last opened held E3. Task, metric or priority changes need candidate-blind reasons and dated user sign-off, and authorized narrowing is distinguished from silent drift.
- 8. Make knowledge a scoped, linked, falsifiable ledger. Unit facts carry level, substrate, priors, dose, comparator and the strongest trivial baseline, effect with CI, scope limits, source path:line, and status with narrowed_by/superseded_by links. Summaries and CURRENT pointers are generated from the ledger. Designs cite fact IDs and failure-class IDs and register numeric predictions, and post-audits score them. Facts earn a 'transferable' tag only by predicting correctly on a new substrate. This is how research-level generalization from unit knowledge becomes measurable.
- 9. Treat the knowledge base itself as a learner that must generalize. Periodically freeze it at date T, have a fresh agent predict post-T outcomes from the KB alone, and score against actual results and against the register base-rate forecaster (currently about 0 of 8 native E3 successes). Demote facts whose predictions fail and promote ones that transfer.
- 10. Treat lineage and answer path as part of the claim. Every design names its executable parent and diffs state, write, read, feedback and priors. Inheritance defaults to unproven. Every scored byte has a provenance tag (native, fitted head, evaluator). Adoption, engineering reference and scientific confirmation are distinct record types, and a renamed recipe inherits its negatives.
- 11. Ground authorization in the user's words and caps, not the agent's framing. Record verbatim text, the options shown with any recommendation, stage booleans, numeric caps and machine-evaluable conditionals judged by another agent. The launcher enforces scope. A user-owned CONSTRAINTS file is embedded in every SPEC, and proposals that touch it cannot execute in the same iteration.
- 12. Require executing, reconciled cross-agent review at the cheap moments. Review before implementation and before any confirmation. The review re-runs gates on inputs they should reject, runs the next stage on an oracle upstream, and traces quoted numbers to code. Findings are reconciled with a status enum and committed reproducing scripts. Read-only claims are UNVERIFIED. This is the strongest observed safeguard in both directions.
- 13. Use a closed vocabulary for claims and machine-rendered prose. Evidence levels, gate outcomes and world roles use enums. A linter bans soft verdict words, 'confirm' outside sealed worlds, 'native/core/inherited' without lineage, and numbers mixed across provenance tags. Integrity fields must be computed, never literal, and compliance sentences are rendered from fields.
- 14. Account for everything the objective divides by. Count every invocation through a wrapper ledger, including tuning, surrogate, failed and audit runs. Use deterministic operation counters as primary compute and persist raw inputs before any assertion runs. Cost claims compare at locked common compute snapshots, not with noisy ratio endpoints.
- 15. Protect the skills from the loop they govern. Gate, linter, countermodel and skill files change only through user-authored, strictness-monotone commits. Each revision must still catch a regression corpus of planted-bug fixtures for every historical incident class. Meta-progress counts only held E3 on sealed worlds. Lessons written by the delivering agent are inputs for independent review, not ground truth.

### What the "three cycles" actually change: classification of every recorded cycle revision (
- **cycle-exit-contract**: A cycle is complete only when CYCLE_RECORD.json exists with these fields:
- a hash-locked plan;
- a pre-run prediction with numeric expected ranges and the observation that would falsify it;
- a revisions[] list, each item tagged {OPS|TEST|MEAS|IMPL|SCI|GATE|SCOPE|WORLD} with informed_by_outcome (bool), motivating_world_ids and an evidence path;
- seeded_bugs_caught[] (at least 1);
- the primary endpoint and taught-E1 value on the cycle's dev worlds;
- a decision in {continue, revise, stop, escalate} with its reason.
The number of cycles is set by decisions and declared caps (maximum SCI revisions, maximum compute), not fixed at 3. _(why: There is no falsifiable prediction in any of 168 cycle notes. Templated or identical cycle docs (C9), cycles spent rerunning import fixes, and 'no fourth cycle' truncation all show that the count is a budget, not a stopping rule.)_
- **cycle-zero-testbed-and-chain-smoke**: Before the design is frozen, run a cycle 0 in minutes:
(a) Testbed validity on the exact split and code. An oracle or exact-gradient learner must succeed, and frozen-random-features, shortcut and constant baselines must fail. Otherwise the task cannot test the claim.
(b) Whole-chain smoke on tiny data through every stage (encoder → classes → address → port → teaching → generation), with progress curves at each stage.
(c) A cheap taught-acquisition (E1) floor.
Failing (a) or (c) blocks the design. A failure there is information, not a result. _(why: learned_bank showed that T-MOD was unlearnable even by BP and that CARRY/CMP are solved by frozen features (C3). In v5.1 the failure was visible in about 1 second but cost a full cycle (C9). v6_r1 ran 34,816 records with taught accuracy at 0% (C1).)_
- **revision-ledger-and-forking-budget**: Any SCI, GATE or SCOPE revision informed by outcome data:
(1) increments a designs-tried counter k, and reports must say 'best of k';
(2) forces fresh, untouched evaluation worlds;
(3) renames the learner lineage if the operative learning equations change;
(4) is checked against a declared allowed-inductive-bias list; task-shaped priors such as ordinal or additive outputs or role slots lower the claim and must be named in the headline.
Amendments go into LOCK.json with the path to the motivating evidence. Endpoint changes need a candidate-blind reason (ceiling, testbed invalidity, measurement defect) and keep the original endpoint as co-primary. _(why: addition_rule's three sequential designs with an engineered prior became a drift node (C2). observation_content_core changed its primary endpoint to a dimension favouring B after B failed protection (C3). learned_bank itself calls amendments the main drift channel.)_
- **mutation-tested-qualification**: Every qualification check must ship with at least one seeded fault it rejects: wrong sign, identical arms, collapsed slots, wrong label, structured shuffle. Run the positive control first, so that a genuine artifact passes before any tamper rejection counts. Use representative state: nonzero state, overlapping patterns, the declared activity density. Machine-diff every spec parameter against the fixture value. Required in cycle 1 for every new port: teaching moves the target margin toward the target compared with a matched no-write event, for both signs; zero dose equals the passive event; zero replay gives zero applications. _(why: Vacuous tests: the v5.1 port 'can't fail', mechanism_transfer's tamper suite, v3's zero-input derivative check, native_next's identical-arm EOS fixture, the SHUF derangement (C4). The v4 negated teaching sign survived two cycles (C5).)_
- **strongest-trivial-baseline-gate**: A primary gate must beat the strongest member of a trivial-countermodel sweep computed on the same saved outputs: constant answer, fixed length 0..L, marginal or frequency mode, position-only, exact-key or canonical-key table, FROZEN, SHUF. Beating an internal reference that scores 0% does not count. A metric conditioned on evaluator-side correctness can never be primary. Run the sweep on dev data before any confirmation is admitted. _(why: The STOP-ONLY official confirmation (225,792 records, 32/32 pairs) was about +0.6pp over a fixed-length baseline on NEW and worse than it on OLD (C7). v6_r1's outputs were 99% one repeated byte plus truncation.)_
- **known-defect-preflight-and-incident-ledger**: Before cycle 1, run a shared lint:
- unique package namespace, sys.path isolation, and a check that every module imports from the expected file;
- JSON round-trip equality for world plans and receipts;
- identity fields such as fly_id excluded from value equality;
- NumPy scalar serialisation;
- tests at zero and boundary slice limits.
Every preserved failure appends one row to a repo-level INCIDENTS ledger (class, symptom, fix, detector), and design reviews must cite the classes they checked. _(why: Import collisions in at least 10 deliveries, plus recurring tuple/list, fly_id and numpy-bool defects. v6_r1's cycle 2 is a rerun caused by one of them (C6).)_
- **pilot-vs-confirmation-labeling**: Cycle-3 or roster results on fewer than about 8 worlds are labelled PILOT, with n, a minimum detectable effect and the worst world stated. A positive pilot cannot be the delivery verdict without a frozen-design confirmation on untouched worlds. Mean-based gates must also carry a per-world floor. _(why: About 11 deliveries end with cycle 3 as the verdict on 1–2 worlds. The only positive E3 pilot came straight out of in-cycle mechanism selection (C2, C8).)_
- **independent-adversarial-cycle-review**: Each cycle is signed off by a reviewer from a different agent, working through a red-team checklist: vacuous tests, trivial baselines, amendment motives, lineage or equation changes, world reuse, the relation of the endpoint to the E-level objective. Any sentence in a note that claims a check passed must cite an artifact created before the note; check the ordering mechanically. _(why: Self-audit is the norm (C11). The cross-agent audit of v5.1 found three missed defects. Claude's own note recorded a check claimed before it was run.)_
- **findings-ledger-for-research-transfer**: Each cycle emits 1–3 transferable findings as ledger rows: claim, conditions (input code, n examples, dose, worlds), evidence path, status (confirmed, retracted or superseded; never deleted), and the program-level E3 endpoint value at the time. A new design must cite the rows it relies on and state its predicted effect on the E3 endpoint. Two consecutive component-only advances with a flat E3 endpoint trigger a route review. _(why: Post-hoc diagnosis kept steering designs toward component proxies (stopping, address capacity) while whole-output OLD stayed near 0% (C10). Lessons across deliveries are currently carried only in prose.)_

### STATISTICAL AND EVALUATION RIGOR
- **gate-calibration-battery**: Before any lock, run the exact primary gate code on DEV/technical data for: (a) at least one known-capable learner at the same data budget (BP/GRU, or oracle features), which must PASS; (b) non-solvers, which must all FAIL: frozen random features, fixed-length 0..8, position-only, frequency/length prior, raw and canonical lookup, shuffled and foreign input, constant answer. Shuffled-label controls must agree with the truth at about chance rate. The primary contrast is against max(all baselines, chance). Block the lock if (a) fails or any (b) passes. _(why: STOP-only would have passed with FIXED_1 (SR-01). KEEP/G62 cannot pass the raw-byte held-out gate (SR-02). - **gate-operating-characteristics**: For every decision rule, including conjunctions, per-unit 'every positive' rules and small-N screens, simulate P(pass | null) and P(pass | target effect) over a sensitivity grid of world-level SDs, or a DEV estimate. Lock only if P(true pass | target) ≥ 0.8, or label the run 'precision-limited screen' with no adoption authority. Correct for multiplicity across claims or candidates. Use intersection-union without adjustment inside a conjunction. Ratio-of-differences endpoints cannot be hard gates. DEV winners must beat the parent by ≥2 SE and report expected shrinkage. _(why: persistent_core_v2 rejected ERROR on an unreachable ratio gate at alpha .05/21 (SR-03). In MiniFly it shows up as built-in priors (A04) and decisions taken after results.)_
- **cycle0-validity-screen**: Before pushing a design, run a seconds-scale battery on the exact split and input code: (a) is the outcome decided at birth (outcome under learning vs birth state)? (b) can exact gradient or oracle features solve it? (c) do frozen random features fail? (d) the gate mutation suite. Any failure produces the verdict CANNOT_TEST_CLAIM_AS_SPECIFIED and a redesign, not more cycles. _(why: V5.1's failure was visible from the random starting values in about a second but cost a full cycle. LEARNED-BANK's task was unlearnable even by gradient descent. AlphaEvolve-style evaluation cascades show cheap screens should come first.)_
- **claim-artifact-binding**: Every number and verdict word in a report is rendered from a results file or tagged {file, key}. An audit script pulls every number from REPORT.md and cycle notes and checks it against the artifacts. Any sentence claiming a check was done must cite an output whose timestamp comes before the sentence. _(why: Hallucinated results (AI Scientist reviews, DGM's fake tool use) and MiniFly's own 'claim written before its check' and summary overclaims show narratives drift ahead of the evidence.)_
- **lineage-and-answer-path-attestation**: Compute a mechanical diff (state variables, write equations, readout, representation priors, budget) between the declared parent learner and the candidate. If it goes beyond the declared changes, label the candidate 'new learner; inheritance unproven'. Log which module emitted each scored byte, and refuse to credit native-branch results produced by engineered predictors. _(why: Methodological hallucination (silent oracle or lookup substitution, shrunken budgets) has a direct parallel in route retrospective A03/A07/A08, where results were attributed to 'the same MiniFly core' after the substrate changed.)_
- **independent-adversarial-audit**: The auditor is another model family or a fresh context. It reads raw artifacts before the executor's narrative and must try to build the cheapest learner or shortcut that passes the gate, with credit for success. Measure auditor recall regularly by seeding known-flawed deliveries. _(why: Self-preference bias and untrusted-monitor collusion are documented. MiniFly's cross-family audits caught real defects that its own in-cycle reviews missed.)_
- **honest-exit-and-tripwires**: CANNOT_TEST_CLAIM_AS_SPECIFIED and NO_ADVANCE are first-class, unpenalized verdicts; process efficiency is scored separately from outcomes. Plant deterministic tripwires (a decoy held-answer file with a canary, a writable but ignored budget or gate config, a decoy scorer copy). Any access flags the cycle for human review. Never optimize agents or prompts directly against audit-flag counts. _(why: An abort option cut GPT-5 cheating from 54% to 9% (ImpossibleBench). Optimizing against monitors produces obfuscation (OpenAI CoT monitoring). Hack-verifiable environments make detection deterministic instead of depending on reviewers.)_
- **findings-ledger**: Every finding that transfers between experiments is a ledger row: claim, evidence level, conditions (priors, feedback regime, samples, compute, answer-producing branch), evidence path, status (confirmed, retracted or superseded, never deleted), reviewer. Retrieval always returns conditions and status. Rows are revalidated when a result they depend on changes. Skills store checks and procedures, not tactics that produced passes. _(why: The experience-following literature shows agent memory spreads errors unless it can be pruned or retracted. MiniFly's root cause is that local limits did not become conditions checked across versions (REPORT.md:130).)_
