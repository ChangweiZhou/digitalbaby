## Changes before dispatch

1. **Fork twins before either prompt.** Start both members of an inserted twin from the same stream state before their different prompts. Restoring a snapshot taken at the first member's `=` can carry its context into the second. For an actual first encounter, score after its `=`. Restore the chunk-start state and byte cursor if training then replays that chunk. Set the pre-reveal boundary by the last **loss target** consumed: a chunk ending with `=` as input can already have used the first answer digit as its next-byte target. Test that boundary on the GRU and require probe-on versus probe-off continuation parity for optimizer, carried state, cursor, counters, and weights. [Probe protocol](https://github.com/ChangweiZhou/digitalbaby/blob/421d18d8/OPUS_TASK_TARGET_SIZING_SWEEP_20261111.md#L46-L55)
2. **Separate the disclosure benchmark from the 20-point recitation margin.** A responder with both disclosed values and the known operation can exceed 80%, making a 20-point margin impossible even for a perfect learner. Report that direct-use benchmark separately, with the operation matched to the family and the values to the correct era. Apply the margin to recitation shortcuts. Pin the acquisition panel and aggregation used for the size decision so later revision performance cannot silently determine whether the initial size passes. [Score classes and decision rules](https://github.com/ChangweiZhou/digitalbaby/blob/421d18d8/OPUS_TASK_TARGET_SIZING_SWEEP_20261111.md#L57-L87)
3. **Specify whether the matched-filler stream is trained.** Building the stream alone does not measure the effect of its content on a learner. If disclosure content informs the base-arm decision, add three paired continuing-stream fits at modulus 97 and four presentations, for **84 fits**. Otherwise, keep **81 fits** and interpret ordinary versus disclosed as the effect of the full disclosure package. [Roster](https://github.com/ChangweiZhou/digitalbaby/blob/421d18d8/OPUS_TASK_TARGET_SIZING_SWEEP_20261111.md#L22-L30) · [Disclosure decision](https://github.com/ChangweiZhou/digitalbaby/blob/421d18d8/OPUS_TASK_TARGET_SIZING_SWEEP_20261111.md#L83-L87)
4. **Bound Stage 1.** Pin profiling seeds, step and CPU limits, and which runs count toward the roster. Profile both batching paths, since 64-episode batches and single-stream chunks have different costs. Resolve the file-scope conflict by putting parameterized modules under `sizing/` and checking default parity against the accepted Step 0 record. [Admission and budget](https://github.com/ChangweiZhou/digitalbaby/blob/421d18d8/OPUS_TASK_TARGET_SIZING_SWEEP_20261111.md#L96-L109)

After these edits, Stage 1 can go to a worker for the modulus fixtures, causal scorer checks, cross-cut diagnostic, and cost forecast. The coordinator can decide on the full roster from that qualification record.
