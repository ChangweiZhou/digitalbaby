# MiniFly V2 limited addition milestone

The V2 milestone is a persistent MiniFly core that learns a limited addition rule from suitable training data and blurry external feedback, then answers never-taught operand combinations itself. This is a bounded task, not general intelligence, mixed arithmetic, NLP or unrestricted byte generation. Full151's internal structure may change. The current exact-context bridge is a working engineering baseline; its qualification will not be reopened.

This is a next-experiment proposal for discussion. No addition protocol, new scientific run or feedback policy is frozen by this document. Previously completed experiments retain their original scope and source locks.

## What the latest results change

The autonomous-observation A baseline demonstrates learning, retention and revision through the operative native memory, within a four-byte exact-context address and four output bytes. It did not test arithmetic transfer. The U045 content-matrix exercise completed three development cycles and remains on hold: final delayed new-content accuracy was 87.5%, versus A's 100%. Its speed advantage does not offset that warning, and its current exact-key instance is not an addition learner.

The old 1,024-candidate, 128-generation mixed-arithmetic search failed its sealed gates across all four architecture families. Increasing the search or adding something named recurrence is therefore insufficient justification. The new proposal changes the bounded task, shared representation, output alphabet and information/credit contract explicitly. The previous role-code result supports retaining role features as a hypothesis; it did not demonstrate an addition rule.

## First experiment

Use operands 0 through 4 and exact sums 0 through 8. Read the ordinary byte expression `a+b=` and emit one of nine digit bytes before feedback. Limited precision means this declared numeric domain; it does not mean counting answers within one unit as correct. Keep exact accuracy primary and numeric error secondary. No carry, two-digit output or learned stopping is required in this domain.

Withhold the complete commutative orbits `{1+1, 1+2, 0+4, 2+3, 3+3}`. Both orientations of a held pair are absent from every learning history. This yields eight held-out ordered expressions and seventeen training expressions. Every operand and every output digit occurs among the training expressions. The held-out split is an example to audit and lock before running; other balanced partitions may be used prospectively, without outcome selection. Repeating an expression or its spacing variant does not create a new relation sample.

All compared cores receive the same fixed, byte-driven earlier/later operand representation, including declared numeric neighbourhood information. Each operand is encoded independently. The interface must not compute the sum, a carry, a correctness flag or already-added counting pulses. Numeric magnitude is an acknowledged engineering prior: a pass would not mean that the fly discovered numerical identity from arbitrary glyphs. Keep the same prompt and output protocol for both cores. The learner's persisted content state must supply the answer; a separate trainable arithmetic solver cannot stand in for the core.

## Blurry feedback is a scientific choice

Two valid interpretations require different learning rules:

1. **Imperfect worked examples:** ordinary equation streams provide answer digits with independently declared corruption or missingness. The core receives only the actual stream, never truth or a corruption flag. Omitted answers supply no answer-target write. A proposed first setting is 10% uniformly wrong answer digits and 10% missing answers, with masks fixed in advance and matched across cores. These are illustrative rates pending the user's feedback choice and protocol audit. This is learning from imperfect examples, not learning from correctness-only reward.
2. **Post-action evaluation:** the model first emits a digit, then receives a noisy correct/incorrect or near/far signal without the answer. This needs an explicit bounded action eligibility and reward update. The existing observed-target `y−p` rule cannot implement it secretly. Feedback delay and sign must be audited within the same preparation cycle. If a warmup supplies examples, both comparison cores and causal controls receive matched warmup, and later learning is measured separately.

Do not conflate missing, noisy and coarse signals. The original autonomous-observation result still has its no-external-correctness evidence label; externally assisted addition learning is permitted by the new user milestone and must be named accordingly.

## Outcome and controls

The primary behaviour is exact held-out addition accuracy after training, delay and a fixed short intervening-learning phase. Report acquisition-end and delayed scores on the same frozen read-only state branches, together with taught-expression accuracy. Tests contain no answers or correctness feedback and perform no content writes. Model time is distinct from elapsed runtime.

Use a paired no-relevant-learning branch with matched bytes, feedback presentations and clocks, plus a feedback-shuffled branch preserving the feedback distribution. If using observed targets, disable the actual target-induced plastic writes; if using post-action reward, separately document which update consumes that reward. Preserve causal equality before the controlled phase. Any feedback generated from the model's action must be matched by world-level random seeds, without claiming bit-identical feedback when the actions differ.

Include exact-key and commutative-key tables, answer-frequency and single-operand shortcuts as countermodels. A learned additive rule is a valid explanation of success, not a countermodel to disqualify it. A hand-coded adder is only an evaluator-side solvability witness and never an arm to promote. Expose every train/test pair and feedback event to an independent auditor; hidden truth, test membership and noise identity cannot enter the model.

A milestone requires both useful absolute held-out performance and a causal advantage over matched controls that persists after delay/intervening learning. The exact absolute threshold, interval procedure, training dose, noise policy and world roster must be fixed before outcomes; they are not frozen here. Training questions and repeated probes are not independent worlds. Report real training examples, delivered feedback, CPU, state bytes and retained held-out ability per compute budget. A fast learner that only recites training facts does not meet V2.

Keep the first comparison to the baseline and one concrete candidate, with a fixed resource ceiling and the user's ten-hour session limit. Do not compensate for a failed rule-learning result with automatic dose escalation, a different held-out set, more families or another open-ended evolution search. Technical sign, branch, exposure and checkpoint checks belong inside the agreed design–audit–test cycles, not another serial glue programme.

## Current decision

Publish the completed U045 development result, retain baseline A, and prepare the bounded addition comparison. Do not launch the old exact-key U045 confirmation just to finish its earlier plan. Choose the feedback contract first, then freeze the corresponding concrete variant and run the agreed preparation cycles before any science launch.
