# MiniFly E16–E19 hostile source audit

November 10, 2026. This memo follows the [November 8 project critique and static audit](MINIFLY_PROJECT_CRITIQUE_AND_STATIC_SOURCE_AUDIT_20261108.md). It covers the consolidated source and the parallel cloud receipts available at review time. The audit used source and existing receipts. No training, tests, imports of experiment code, or model replays were performed. Fable 5.2 identified the original E17 embedding-decay defect. The earlier Codex audit missed it. This review applies the same approach to newer arms by following each loss through its time steps, gradient paths, and optimizer groups.

## Findings that change the reading of existing evidence

### E18 B3 cannot learn its prompt-only byte embeddings

B3 starts from random weights with local heads, the short trace, answer-only loss, and no embedding decay. The batch constructor shifts the byte stream by one for prediction. The first supervised target is the first answer byte, so the corresponding input byte is the prompt terminator `=`. The operation symbol, task code, and distractor letters occur before that position. In the default E18 stream those symbols appear only in the prompt.

Both recurrent banks detach the previous state for the short-trace rule. The top head also receives detached inputs from the first bank. The auxiliary head can credit the first bank at supervised positions, but the answer mask excludes earlier positions. The manual scan restores temporal credit for the content and gate parameters. It does not write the embedding gradients or restore the path from the answer to the earlier embeddings. Thus the prompt-only rows receive zero gradient throughout this configuration. AdamW starts with zero moments for those rows and the embedding group has no decay, so those rows remain at their random initialization. The bank weights can still learn to use the random codes.

This is different from Fable’s earlier defect. In E17’s affected runs, decay actively erased rows that had no learning signal. E18 B3 prevents erasure while leaving the missing credit path in place. A B3 failure can therefore be explained by a rule that cannot learn its input code from the available signal. The current arm does not separate that from the bank’s ability to learn operations given adequate codes. Record per-byte gradient, optimizer update and displacement from initialization separately. For a focused short-trace comparison, provide identical fixed input codes to both arms and label the restriction. Retain the from-scratch arm to measure the whole package.

### E16-M2 staged seed 600013 compares different composition tests

M2 says the update rule is the only difference between matched replay arms. The original T and D receipts for staged seed 600013 use the old composition panel, while M and the oracle T use the corrected panel. The changed shortcut counts in the receipts independently expose the mismatch. At checkpoint zero, before any lifetime update, the original T and D scores are 25.2% and the new M and oracle T scores are 24.6% from the same reported birth. This is a direct counterexample to the report’s one-factor interpretation. The original learner also has the score-time Store and M does not. That is a separate scorer difference. The single-operation panel is unaffected by this particular composition split mismatch.

The score of each arm on its own panel remains historical evidence. The composition gap and the ratio to the staged reference need a common-panel comparison before being treated as an effect of the update rule. If compatible checkpoints exist, use a shared corrected panel, common Store setting, and the same generation cap and exactness definition. Record each panel hash and checkpoint hash. If a checkpoint is missing, mark the comparison unavailable at that stage instead of substituting a receipt from the other panel.

### F7 mixes panel versions, and ordered-pair holdout still permits semantic overlap

The current integrated generator fixes the old deterministic 600-triple collision. It separates held and taught random seeds and excludes the union of all taught triples from the composition panels. Older E7/E8/E10 artifacts remain historical. F7’s eighteen-seed drift tally still joins three original pre-fix E16-S pairs with fifteen corrected-panel pairs. The reducer accepts receipts by name and stage count. The 73129 learner’s blob is identical to its original E16-S receipt. The corrected-panel cohort has **13/15 family-average passes, 2/15 hard-pair passes, and 9/15 complete worked-answer passes**. The corresponding mixed-panel counts are 16/18, 4/18, and 12/18. The six new F7 runs contribute 6/6 family passes and 1/6 hard-pair pass. Publish the registered metrics and their panel strata together.

Two separate semantic holdout gaps remain. The single-operation splitter shuffles ordered pairs for all operators, so a held addition, max or min example can have its reversed equivalent in teaching. At a quarter teaching split, roughly a quarter of held off-diagonal commutative pairs are expected to have their reversals in the teaching pool. That is a property of the split, not a measured overlap count. Also, F2 explicitly supervises intermediate and final subcomputations. Excluding whole composition triples does not exclude those primitive computations from the F1 held panel over a lifetime. Group commutative pairs before splitting and report history-wide exposure at both whole-prompt and subcomputation level. The first F1 block precedes F2 in the blocked schedule and can be interpreted separately.

The suffix metric deserves its own column. It can pass a response with an incorrect intermediate or malformed prefix if the last two digits and EOS agree. Complete worked answers test a different behavior. Keep both, especially on the harder plus-minus pairs. F7’s early signature also missed its registered correlation criterion and saw no new seed below its failure threshold. Its retrospective separation of the two discovery failures is not prospective validation.

### The drift clock and replay budget change what M3 and M4 measure

F7 calls checkpoint four the end of the composition blocks. In the drift generator it is two-thirds through the run, where F2 and F3 have equal weights. Fresh F2 is possible until three-quarters through the run, halfway to checkpoint five. F2 can continue to appear in replay after that. A drop from checkpoint four to six is therefore net change under continuing supervision and shifting interference. It cannot identify forgetting after fresh composition teaching stops. M4 uses the same interval for its late-loss prediction.

M3’s higher-replay result is an allocation-policy result under a fixed optimizer dose. Replacing fresh observations with replay changes how many new observations the learner gets per unit of drift, how many records reach the reservoir, and what is available later. At seed 400009 the saved fresh-admission counts are 1,769,488 at 25% replay and 589,872 at 75% replay. Replay drawing and replacement also share a random generator, so the exact reservoir contents do not stay fixed when draw counts change.

The nominal share is measured in rows, while the loss averages over supervised bytes. A single operation supplies three answer targets. A composition supplies six. In a 64-row batch with 48 replay rows, replay supplies 60% of loss targets when the replay rows are single operations and the fresh rows are compositions. It supplies about 86% in the reverse case. Log fresh and replay rows, distinct semantic examples, and supervised tokens by family and origin. A retention experiment can start from the same acquired checkpoint and fix the delivered fresh history while comparing old-example rehearsal against a matched additional-update control. Keep the policy curve as a separate resource-allocation result.

### E17 Phase 4 rescues trainability, with an unresolved mechanism comparison

The published Phase 4 arms share the same birth within each seed. The unfrozen full-time sign arm reaches roughly 86–88% on final mod-97, versus 44–47% for the projection-only arm. This withdraws the claim that freezing the first bank is necessary. But the full-time arm uses `sign(W) * mean(abs(W))` in each backward layer. The projection-only arm manually combines terms using raw sign matrices. Because the candidate and gate matrices can have different mean magnitudes, the change can alter the direction of the combined gradient. AdamW’s approximate invariance to a uniform scaling does not remove that difference. Hold the feedback map fixed when varying the time reach of credit.

The matched replay backprop arm remains ahead by several points and costs roughly the same CPU time. On the original development modulus, the full-time arm drops from 93–95% at birth to 47–60% after block one and 11–43% at the end. The 91–93% first-block figure is for a new modulus. Final mod-97 add/sub drops from about 79–82% at 12 distractors to 18–24% at 40. Complete answers on individual hard composition panels remain below 4%, and matched backprop also struggles. These results delimit the rescue to trainability on single operations under this protocol. Full-time sign credit uses a backward pass over the item. E17’s direct equivalence check calls the same underlying implementation on both sides, so it establishes dispatch parity. Its downstream comparisons provide a narrower independent invariant.

## Source defects and limitations that can affect later runs

### E18 objective routing and checks can accept the wrong run

- The birth stem and receipt omit the loss mode. Local-head and sign-rule births can honor the requested all-byte loss while using the same artifact name as answer-only training. An existing checkpoint skips training based on file existence alone. Top-head backprop goes directly through the answer-only updater and silently ignores the all-byte request. Add the full effective objective to the run identity and reject any unsupported combination.
- The isolated-head checker measures cross-bank gradient leakage and output-switch agreement, but its executable exit gate checks the subprocess exit code. Nonzero leakage or a false switch can still yield success. The archived readings were zero and true. Add numeric assertions and a deliberate leak fixture that must fail. Record both head losses, since the current logged scalar is the main loss even when training optimizes the sum.
- The planned relay comparison also changes auxiliary supervision, parameter count, feedback form and in some arms optimizer decay. B0/B2 use through-time autograd with sign feedback. B3 uses a backward scan for its manually written gradients. B1 uses within-module backprop. Describe the actual execution paths, and compare the same heads and objective with just the inter-bank detach toggled when the claim concerns relay.

### E19’s forward gradient result is narrower than a deployable learner

- The state transition uses checkpoint buffers `R1` and `R2`. Trace groups and rate values come from module constants. Swapping two loaded rates across groups preserves tensor shapes and can silently desynchronize state and credit. Fixed-rate births tested to date share the defaults. Derive groups from loaded rates or assert exact equality before calculating any trace.
- The independent check supports gradient equality for the fixed-weight, exact-feedback, answer-masked model. Production batches pre-scan all input bytes and the mask, and the separate incremental implementation checks parity on a small fixed-weight sample. Behavioral scoring rebuilds the entire state from the prefix for each output byte. A standalone check of incremental inference and reset behavior is still needed before claiming a streaming deployment. R2 allocates the deep-trace tensor even when it skips the deep update, so its measured memory cannot establish the saving available from removing that trace.
- The cloud Stage A backprop births pass the 60% feasibility cutoff at 69.0%, 70.5% and 69.3% on held ordered add/sub at 12 distractors. The Stage B relative cutoff translates to about 59–60% absolute. Keep the registered threshold and show absolute performance and longer delays. A gap to Stage A does not isolate weight signs because decay is 0.30 in Stage A and 0.25 in the rule arms. The E17-to-E19 architecture change also replaces several components at once, so it does not isolate the removal of the upper write gate. The cloud snapshot reviewed here has Stage A and gradient checks. It has no completed Stage B evidence.

### Receipt and launch integrity still depend on filenames

- E16 exposes a seven-stage JSON before it saves final weights. E18/E19 save weights first and the score separately. Interruptions can leave a completed-looking score with missing or stale weights, or a checkpoint without its score. E18 silently skips an existing checkpoint and E19 refuses to start if one exists. E19’s birth verifier loads weights without binding them to the matching score receipt. Publish completion atomically after validating all files. Bind the effective config, source, birth, checkpoints and evaluator panel into one receipt, and separate partial files from completed ones.
- The new E17 Phase 4 launcher overwrites any existing machine lock containing the string `Claude` and later removes a lock by that same substring. Two producers can overwrite or delete one another’s lock. The shell group wait also does not validate individual child exit codes. Use exclusive creation and a unique owner token, then require an individual completion receipt per job. The source permits these races. This audit found no evidence that a race altered the completed Phase 4 data.
- Replay filenames use rounded percentages, while behavior uses rounded batch slots. For batch 64, .875 and .883 both tag as `_rs88` while requesting 56 and 57 replay rows. The prescribed M4 settings are distinct. Key artifacts by effective config and include the integer allocation in each receipt. The plain same-loss summary route was fixed, but a future drift-plus-all-byte run would still map to the drift answer-loss comparator by branch precedence. Join on explicit fields rather than filename substrings.

## Order of correction

1. Amend the M2 attribution and publish F7 by panel version. Preserve the original receipts. Treat a corrected common-panel score as a separate analysis.
2. Define a byte-level credit census for the actual training path. For each symbol role, record supervised locations, first-step gradients, per-stage weight movement, optimizer state and decay. An active parameter tensor or a passing aggregate gradient check does not establish that the required rows learn.
3. Require fail-closed executable checks for split overlap, gradient isolation, rate-buffer consistency, loss routing and artifact identity. A check should reject a deliberately wrong panel, a known gradient leak, and a deliberately mismatched checkpoint.
4. Use three separate decision rows for mathematical equivalence, behavioral learning, and resource advantage. E19’s exact trace can pass the first while the other two remain open. Compare feedback maps, temporal reach and optimizer settings independently before choosing a mechanism.
5. For a durable learning result, measure complete autonomous outputs, longer gaps, and an unrehearsed old skill at an explicitly logged exposure budget. Fixed decay banks carry traces across positions within an item. Persistent cross-record state, iterative transformation of held information, and slow weight consolidation remain different hypotheses.
