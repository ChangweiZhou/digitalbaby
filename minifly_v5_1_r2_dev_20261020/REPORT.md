# MiniFly v5.1-R2: three-cycle development exercise

**RESOURCE_LIMIT_NO_EFFICACY_VERDICT.** 4,303 main applications and 6 complete histories were recorded before the resource limit. The fixed resource bound stopped execution. Missing histories/endpoints were not filled by a smaller task or automatic continuation. Stop reason: total CPU/wall cap.  No formal science, efficacy confirmation, GitHub upload or core adoption was performed.

The important separation is that upstream byte formation now works in this assay, while exact arithmetic behavior must still be judged from the complete learner's own generated bytes and EOS. Component success is not addition success.

## Fixed goal and evidence

The goal remains better retained generalization to unseen addition per all observed training presentations and actual compute. Gradual warmup, raw 256-byte payloads, a distinct own EOS, the native Full151/R_center-derived value path and the architecture exclusions were retained. There are no arithmetic features, role labels, arithmetic rules, attention, Transformer, ELM or backpropagation in the new learner. Addition parsing and analytic answers live only in evaluator-owned data/audit code.

This is a two-birth engineering diagnostic with four **correlated** histories per birth. Taught-item exact recall is E1; held unordered operand pairs with no answer exposure and the no-OLD-write/shuffled controls are exploratory E3 tests conditional on common D0. E0 component/interface repairs and negative addition acquisition/held observations on completed histories; full planned two-birth paired E3 harness incomplete. Repeated presentations and correlated histories are not independent worlds. A small null result does not prove arithmetic or local learning impossible.

## The three cycles

1. **Design/audit/test/revise — causal and numerical interfaces.** Observed-vector farthest-first initialization replaces random unmatched prototypes. Float64 MSE distinctness tolerance is locked at 1e-12; duplicate placeholders never compete. Native equation/reference parity was exact in the tested fixtures at 5,177 and 65,536 cells. All 256 payload tokens and EOS round-trip; EOS masks the eight byte teaching channels. Shared prefeedback frames, BEGIN reset, separate REPLY clock, query-copy parity and readonly checks passed. The component suite consumed 3.21 CPU seconds, below its 60-second limit. Revision locked these executable details without changing the task or rates.
2. **Design/audit/test/revise — integrated representation.** M2 and all M3 candidates were seeded from actual observed vectors, with bounded reservoirs, gradual local rates, output gates and fixed reseed rules. M2 froze before normalized context profiles; class count was selected only from D0 listening validation. The actual native side masks and activity fraction 0.035355339 were used. M4 calibration consumed the same passive prompt, REPLY, pre-answer and terminal EOS frames as the learner. Representation and thresholds then froze. A one-class result remained a warning, not a reason to avoid the whole-chain test.
3. **Design/audit/test/revise — bounded addition chain.** The fixed 16-OLD/8-NEW/64-held-orbit roster was used. OLD had 512 presentations, then one simulated hour, NEW128, another hour, and readonly probes. R-W, A-W, R-N_OLD and R-SH_OLD were processed sequentially, paired on D0 and data. The initial 16-record profile projected 539.1 CPU seconds of production; actual evaluation/formation costs were also charged. Replay was disabled. Rates, n, task and sample counts were not rescued after seeing results. The postcycle revision below is proposed, not another executed model.

The prototype still performs global projections, sorts and all-cell native sweeps. Sparse activation is not sparse computation or a scaling result.

## Interpretation and remaining limits

D0 exposed correct answers but deliberately disabled native value learning. Its thousands of records trained byte/context/threshold formation, not the operative native input-to-answer association. The complete arithmetic value path then saw only 16 OLD facts and 8 NEW facts, repeatedly. All D0 still counts against sample efficiency; it must not be described as thousands of native arithmetic teaching examples.

The earlier byte aliasing diagnosis is no longer sufficient to explain this run. The repaired chain can retain distinct observed byte identities and stable addresses; that does not establish useful task-dependent native value separation. Poor exact taught acquisition means a held null cannot be diagnosed as pure overfitting or an arithmetic-abstraction failure alone. Improvements in teacher-prefix bit/loss measures can reflect common output statistics while free answers remain wrong.

The native-allocation arm is a direct control for the strict slow-write gate under the **same repaired encoder and gradual dose**. Its actual curve, not the old isolated port, determines whether changing that gate alone helps. The two births also differ in learned context grouping; this is descriptive birth variation, not an independently randomized class-count ablation.

The provisional schedule was not strengthened. Its counter starts at the first post-D0 native record: strength rises from 1/256 to about 0.04047 by record 640, below the 1/16 ceiling; this is not a full-strength acquisition test. The real-frame one-event check does not settle cumulative dose versus cross-input interference. Per-event mixed-sign and spacing-rejection telemetry was not retained; final q/fast/slow compartment distributions are in results/STATE_AUDIT.json. This omission is carried into the proposed revision rather than filled by rerunning histories. No stronger-rate grid, extra worlds, task reduction or automatic scientific launch follows.
