# V157 C — independent architecture sufficiency protocol

**Protocol only, not launch-ready.** C must be specified independently of A1 and B; it is not paused until they succeed. This delivery defines the computational contrast and its obligations. Exact forward equations, dimensions, local learning rule and resource manifests remain to be locked before implementation. Do not instantiate five speculative architectures from this roadmap as one experiment.

## Question and minimal contrast

Does **stored native knowledge influencing later learned state transitions** add useful computation beyond a bigger associative store or recurrent state alone?

| Registered role | Purpose |
|---|---|
| NATIVE | Pinned N_2B/P_SLOW lineage reference |
| WORKSPACE_OFF | Generic learned recurrent state; native-memory-to-state input exactly zeroed |
| WORKSPACE_ON | Same birth/forward graph/state size; native expressed values affect the next state transition |
| CAPACITY_OFF | Additional active state/edges without memory feedback; exact counts and measured work separately matched before comparison |
| LEARNED_KEYS, optional later | Only a separately qualified B functionality, added in a new component/integration contrast |

OFF is an exact causal lesion, not a functional capacity match: unused feedback weights cannot be counted as useful computation. CAPACITY_OFF must state active/total parameters, state bytes, visited edges, arithmetic, communication and measured per-event cost. Report remaining mismatches instead of asserting “matched” from equal hidden width.

## Required causal forward path

A valid candidate has the generic path

`raw byte → learned recurrent workspace → bounded native cue modulation → native value memory → own C16 byte/EOS output`,

with a separate arrow `previous native expressed values → next workspace transition` only in ON. Neurons have no assigned arithmetic roles. The workspace must change the operative cue/read path; a decorative recurrent vector does not test the question. The addition protocol supplies no special stack, operand slot, carry unit, parse tree, arithmetic action or fixed retrieval/composition loop.

Before each byte transition, read only the declared previous native state to obtain the 16 native expressed values. Update the workspace once from its prior state, the actually observed/generated byte and that previous memory signal. Apply one declared bounded cue modulation and native event. This causal delay prevents an algebraic fixed-point loop. During training the current expected target is unavailable until the candidate has predicted; during recall only its generated continuation is fed back. No external readout, witness or future target supplies the memory signal.

The source must explicitly define workspace initialization/reset versus persistent memory, byte embedding, transition/gating matrices, normalization/scale, cue modulation, native event order, memory-read count per byte, and end-of-record behavior. Ordinary recurrent gates are allowed; attention, Transformer operations and query/key ranking are not. An alternative complete core remains possible as a separately identified design, not a Full151 success by name.

## Bounded diagnostic ladder

Use existing byte/addition scoring and at most these small diagnostic families before broad architecture claims:

1. **KEEP:** predict a sampled raw byte after independently sampled distractors. Specify trained lengths and a held length; audit first/last-byte and key-table shortcuts. This is an E0/E1 memory/sequence stress test where positional shortcuts can solve it, not proof of learned arithmetic or general computation.
2. **UPDATE:** a data-stream context switch changes which sampled byte is relevant. Any instruction markers/grammar live in the data, never in a parser or neuron role. Compare pre-switch/last-field/frequency shortcuts and no-relevant-teaching controls. State the evidence level actually supported.
3. **USE, conditional:** learn opaque random byte relations in earlier records, then query a prespecified never-taught composition or new content using them. No composition operator is programmed in the candidate. Compare prior-teaching inhibition, direct-query lookup, component/frequency shortcuts and an explicitly engineered composition oracle as a scorer/reference only. The full grammar, exposure counts and held combinations must be locked before this stage; it is not implicitly authorized by naming the task.

These tasks isolate candidate functions. They cannot replace unseen addition, turn copy-task success into arithmetic-rule learning, or relax complete own output. Any longer input or output limit is an explicit new capacity declaration, not a hidden task-specific exception.

## Separate expression, optimization and local learning

A constructive witness or qualified optimizer may establish attained performance on the **same declared forward architecture**. It must declare where differentiation stops or uses a surrogate; hard KC competition and native stores cannot be silently replaced by a smooth classifier and called an identical model.

Reference weights and targets never feed the local arm. Freeze the forward graph before comparing the actual biologically motivated update rule. A failed reference leaves architecture/optimization unresolved; a successful reference with failed local learning localizes a learnability gap only to that tested setup. Neither result is a mathematical architecture impossibility proof, and neither blocks A1.

V6-R1 found no complete taught/held answers and universal truncation in its specific eight histories. Its subsequent review measured cue signals small relative to stochastic tape effects, and no qualified optimizer established that implementation's sufficiency. Preserve that negative result; do not claim “recurrence has been ruled out.” Qualify input/state signal scale and initial sensitivity before spending another architecture run.

## Mandatory pre-implementation closure

Before a C implementation or test is requested, deliver:

- Exact graph/dimensions, source parent, cue modulation and read/transition schedule, with no inert workspace or answer bypass.
- A literal local update equation, eligibility scope, feedback provenance and timing; no undefined “three-factor rule” standing in for an algorithm.
- A gradual warmup schedule and actual counter for every new plastic path; compatible supervised feedback; no inferred scalar-only capability.
- Fixed arms, actual capacity/compute mismatches, ablations, seeds and data/exposure manifests.
- A known solvable mechanism fixture, mutation/readonly tests and qualified reference limits.
- A single declared record/CPU/RSS/query cap, counted replay/optimizer reuse and stop conditions; no automatic grid expansion.

A small interface/reference qualification can be the first independent C delivery once those specifications close. There is no runtime budget or runnable architecture implicit in this annex. It neither retries V6 nor borrows A1/B's unused budget.

Integration follows demonstrated functionality: compare a parent, each function alone and the combination with matched information and own-byte/EOS outputs. Only a subsequent controlled unseen-addition result earns an addition claim.
