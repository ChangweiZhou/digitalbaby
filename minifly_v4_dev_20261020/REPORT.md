# MiniFly v4 three-cycle engineering report

**Verdict: NO_ADVANCE — coverage and acquisition prerequisites are not qualified.** This is a bounded engineering result, not a scientific rejection of rule-free addition learning.

Claude’s v4 memo at commit 190a26c was implemented as generic raw-bit IO, learned segment boundaries, position-local/random KC maps, native nine-channel value memory and recurrence-gated consolidation. No arithmetic parser, arithmetic-designated neurons, attention, Transformer, ELM answer model or backprop was introduced. Gradual warmup was retained.

## Three cycles

1. **Design/native audit:** native event parity at 5,177 cells, all-byte IO, content-identity confirmation, frozen queries and checkpoint/resume. Event parity did not by itself qualify the new teaching port.
2. **Coverage preflight:** six registered 65,536/262,144-cell size/policy/wiring cases; 128 fitted and 64 held records each. The external linear readout fit training bytes at 100%, but held answer-byte correctness was 5.39%–9.13%, with 0% teacher-forced exact held records. The 95% coverage gate failed. This fitted head is an evaluator-only diagnostic, not a learner or an impossibility bound.
3. **Bounded learning sanity and revision:** corrected native-port teaching, replay limits and query chronology, then two technical worlds × seven arm/control histories, 64 fresh external records +8 replay applications each. The large P3/G2 run was not started.

## What the result does and does not establish

The correct teaching direction is verified, but the current short warmup does not qualify exact byte acquisition. Boundary learning remains close to its neutral policy; nonzero confirmation/slow weights are not proof of useful reusable structure. A recurrence gate can consolidate ordinary bit/format regularities as well as useful patterns. Its sigmoid also permits 0.899% slow allocation at q=0, so it is not a strict “nothing permanent before confirmation” rule.

The pre-learning G0 ordering is circular if useful segment codes require learned boundaries. A fit on untrained stochastic/neutral features does not reject the eventual learned representation. Conversely, increasing KC count fourfold did not meet G0 in these probes. Neither observation licenses a larger run or a claim of impossibility.

Compared with v3, v4 changes input encoding, output ports, cell population, commitment, segmentation, arithmetic length and repetition policy. These tests do not isolate which change explains the difference from v3’s strong taught recall. Stability-controlled warmup and a small fresh-only dataset also differ from v3’s repeated facts. No arithmetic-specific repair or lowered exact-answer standard was used.

The first empty-set digest failure used four generic applications. A zero-replay slice bug used four preflight applications plus 64 external and 40 replay applications in an invalid B0 history. A reversed teaching coefficient was subsequently found by source-to-port audit; six complete wrong-sign histories and 16 whole records in a seventh were preserved as invalid, along with four preflight applications. A directional fixture then needed a matched passive-adaptation control; its four generic applications are also counted. Syntax/import/launch failures before training used zero records. None supports a model efficacy verdict. The corrected sign, replay boundary and passive chronology are tested in the final source.

The ledger totals **1,602 native full-record applications**, including all failed work and replay. Corrected G1 contributes 14 correlated histories and 1,008 applications (896 external, 112 replay). G0 separately used 1,152 teacher-forced code-extraction record presentations and 5,430 target positions, with no native learning. The combined presentation total is 2,754; it is not a scientific sample count. Scientific records/jobs: **zero**. Partial native-event fixtures are listed separately.

## Compute and limits

Corrected accepted jobs recorded 126.22 production CPU seconds, 435.56 primary-evaluation CPU seconds, and 652.47 full job-phase CPU seconds. G0 used 55.74 CPU seconds. The corrected third cycle’s process peak RSS was 542.1 MiB. One numerical thread was used; caffeinate followed the controller.

Cycle/job intervals exclude startup imports; historical CPU of failed attempts and secondary-greedy timing are not independently itemized. No end-to-end efficiency advantage is claimed. ru_maxrss is a cumulative process high-water mark, not an isolated per-arm peak. Global KC projection/top-k and query-state copies remain explicit prototype costs; sparse activity is not a sparse-compute claim. No end-to-end efficiency advantage is established.

## Revised next prerequisite

Keep the addition goal and generic architecture constraints. First qualify the new bit-output/native interface on bounded taught byte episodes under the declared gradual warmup, with matched native no-write controls. Then qualify boundary learning from the same observed raw addition stream, and run G0 on frozen **learned** codes with a new diagnostic split. Only after those prerequisites should consolidation’s benefit be compared at matched data and cost. A generic byte-prediction feedback arm may be designed separately; no delimiters, digit/place/carry features or arithmetic relations may be supplied. No such new training run was executed here.

A future comparison should retain an explicit v3 anchor on a shared addition range and distinguish output-format acquisition from arithmetic transfer. Do not silently grow N, repeat the held set, change answer order or relax exact own-output scoring to manufacture progress.
