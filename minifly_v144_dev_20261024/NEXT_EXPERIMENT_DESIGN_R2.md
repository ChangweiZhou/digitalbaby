# V144-R2: bounded complete-addition capacity screen

24 October 2026. **Prospective design; the screen described here has not run.** This document refines the [V144 design](../minifly_v144_addition_readiness_design_20261024/DESIGN.md) and [R1 amendment](REVISED_DESIGN.md). It supersedes their Stage C implementation and reporting rules where stated below. The completed three-cycle [V144 report](REPORT.md) remains historical evidence, not a result of this screen. Writing this document does not authorize or launch training.

## Question and boundary

Can the inherited raw-byte representation and a bounded shallow learner acquire **complete, self-generated addition answers on never-taught operand-pair orbits**, at a measurable cost? This is a reference-capacity diagnosis. It is not a new MiniFly core, a native Full151 efficacy run, a persistence test, or a test of scalar-only feedback. The evaluator may calculate the correct sum and reveal answer bytes during the existing supervised warmup. The learner receives only the FE-PERM byte events, generic boundaries and observed feedback tokens. It receives no parsed operands, arithmetic feature, carry rule, target length, answer codebook or forced EOS.

The next action is to repair and qualify the finite Stage C dispatcher and result reduction, then run the already specified screen. Do **not** add centering, replay, homeostasis, bank arbitration, another decoder family or extra prompt renderings to this experiment. V144's native D2 parity diagnostic need not be rerun. Its residual and update norms refute *vanishing* teaching for that recipe, but do not establish useful credit direction. Its high code overlap coexists with class information; overlap alone is not evidence that separation machinery is required.

The 64-pass H128 reference trial is a development fixture, not the capacity screen: BP/DFA/FROZEN held complete-orbit scores were 6.67/3.33/6.67% while taught scores were 77.50/81.25/15.00%. These numbers neither establish addition generalization nor prove that the data cannot support it. BP often generated EOS at the correct length yet missed the answer, so stopping is not the sole observed bottleneck. V143's parity result remains partial native component evidence, not complete-addition evidence.

## Frozen scientific protocol

Retain the original Stage C data generator, FE-PERM event API and byte/EOS interface. Prompts are `a+b=` with single-digit operands. There are 55 unordered operand-pair orbits; each world holds out 15 entire orbits, including both orientations, and uses nested 20/30/40-orbit training pools drawn from the other 40. Expected payload is the canonical ASCII `str(a+b)`, followed by EOS 256. A generated output succeeds only if its **entire own payload and own EOS** are exact within eight output decisions. An invalid code, premature/late EOS or cap exhaustion is failure. Generated prefix bytes feed the next prediction; no teacher-forced prefix enters evaluation.

Keep the four named worlds `V144-CAP-D1/D2/H1/H2`, the SHA256 seed convention and split constraints in the original design. D1/D2 are development worlds. H1/H2 are holdbacks and remain unopened until **all** configuration selection, code, reducer, baselines, metrics and manifests are frozen. The earlier `V144-EXERCISE-C2` split never becomes a holdback. If a split is regenerated or a holdback is inspected prematurely, record the incident and do not call it untouched confirmation.

Retain the three modes: exact-gradient BP, fixed-feedback DFA, and feature-frozen with trainable output weights. They have the same initialization substreams, presentation order, nine-bit byte/EOS loss, rate ramp and output protocol. These are evaluator-side references, not replacements for native banks. Preserve the original 27-cell grid: hidden size 128/256/512 × learning rate 0.003/0.01/0.03 × decay 0/0.001/0.01. No new optimizer or model family enters the grid.

1. Run all 27 BP configurations on each D world at 40-orbit dose through 64 passes. Preserve **one finalist per hidden size**. Rank within size by mean development held complete-orbit accuracy, then lower development teacher-forced BCE per token, then measured CPU, then lexicographic rate/decay. This is development selection, never independent confirmation.
2. Continue each finalist BP history from its saved pass-64 state through 4,096 passes. Run DFA and FROZEN on the same three configurations and D worlds from birth through 4,096 passes. Save birth and pass 1/4/16/64/256/1,024/4,096 checkpoints. Select one common configuration by mean final development BP complete-orbit accuracy, with the original tie rules. A DFA comparison at this BP-selected setting is **not** a best-possible local-rule search.
3. Freeze that configuration and run BP/DFA/FROZEN in H1/H2 at each nested 20/30/40-orbit dose through the same checkpoints, with no holdback-driven tuning. Each dose is a separate fit from birth; nested pools do not make their outcomes independent. This is 18 holdback fits.

There are at most 66 development starts and 18 holdback starts. The original conservative ceilings remain: 10,567,680 record presentations, 31,703,040 revealed target tokens and six **summed process CPU-hours** for Stage C, including failed attempts and probes. Use at most two processes and one numerical thread each. The dispatcher must admit work against the remaining budget before starting it, checkpoint only at whole-record boundaries, and record interrupted attempts. If the roster cannot finish inside the ceiling, return `INCOMPLETE_CAPACITY_SCREEN` with missing cells; no best-so-far result is a completed holdback verdict. An increase in resources requires a separately dated revision, not a silent extension.

## Repairs required before training

These are narrow engineering corrections to the existing Stage C implementation, not extra research gates.

**Typed result validation.** Replace the present `complete == true` plus nonempty `metrics` test with an explicit schema per native, reference and fixture artifact. Require exact identity (world, split hash, mode, configuration, dose, checkpoint/pass, code and asset lock), unique roster ID, expected checkpoint sequence, and present nested metrics for both taught and held sets. Numeric metrics must be finite and in range; counts must be nonnegative integers. Reconcile per-history record/target-token totals with checkpoints, attempt ledger and declared exposure ceiling. Reject duplicate/extra histories, unexpected settings, missing assets and mismatched source closure. A validator success means only that the specified checks passed.

**Negative fixtures.** Demonstrate nonzero checker exit and an invalid verdict for each of: a missing nested metric; NaN and infinity; an out-of-range accuracy; wrong world/configuration or checkpoint count; duplicate result; absent expected result; inconsistent record/target total; source/asset mismatch. Keep synthetic fixtures out of scientific exposure counts, while charging their CPU to campaign cost where measured.

**Complete reduction.** Derive an exact expected roster from the locked manifest. The final reducer must compare this roster with files on disk before aggregation; it may produce an exploratory partial table, but that table must be marked `INCOMPLETE`, name every missing/extra cell and carry no final verdict. Never silently skip a missing native result or accept a glob of whatever reference results happen to exist. Validate checkpoint counts and settings again at reduction. A failed reduction exits nonzero.

**Restoration and provenance.** Provide one deterministic local restoration command or script that fetches/checks the pinned V143 source commit `4c12621d0804d2495c2eacaebf4e17aaeb994771`, the V144 source revision actually used, imported Full151 dependencies and the canonical birth/graph assets from their recorded locations; verifies SHA256 for each; then runs the synthetic qualification and compact reduction. Record runtime versions, numerical-thread settings, source hashes and asset hashes in a new lock. If an owner-only asset is unavailable, fail with its identity and expected hash; do not silently substitute a dataset. The compact bundle may remain under 10 MB and point to unchanged parent assets. It is reviewable source/results, not a claim that absent raw trajectories are independently reproducible.

Qualify the repaired dispatcher, resume path, validator and reducer on disposable synthetic or development fixtures before opening H1/H2. Changes to scientific protocol after inspecting capacity results require a new version and fresh untouched worlds.

## Scoring and competitive controls

The primary score is **held complete own-generation accuracy**, averaging orientations within each held orbit and then orbits within each world. Report each world, dose, mode and checkpoint separately, together with all record presentations, revealed answer/EOS tokens, process CPU, wall time and peak RSS. Give taught complete accuracy and an exposure/CPU curve; this separates acquisition from generalization and sample efficiency. Report one- and two-byte answer strata, invalid/cap rates, and EOS-at-correct-length. Teacher-forced loss and accuracy are diagnostics only.

Compute payload-only and complete accuracy on **the same oriented prompts and with the same orbit-level weighting**. Their difference then has a valid stopping interpretation; do not compare percentages made with different denominators. Count withheld relations as 15 orbits per world, not 30 orientations or many output tokens. Any later surface rendering of a known relation is a separate rendering measure, not a new independent relationship.

Run evaluator-only baselines on the identical split and score denominator: existing raw/unordered lookup and frequency controls; literal `COPY_A` and `COPY_B` from the prompt byte positions; and a training-only nearest-neighbor answer retriever using a prespecified distance on the same raw byte representation with deterministic tie-breaking. These heuristics must emit their predicted payload followed by EOS and obey the same output cap. The trained FROZEN reference is a separate matched learner control. Lookup abstention on intentionally withheld keys is expected and is not a meaningful positive hurdle. None of these baseline predictions, parsed prompt positions or labels enters the learner's training path. Freeze distance, ties and fallback before H1/H2.

Present paired BP−DFA and BP−FROZEN differences by world, dose and exposure, plus each mode's margin over the **strongest** shortcut heuristic. A single correct orbit in one small holdback is not robust transfer. For a *screen-positive reference feasibility signal*, require at least one of BP, DFA or FROZEN to exceed the strongest heuristic on complete answers in **both** H worlds, including at least one correct held two-byte-answer orbit in each, and disclose the exact orbit counts/margins. A FROZEN success establishes feasibility for that control, not a benefit from feature learning. This is a conservative decision rule for the next experiment, not proof of a general arithmetic algorithm or a claim of statistical population confirmation. If it is unmet, show the full curves instead of promoting a favorable checkpoint.

## Decision after the screen

| Observed pattern at the frozen final configuration | Licensed next question |
| --- | --- |
| BP and DFA transfer on complete held answers at reasonable exposure, native integration still absent | Can native addressing/readout and joint learning preserve that structure? Design a separate paired native addition run. |
| BP transfers but DFA does not, with comparable taught acquisition | Test local-credit direction on a fresh bounded development stream, recording the missing per-event feedback vectors and gates. Do not infer direction from update norm alone. |
| Both acquire taught answers but fail held complete answers | The tested representation/training bias overfits. Probe reusable byte-level transformations before adding memory storage. |
| Both acquire taught answers poorly | Diagnose basic optimization and interface limits; no data-insufficiency theorem follows. |
| Only very high repetition works | Report capability and its poor sample efficiency separately; seek a lower-exposure mechanism next. |
| Payload succeeds but correct EOS does not | Localize generic sequence termination without supplying target length. |
| FROZEN matches learned features | Learned features have not justified their extra learning/compute cost at this task and budget. |

These branches are interpretations, not an automatic launch of another arm. If the capacity screen supports native integration, write a separate design comparing V143-derived learned and frozen addressing on the same complete-byte task. That design must account for the native nine-bit port, both banks and combined output, no-prior-teaching and orbit-consistent answer-shuffle controls, and **actual intervening learning** before a persistent-core claim. Merely waiting after training, fitting held lookup keys or improving parity is insufficient.

Deliver `REPORT.md`, locked manifest and source/asset hashes, full roster and validity result, compact final metrics tables/curves, key figures, configuration/model files, acceptance checks, attempt/cost ledger and a restoration manifest pointing to unchanged parent assets.
