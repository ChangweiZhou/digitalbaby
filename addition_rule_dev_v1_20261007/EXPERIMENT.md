# Limited addition learning development exercise

The user authorised three design–audit–test–revision cycles, not a scientific confirmation run. The goal is a persistent MiniFly V2 that learns a bounded addition rule from imperfect worked examples. This exercise compares native Full151 and a new U045 content-matrix instance. The older exact-key U045 instance remains on hold. No E4, mixed arithmetic, carry, free-running output, or new front-end search is included.

## Frozen task and feedback for these cycles

Operands are ASCII 0–4, exact answers 0–8. The model consumes raw bytes `a+b=` and emits one answer byte at the visible `=`. The answer then actually arrives, or a newline signals its absence. The model API accepts only the current byte and clock; truth, pair ID, phase, missingness/noise identity and held-out membership are not model inputs. A finite grammar/labelled-digit decoder and independent thermometer features are declared engineering components, not learned fly mechanisms. The encoder encodes the earlier and later digit separately; it contains no addition or answer feature. Cycle 1 used the common native PN→KC projection. After its valid 0% held-out outcome, cycle 2 uses common role-partitioned fixed sampling: each independent input feature receives fifteen eligible KCs, 420 fixed edges and 180 active KCs per expression. This is an engineered U069/U070 component, not the anatomical PN→KC map. Both cores receive identical codes; native content dynamics and canonical births remain unchanged. No sum or answer is encoded.

All 25 expressions are prospectively partitioned. Held-out commutative orbits are `1+1`, `1+2`, `0+4`, `2+3`, `3+3`, eight ordered questions including reverses. They are absent from all training. Thirteen old training forms cover every operand and all nine output digits. The later four forms are `1+3`, `3+1`, `2+4`, `3+0`; some reverse forms already occurred in old training. Their teaching is intervening additional experience, not a second unseen-rule milestone. None intersects the held-out set.

Each training form occurs 40 times: exactly 32 correct answer observations, four uniformly sampled wrong digits and four missing answers. Order, corruption and missingness are seeded by the world. Thus missing answers give no answer-target update; an incorrect actual answer teaches the incorrect byte. N_OLD receives exactly W's raw stream and clocks. SHUFFLED permutes the old present answer digits while preserving missing locations and the answer histogram; new records match W. SHUFFLED therefore has the same questions and times, but deliberately different old answer bytes. Do not call its sensory stream bit-identical to W.

Chronology is old teaching → 24 h model-time rest → four new forms taught → another 24 h rest. Model time is not wall-clock waiting. After each phase, a read-only clone answers all 25 questions without answers or feedback. Closing newline resets the sensor. All questions have the same prospective ordering within a checkpoint across configurations/histories. Probe clones and their cache cannot alter the operative state.

Each configuration has W, N_OLD and SHUFFLED, six training histories per world. N_OLD disables actual old answer writes and enables new ones. Readouts must use the same operative state as updates. A final clone with content erased must match its zero-content distribution: uniform for native/categorical instances, zero-centred fixed ordinal rendering in cycle3. Independent tests check real arrays, teacher sign, branch flags, missing-answer behaviour, source/fixture exposure, code equality and pending checkpoint equality.

Primary DEV feasibility is delayed held-out exact accuracy, plus causal W−N_OLD and W−SHUFFLED. Report all checkpoints, every held-out question, trained old/new accuracy, MAE, probability loss, training bytes/feedback count, CPU and mutable storage.
