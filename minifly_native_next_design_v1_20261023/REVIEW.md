# Static design review

23 October 2026. Author's document review only; no independent agent, implementation audit, technical cycle or training run is represented here.

The attached review is incorporated with three deliberate distinctions:

1. **Preserve the storage candidate exactly.** Confirmation uses fresh pairs and the original asset hashes. More cells, different graphs, larger feedback, EOS retuning and new heads are excluded. Four storage/attribution contrasts and two complete-output contrasts have separate claim levels within a fixed six-comparison family. A passed gate does not certify deployment reliability.
2. **Make arithmetic admission depend on actual native addressing.** Hidden-state Euclidean noise need not by itself prevent a useful code. The birth screen therefore uses equal-length input identification from supports, cross-tape support contrast and synthetic teacher-to-native-margin responses. Only OLD prompts and no answers are used. The null boundaries are zero contrast and 1/8 identification chance, not a retrospective desired SNR. Two length strata and two worlds remain a limited engineering check; passing does not establish universal input reliability or arithmetic learning.
3. **Separate EOS class balance from payload and total dose.** The new rule never amplifies a terminal teaching event and uses only completed-record counts. Its uniform reference matches a predicted average attenuation, not realized applied plastic dose. Both that limitation and the actual L1/L2 accounting are explicit. Frozen STOP, direct EOS, positional and fixed-length results remain separate.

No arithmetic-specific representation, numeral topology, auxiliary parity/modulo task, supplied relation, worked-example stream, backpropagation, ELM, attention, Transformer or new payload decoder is admitted. Historical proposals do not authorize these additions.

Gradual warmup, all repeated observations and preceding source/head/calibration provenance remain chargeable. A/C explicitly permit exact-key recitation and stay E1. B's learned/frozen/no-OLD/shuffle and observed-only countermodels prevent better fixed addressing or marginal byte prediction from being automatically called arithmetic abstraction.

The sampling choices are engineering decisions, not demonstrated power calculations: A uses 32 fresh pair units, B two development worlds, C eight development pairs. A publishes uncertainty and approximate paired-family bounds; B/C are exploratory conjunctive screens without confirmatory significance claims. No probability forecast from Claude's discussion note is used to justify these counts.

Resource and record arithmetic was checked statically in SPEC.json/STATIC_CHECKS.json. This does not establish runtime feasibility. Qualification plus the first complete planned unit must support the locked budget before continuation, and the original units cannot be replaced after a failure.

Potential failure interpretations remain separate: (a) inadequate input-conditioned state, (b) acquisition/teaching failure after a passed state screen, (c) taught success but held-out failure, (d) genuine held-out learning contribution, and (e) positive storage without reliable EOS. None leads to automatic sample extension or mechanism stacking.

The arithmetic, memory and procedural execution pointers are byte-identical to their pre-delivery versions. This package describes future work only. Implementation, a three-cycle exercise, execution, confirmation and publication each require a subsequent instruction.
