# MiniFly V192 · Context compartments for continual successor learning

**Status** DESIGN_ONLY. **Date** November 3, 2026, New York time. **Owner scope** Publish the V192 design. Implementation and execution are pending.

## Decision and lineage

Does a locally learned context gate protect useful successor statistics when conflicting transitions appear in the same byte stream? Keep direct online TD as the reference. A matched random gate tests whether any gain comes from updating less often. A provenance oracle tests whether selecting the right transition could recover the loss at all.

The operative reference is the parallel branch's V191 continual-structure direct arm, pinned at 723b49ba2232f3a9e91ec2134fe3a55d03ce6b1d. In 12 paired worlds, it reached 98.4% changed-pair accuracy after 32 feedback events and 100% at 128. Slow deployment reached 78.6% at 32 and did not meet its stable-pair gate. Those figures use an explicit parity query frame and a separately predicted newline. The consolidated V191 at fc89433801c719a6994af32682ee468143f4640b is the Round 4 replay audit. Its original parity holdout contained only even distances. V192 uses both classes and holds out reversed pairs together. The Round 5 filler observation motivates the interference test, but its cleaner-filler comparison has one seed and its confidence-weighted gate did not improve transfer.

## One intervention and matched controls

Start all arms from the same serialized A state per world. Reuse the source's aligned stride-one and stride-two TD rules, 0.65/0.85 discounts, 0.12 TD step, fixed 2,000-row projection, and 100 active readout rows. The source's explicit parity query frame and observed query cue are common to all arms. They constrain the claim to this structured byte interface. Keep local readout updates enabled on identical labeled events, with identical order, initial weights, and rates. Never feed a held answer or the evaluator's cycle order into a learner.

| Arm | Which observed transitions update the deployed maps |
|---|---|
| DIRECT | All eligible transitions in the observation records. This is the direct online rule applied to the mixed stream. |
| CONTEXT | Assign each eligible transition to one of two map compartments using a context score computed before the next byte arrives. Only the foreground map is deployed for queries. The other compartment receives the remaining observations. |
| SHAM | Same two compartments, update rule, and foreground update count as CONTEXT. Permute assignment bits within fixed 32-feedback-event blocks, separately by stride, and keep observed transition order intact. |
| ORACLE | Same compartment budget. The evaluator routes true structural observations to foreground and distractors to the other compartment. This explicit provenance control defines a recoverability reference. |

Use a small, fixed raw-prefix classifier for CONTEXT. During the common clean warmup, count byte bigrams and trigrams from the observed structural stream using a 4,096-bin fixed hash and saturating counts. Freeze these counts. For each stride update, form a score by summing log-smoothed count ratios over n-grams in the preceding eight bytes, against the uniform hash-bin prior. Omit the transition's destination byte from the scoring prefix, including for stride two. Set one threshold during technical calibration on separate synthetic development worlds. Match the foreground update fraction to the declared structural observation fraction on those worlds, then lock that threshold. Apply the same threshold at all phases and report realized rates. This gate is learned from a common clean exposure. It does not test discovery of the foreground context from an entirely unlabeled mixed stream.

Generate SHAM's assignment permutation from CONTEXT's training-only mask after that mask is computed. Use independent fixed hashes per world, fork, stride and block. This offline matching is an evaluator control. It may inspect block assignment bits but receives neither targets nor held metrics, and all updates retain original chronological order. Verify exact foreground counts in every block, including the final residual. Report update norms and mismatch in which symbol rows receive writes. If ORACLE differs in dose, disclose it and interpret it as a reference rather than a dose-matched causal contrast. Use the same two-compartment allocation in DIRECT with its second compartment dormant. Score only the foreground maps in every arm. No hidden feedback from the quarantine bank, replay, architecture search, backpropagation, attention or supplied arithmetic rules.

## Stream and lifetime

Use eight paired development worlds. Derive world seeds from the first 64 bits of SHA-256 of MINIFLY|V192|WORLD|i, i = 0 to 7. Prelock all byte schedules, label polarity, swap, query and filler draws, and the two held pair panels. Preserve the same 12-symbol relation as the parallel source. Hold out 16 still-valid and 16 changed ordered pairs, each balanced across both answer classes before and after the swap. Withhold each reverse and every alternate rendering from all answer teaching. Verify both labels appear in taught pairs and some taught labels change. Each pair is scored against the actual relation of the phase.

1. **A, common clean acquisition.** Match the source schedule of 1,200 observed 16-byte cycle records and 2,048 labeled relation feedback records. Qualify the source's clean first-byte/newline reference on a small engineering roster. The native EOS adapter below must also pass the clean held-panel floor before the mixed test is admitted. Preserve all learned A state at the arm fork.
2. **B, mixed experience.** For each of 512 relation feedback records on the original cycle, interleave one 16-byte structural record and one 16-byte distractor record. Distractors reuse the same 12 symbols and contain transitions inconsistent with the original cycle. Balance marginal symbol counts and interleave record order without a model-visible provenance flag. Use frozen prefix variants to make recent context informative but imperfect. Their bytes occupy the same length budget and are included in the exposure census. Check that clean calibration prefixes distinguish the two streams above a label-blind constant, and record collisions rather than cleaning them post hoc. Both streams train the observation interface, but only genuine relation feedback writes the answer readout. End B with an independently restorable state per arm.
3. **C, EDIT and NOEDIT.** From each arm's identical B state run two 512-feedback continuations, with one structural and one distractor record per feedback. EDIT makes the single adjacent opposite-parity swap and teaches the revised labels on the original train roster. NOEDIT keeps the original cycle and labels. Match schedule, byte counts, random draws and supervision. Hold the distractor bytes fixed across the two forks. Measure before C, then after 32, 128 and 512 feedback events.

Pair all arms on input bytes and targets within a world/fork. A stride update may use only observations within a record. Reset transient byte history at the genuine boundary and preserve learned state. No arm sees the shift flag, held membership or structural provenance except the explicitly labeled oracle. A and B preserve the same underlying relation. Facts and natural prose can be follow-ups after this controlled conflicting-transition test.

## Readout and endpoints

Keep the same operative 257-class local head across arms, with the source's answer readout expanded by one EOS class. The projection may receive the same bounded causal suffix features for every arm, including bytes the learner has itself emitted. Specify and freeze the adapter during engineering qualification. Do not insert a terminal target by output position at inference. Train on genuine answer and boundary observations. For held queries, choose from all 257 classes, feed back only own bytes, and stop at own EOS or cap at eight outputs. Score a correct first byte separately from exactly one correct byte followed by own EOS. Log premature stops, extra bytes and cap hits. An engineering-only replay of the historical bigram newline convention preserves source comparability. It is a different endpoint.

Primary contrast: exact own answer plus EOS on **changed held pairs at C32**. The decision is:

- **Room for separation.** Require ORACLE to beat DIRECT by at least five percentage points on mean C32 changed-pair score. If it does not, this assay supplies no evidence that selective routing can rescue a material loss. Do not promote CONTEXT on that premise.
- **Context selection helps.** Require CONTEXT to beat both DIRECT and SHAM on the paired mean, with both two-sided 95% paired-world intervals above zero, and to recover at least half of the ORACLE minus DIRECT point gain. Five points is the prior parallel study's practical margin. Keep the full signed effects and denominators.
- **Preservation.** At C32 and C512, require CONTEXT to score at least 85% on still-valid pairs and stay within five points of DIRECT on the paired mean. In NOEDIT, require the same guard on both originally valid panels. Report B performance and the C128/C512 changed trajectory even when the primary fails.
- If the clean own-byte/EOS reference fails the 85% floor on either panel, record the adapter as unqualified before science. If first-byte gain exists but exact EOS fails, preserve that diagnostic and withhold advancement of the complete package.

Use two-sided paired t intervals on the eight world differences, and report the individual world scores. Within-world pairs and correlated forks do not count as extra independent replications. Score before feedback from disposable read-only clones. Log A/B and every C panel, including old-label responses after the change. Because structural observations and revised answer feedback arrive together, the result measures routing under joint exposure. A separate no-changed-label branch would be needed to claim zero-shot structural revision.

Compare with constant/frequency, operand marginals, exact and reverse lookup and a transition-count graph baseline that estimates the two-step relation from observed bytes. Fit its label polarity from taught pairs only. Show a separately labeled provenance-filtered graph ceiling. These evaluator references never supply learner outputs. The outcome supports at most bounded synthetic transfer in a fixed parity interface. A two-step architecture already expresses a useful parity bias. This design cannot establish that MiniFly discovered parity, learned arithmetic, or earned core adoption.

## Size, accounting and qualification

Eight common A histories, 32 B continuations, and 64 correlated C branches. Common A costs 3,248 records per world. Each arm adds 1,536 B records and 3,072 C records across both forks. Total **173,440 physical presentations** with shared A, including **107,904 structural/distractor records** and **65,536 relation feedback records** when A's 9,600 warmup observations are included in the former. The full byte/EOS ceiling is **2,424,192 sites** using 17 sites per observation record and nine per query-feedback record. Report actual per-stride eligible/accepted updates, readout writes, technical and read-only work, CPU, RSS, checkpoint and output bytes separately. Shared warmup is not multiplied by the arm count. Replayed control masks are separately charged compute.

Proposed campaign caps: 180,000 total physical records and 2.6 million byte/EOS sites, including technical; 7,200 CPU seconds, 10,800 active wall seconds, 1 GiB peak RSS, 8 MiB per deployed model and per complete state, 256 MiB retained outputs including archive. This is a new design budget. The dominant float32 readout is 2,000 × 257 scalars, about 1.96 MiB. Count fixed projections, both map compartments, hashed gate state, scratch, all checkpoint copies and verification. Store the eight complete A states and 32 complete B states. For C, retain score panels, cumulative cost counters and full-state hashes at each declared checkpoint. C states are not resume points. Budget all 40 state files and the compact results archive before admission.

Before launch, run three refinement → audit → test rounds. Check source parity and endpoint equivalence on clean fixtures, qualify causal routing and exact sham count matching, then rehearse the production entry point through the paired reducer, receipts, finite serialization and ZIP readback. Bind the rehearsal to the launch hashes. Profile the actual full roster before admitting it. Record stop reason if source closure, positive control, resource or data checks fail.
