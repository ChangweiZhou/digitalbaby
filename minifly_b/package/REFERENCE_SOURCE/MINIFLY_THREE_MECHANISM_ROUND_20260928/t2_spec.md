# T2: bounded-degree expanding PN→KC birth graph

**Implementation specification, 2026-09-28; no T2 science run has occurred.** T2 is the **T-family** representative in the three-mechanism round (R2, Z1, T2). It is a new, fixed PN→KC adjacency graph installed before the first experimental byte. The paired `T0_2` graph uses the same PN and KC nodes, exact degree sequences, edge count, weights, downstream model, and number of accepted construction switches. Both run the common **FE0-only, four-output Full151** mixed lifetime. FE1, its `h` state, and its result receipts are excluded entirely. R2's dual-bank R0 is a separate family comparison and is not used as T2's baseline.

## Source facts and narrow claim

The instantiated Full151 encoder computes `raw = m.B.T @ p[m.pn_type_index]`, then selects the top active KCs separately on the two `kc_side` halves (`minifly/V82E/src/model_evo.py:124–134`). Thus `B` is PN rows by KC columns, while the byte front end has 88 effective input channels mapped to 302 PN rows by the unchanged `pn_type_index`. The inherited full-size reference has `B.shape=(302,5177)`, 27,572 edges, PN row degree 1–590, KC column degree 0–17, and 323 input-isolated KCs. Full151's `g_pnkc_weight=0.120990` perturbs weights; `g_pnkc_rewire=0`. The exact **instantiated** Full151 `B` and its expected digest `32a3726cb25a8255c1aef5696ff40aa303138c5d061a598004d2087d4da5f964` must be checked at startup. These dimensions are source observations, not silent assumptions if the parent asset changes.

The old `g_pnkc_rewire` implementation permutes `B.data` within PN rows while leaving `B.indices` intact (`model_evo.py:103–113`). It cannot implement T2. A11 v3.8 explicitly removed its old static perturbation panel: loss after random rewire would show sensitivity, not superiority of a new graph (`WorkstreamA11_v3_8_20260923/PROTOCOL.md §34`). T2 therefore tests a constructive geometry against a degree- and weight-matched random geometry. Its graph contrast can support an architectural **E1** benefit on taught associations or, with the common no-old-relation-write branch and exposure audit, a narrow **E3** effect on the never-reinforced category relations. No topology score alone is behavioral evidence.

The common `fixture.py` fixes 600 mixed records (336 old, 264 new), two 24-hour model-clock gaps, four output stores, and first-answer-before-teacher timing. The old relation's six held-out ordered cues are absent from all teaching. A raw/canonical exact-pair table cannot answer them; a one-bit category rule learned from taught edges can. Report that simple rule, position/side/frequency shortcuts, and `W−N_old_rel` on the same continuing model state. Exact fact recall is E1, untouched spacing/prefix forms are narrow E2, and only the held-out relation with causal teaching effect can be called bounded E3. The older single-store FE0 E3 receipts and four-store CONTENT E1 receipts are references, not scores to combine.

## Fixed graph budgets and label-blind generator

For each prespecified world `w`, read the **same** verified instantiated Full151 CSR `B_native` for both arms before looking at its task labels or outcomes. The archived parent CSR is unsorted but has no duplicate edges; hash its original byte order and require unique `(PN,KC)` pairs, finite strictly positive weights, and the fixed source digest. Canonicalize only the *new* arm graphs. Let `P=302`, `A=88` independent input types, `K=5177`, `E=27572`, `c_k=nnz(B_native[:,k])`, and `W_k` be the multiset of that column's exact float64 edge weights. Preserve every `c_k`, including zero columns. Give each PN row degree `d_p∈{91,92}`: `E=302·91+90`, so select exactly 90 rows for degree 92 by ascending `SHA256("T2-v2|degree|" || uint16_be(p))`; the other 212 have degree 91. For input type `a`, let `D_a=Σ_{p:pn_type_index[p]=a}d_p`. This cap of 92 replaces the native PN hub tail in **both** paired arms; exact `D_a`, `d_p`, `c_k`, edge count and weights are matched between T2 and T0. The native graph is a separate descriptive anchor.

Use SHA256 counter streams to avoid implementation-specific RNG behavior. A stream key is `SHA256(UTF8("T2-v2|" + decimal(w) + "|" + domain))`; the next unsigned 64-bit integer is the first eight bytes of `SHA256(key || uint64_be(counter))`, starting at counter zero. `randbelow(n)` rejects values at or above `floor(2^64/n)·n`, returning the first accepted value modulo `n`; rejected draws still increment the counter. Use disjoint domains `hh`, `mix`, `opt`, `null`, `assign`, `weight`, `audit`. Save the generator version, source hashes, world ID, keys' SHA256 digests, proposal and acceptance counts, and output graph digests. Nothing in these keys or in graph construction may depend on fixture labels, correctness, byte history, or candidate behavior.

1. **One simple effective-channel graph.** Process KCs by descending `c_k`, breaking ties by `SHA256(key_hh || uint16_be(k))` then KC index. At KC `k`, choose `c_k` *distinct input types* with largest remaining `D_a`; break ties by `SHA256(key_hh || uint16_be(k) || uint16_be(a))` then type index. Add `(a,k)` and decrement those remaining type degrees. Assert no negative or nonzero final remainder. This is a deterministic bipartite Havel–Hakimi realization on the **88 channels actually driven by bytes**. At most one PN of a given type will later attach to any KC. A failure is `T2_GRAPH_NOT_INSTANTIATED`.
2. **Common random start.** Store the `(a,k)` edges as a lexicographically sorted length-`E` array and membership set. A switch proposes two array positions independently with `randbelow(E)`, yielding `(a,k),(b,l)`. Reject if positions, types or KC columns coincide, or if `(a,l)` or `(b,k)` exists. Accept a valid switch by replacing those edges. Use the `mix` stream until exactly `8E=220,576` valid **type-level** switches are accepted; cap attempts at `80E=2,205,760`. Save this common mixed `G*` for both T2 and T0. No task data enter it.
3. **T2 effective expansion optimization.** For input types `a<b`, define `C_ab=|N(a)∩N(b)|` and integer collision score `J(G)=Σ_{a<b} C_ab(C_ab−1)/2`. Starting from `G*`, make exactly `16E=441,152` `opt`-stream proposals. Reject invalid proposals and valid proposals with `ΔJ≥0`; accept only `ΔJ<0`. Maintain `C` incrementally: in a swap `(a,k),(b,l)`, `k` loses `a` and gains `b`, while `l` loses `b` and gains `a`; update overlaps with other types in those two KC columns, aggregate repeated pair deltas, and compute exact integer `ΔJ` before changing the graph. `J` strictly falls on every accepted switch. Let `A_w` be the accepted count; zero is technical non-instantiation.
4. **Matched random T0.** Copy the same `G*`; with the `null` stream accept its first `A_w` valid type-level random switches, ignoring `J`, within `80E` attempts. This matches the candidate's actual type-level switch count, exact type and KC degrees and edge count. A null graph with favorable expansion is kept; no reroll or outcome-based relabeling occurs.
5. **Assign anatomical PN rows and weights.** For each final type graph (also `G*` for diagnostics), sort type `a`'s KC neighbors by `SHA256(key_assign || uint16_be(a) || uint16_be(k))`, then KC index. Make `(p,slot)` stubs for every PN of type `a` and every `slot=0,…,d_p−1`; sort stubs by `SHA256(key_assign || uint16_be(a) || uint16_be(p) || uint16_be(slot))`, then pair. Zip the two equal-length lists and replace every `(a,k)` with one `(p,k)`. Each PN row then has exact `d_p`, every KC retains `c_k`, and each `(a,k)` has exactly one PN representative. For each arm and KC, sort native weights `W_k` numerically; sort its new PN neighbors by `SHA256(key_weight || uint16_be(k) || uint16_be(p))`, then PN index; assign sorted weights in that order. Build canonical PN×KC CSR with sorted column indices per row. Thus T2/T0 match every PN row degree, every effective type degree `D_a`, every KC degree, edge count, each KC's exact native weight multiset and sum, and global histogram. Report PN weighted sums; they need not match exactly across different partners.

`J` is a surrogate for **effective input-channel** expansion: for two types, `|N({a,b})|=D_a+D_b−C_ab`. It does not prove that larger subsets expand. The unused `audit` stream fixes 256 independent type subsets at each size `s∈{4,8,16,32}` by sampling without replacement, and separately 256 PN-row subsets per size. To sample size `s` from `n` IDs, reset a pool `[0,…,n−1]`; at `j=0,…,s−1` swap entries `j` and `j+randbelow(n−j)`, then take the first `s`; use one continuous `audit` stream, drawing PN subsets then type subsets for each size. For each subset report `|N(S)|/Σ_{i∈S}degree_i`, its mean and 5th percentile (linear interpolation at index `0.05·(256−1)`), for T2, T0, `G*` and native; native effective type degree is its actual number of distinct reachable KCs. Report exact type-pair and PN-pair overlap distributions/maxima, the type-level `J`, and final PN and type adjacency symmetric differences. No audit subset enters the objective. For technical world `w`, let `L_w` be the mean over the four sizes of `[p05-effective-type-expansion(T2,s)−p05-effective-type-expansion(T0,s)]`. Technical qualification requires exact construction invariants, `J(T2)<J(G*)`, and `median_w L_w>0` over the common reserved technical roster. Science-world graphs are never rerolled based on their audit metrics. PN-row expansion is secondary: because only 88 independent values enter through `pn_type_index`, a PN-row gain without a type-level gain would not justify the intended byte-input expander interpretation.

## Integration and causal controls

Install one immutable graph per `(world,arm)` into the Full151 `m.B` of **all four** output stores before their first experimental byte. All W/no-write branches and read-only probe clones of that `(world,arm)` share the same immutable graph. Clone source synapses, reader, teacher matrix, `pn_type_index`, `kc_side`, KC count, top-k rule, FE0 receptor state, byte predictor weights, clock and output organ by the common platform's exact rule; neither graph construction nor `B` may change during the lifetime. `T2` and `T0_2` receive identical raw bytes, answer bytes, feedback, teaching route and allowed write events. The only T-family difference is the constructed graph adjacency and its matched distribution of native weights. The existing `g_pnkc_rewire` and `g_support` hooks are not substitutes.

The common round's birth rule is **fresh Full151 native plastic, FE0 sensory and byte-predictor state at `t=0`**. The V9.2 checkpoint is historical source context, not an initialized predictor for this round. The prior checkpoint's native fast/slow/adapt and `B` matched fresh Full151 while its clock had advanced to 428,777 s; constructing a wholly fresh model avoids carrying that old clock into a birth graph. Apply the same birth to R2, Z1, T2 and controls. Install T2/T0 before the first new byte, then clone the four output stores and causal branches. Assert all T-family pre-first-byte states are identical except for `B`, with native elapsed time zero. Any older checkpoint-conversion wording in family drafts yields to this shared source lock.

The four-store FE0 parent is the shared behavioral reference; T2's primary contrast is `T2−T0_2` on the same worlds. Keep the common branches `W`, `N_old_fact`, `N_old_rel`, `N_new_fact`, `N_new_rel` and their same-clock read-only probes. For E3, the candidate's own `W−N_old_rel` must show earlier teaching causally improved unseen relation choices; a positive `T2_W−T0_W` alone cannot establish reuse. An exact taught-cue table could account for E1, a canonicalized table for the narrow E2 forms, and an exposure-independent symbol or side shortcut must be tested for E3. Record all task-specific learned write counts, first-answer timestamps, and branch state digests. The T family creates no extra learned state and no new online topology write budget; count the `B` storage and one-time construction CPU separately.

The new `B` is static but historically the Full151 `state_digest` and checkpoint path may assume a genotype-fixed `B`. Extend the **local round adapter** (do not edit frozen parent code) so fixed digest and save/restore include a canonical graph digest plus the world/arm/generator version; restore must verify the graph bytes or deterministically regenerate and verify them before any state load. A clone may share this graph only if arrays are read-only. Verify four-store and branch cloning cannot alias mutable plastic or FE0 state. Hash `B.indptr`, `B.indices`, `B.data`, shape and dtypes, and check separately that support differs from native and T0. A byte change in `indices` must fail audit even if `data` and learner output happen to match.

## Technical gate and result language

Before science, run reserved technical worlds through the **entire** mixed life and fault injection. Independently reconstruct edge sets and verify: simple graph; `(302,5177)` shape; 27,572 edges; exact 91/92 PN roster and every `D_a`; at most one PN of each input type per KC; per-KC degree and weight-multiset equality between T2/T0/native; unchanged `T`, `Q`, reader, `pn_type_index`, `kc_side`, top-k and four-store readout sparsity; exact `A_w` accepted **type-level** switches; monotonic integer type-pair `J`; changed `indices` and effective-type support; constant graph hash across every event, branch, clone, checkpoint and rest. On prespecified label-free 88-channel vectors, compute `B.T@p[pn_type_index]` independently and check adapter KC codes against the parent encoding formula; at least one vector must change raw KC drive and top-k code between graphs. Verify true FE0 with no `h`, exposure/label separation, pre-feedback first answers, no-write selectivity, timing, read-only probe isolation, deterministic replay, and save/load equality. Deliberately alter one index, weight, teacher route and held-out label in separate receipts; the independent audit must reject each.

Measure full-life wall time, peak RSS and graph/receipt bytes before setting the common science-world count and resource ceiling. Publish paired world-level estimates for delayed old taught facts, new facts, each E2 presentation, trained old relations, and final old held-out relations, including `W−N_old_fact` and `W−N_old_rel`. Report absolute W and N scores, positive-control task solvability, graph metrics and native descriptive anchor. If graph construction or shared assay fails, label it technical failure, not scientific null. If no confirmed relative effect appears, the conclusion is limited to this T2 construction on this four-store FE0 task; no FE1 inference and no claim that all static topologies fail follows.

## Implementation status

The local, label-blind generator is `t2_graph.py`; the FE0 Full151 graph/checkpoint adapter is `t2_model.py`. The 11 focused tests in `test_t2_graph.py` and `test_t2_model.py` passed under the pinned V88 native runtime after the effective-type revision, including exact PN/type/KC degree and per-KC weight audits, true support/code change, deterministic replay, independent objective recomputation, source tamper rejection, four-store cloning, checkpoint mismatch rejection, and roster-gate tampering. One graph-only technical construction on the **actual** Full151 `B` matched its expected source digest and took about 5.0 s on this host for all 441,152 optimization proposals and audits. Its type-pair `J` fell from 1,737,722 to 1,218,498 versus matched T0 at 1,722,452, and the unused effective-type lower-tail metric was +0.01408; these are E0 topology checks, not behavioral outcomes. A common full-life technical run, reserved-roster median audit, source lock, resource cap, science roster and any behavioral result remain separate work.
