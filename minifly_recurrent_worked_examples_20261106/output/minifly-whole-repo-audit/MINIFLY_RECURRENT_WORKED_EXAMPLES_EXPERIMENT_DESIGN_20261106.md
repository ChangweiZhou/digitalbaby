# MiniFly experiment on recurrent state and worked examples

**Proposed development design · November 6, 2026**

Test whether a learner can reuse the same learned answer when the order of the input records changes. Then test whether it can apply the taught rule to unseen graphs. Cross two interventions in a single experiment. One gives the model an order-dependent state that it carries through each byte sequence. The other teaches intermediate steps as ordinary bytes. The learner answers from the query alone at evaluation.

The ordered-byte run gives a concrete starting point. Its best arm answered 93/128 and 94/128 repeated teaching prompts correctly. On fresh renderings of those taught graph shapes with familiar actors it answered only 12/128 and 10/128, and it scored 0/32 held quartets in both blocks. The fresh renderings changed several aspects of presentation together. The new first test changes only edge-row order. V223's direct-byte GRU gave 6/1,536 exact held sums under BPTT32 and 7/1,536 under exact forward credit. A recurrent reference therefore needs a controlled test of what it learns from the added teaching. [Ordered-byte campaign](../minifly-ordered-front-end/CAMPAIGN_REPORT.md) · [V223 official report](../minifly-learnable-recurrent-reference/OFFICIAL_REPORT.md)

## Task and exposure

Keep the eight-link raw graph grammar from the completed experiment. Each episode introduces eight actors and their starting locations, lists eight candidate links in arbitrary order, then moves a source actor and queries another actor's location. Movement reaches the query along a directed path of active links. Two opposite teaching histories assign the active meaning to different opcode bytes while keeping every A query prefix identical. Both histories use the same familiar actor byte vocabulary.

Use the existing two-hop chain, three-hop chain and direct-plus-indirect teaching topologies. Draw 256 semantic teaching keys per block and balance their four move/stay outcome patterns across the two laws. A semantic key fixes the rooted graph, opcode assignment and location binding. Expose each key in two edge-row orders, giving 512 training prefixes. Replay seeded permutations of the resulting bank. Hold out two further row orders for each of 64 stratified keys. These are the primary presentation-transfer cases. Changing actor names and location layout is a separate diagnostic. All feedback and probe streams are generated and hashed before training.

Each presentation of a teaching key yields one answer episode and one auxiliary episode. The ordinary query ends with a query marker and the learner sees the location byte and EOS as subsequent observations. The auxiliary query uses a different final marker and has 12 observed bit bytes plus EOS. For worked examples those bytes show which of the six actors other than the mover and queried actor were newly reached in propagation rounds one and two, in the order the actors were introduced. The auxiliary trace omits the final location and both endpoints. The evaluator never provides a trace or a worked step on an answer probe. The grammar and observation stream are the only inputs. Graph traversal, actor roles and reachability vectors never enter the model as features.

## Comparison

Cross both model variants with all three teaching conditions. Initialize paired arms from the same birth and use the same fixed byte code, ordered 72-byte window, 32-dimensional GRU cell and byte/EOS head. A learned common input projection maps ordered age slots to a 32-dimensional vector (u_t). Use a fixed, seed-generated, distinct nonzero 8-dimensional vector for each byte and EOS, and zeros for missing context. Concatenate the 72 slots, then apply a learned affine map and tanh. A standard dense GRU cell with two bias vectors and a linear output head gives 33,281 trainable scalars per arm, including the input projection.

| Model | Previous vector supplied to the shared GRU cell |
| --- | --- |
| Ordered-window control | (u_{t-1}), recomputed directly from the previous ordered raw window. The result of the cell does not feed the next transition. |
| Recurrent reference | (h_{t-1}), the cell's actual previous output. |

Both variants see the whole maximum-length episode through their ordered windows, have the same trainable tensors, and call the cell once per observed or generated symbol. The recurrent arm can accumulate intermediate computations as bytes arrive. Reset working state and byte windows at an episode boundary in both variants. Weights and optimizer state persist across the whole teaching history. This isolates within-episode computation from across-episode learning.

| Teaching condition | Auxiliary observation and loss |
| --- | --- |
| Answer only | Deliver the same auxiliary bytes as the shuffled condition. Mask all auxiliary response loss. |
| Shuffled steps | Give the same trace targets as the worked condition, re-paired with different semantic keys by a seeded permutation. |
| Worked steps | Pair each trace with the episode that generated it. |

Shuffle within a law and training epoch using a derangement across semantic keys. The valid and shuffled arms therefore match trace length, byte counts and trace target frequencies. Audit that the shuffled pairing does not systematically preserve trace-to-query relations. The answer-only arm measures whether shuffled supervision is harmful. Every arm gets the same answer prefix, label, EOS, timing and answer-loss coefficient. Use one Adam step per answer/auxiliary pair at learning rate 0.003, with betas 0.9 and 0.999 and epsilon 1e-8. Keep settings and update counts fixed across conditions. Answer and auxiliary branches have separate reset states. Weight each prefix target once, each ordinary answer byte and EOS four times, and each supervised auxiliary bit and EOS once. Normalize by the fixed number of sites in each frame before applying the loss mask so the mask does not increase the answer coefficient. Log delivered symbols and scored target sites separately.

Train both variants with within-episode BPTT as feasibility references. This is a diagnostic use of gradients in the reference. The design preserves the project's constraints on attention and candidate learning. The selected architecture stays fixed during the comparison, and no candidate with a local learning rule is promoted on this evidence.

## Evaluation and decisions

Use two fresh paired development blocks and two teaching histories per block. The birth is the comparison unit. Report scores for each history, graph family and block alongside pooled counts. All evaluation is pre-feedback, read-only and free-running, with a common 16-symbol cap. An exact answer requires the correct location followed by the model's own EOS. Report correct first byte, EOS and cap hits separately.

1. **Check acquisition and transfer of presentation.** At 2,048 answer episodes per history, score 64 literal taught prompts and the two withheld row orders of those 64 semantic keys. To pass, a condition needs at least 52/64 exact taught answers and 48/64 pairs with both withheld renderings exact, under both laws in each block. Continue the full factorial to the locked 8,192-episode checkpoint so the early screen does not change exposure among conditions. Apply the same acquisition and transfer floors at the final checkpoint for eligibility. A practical improvement on presentation transfer is at least 8 additional both-correct pairs out of 64 over the relevant matched control under both laws in both blocks. Compare recurrent against ordered-window at each teaching condition, and worked against both shuffled and answer-only within each model. Report the interaction descriptively. The presentation result is E2 because canonicalized lookup can recover the trained key.

2. **Check rule reuse only after a condition passes presentation transfer.** Score every one of the 256 opcode assignments on each of the two previously held graph families, on familiar actor bytes, from the frozen final A checkpoints. Seed the renderings independently of feedback. Use the same literal prefix for the two opposite laws. Primary E3 screen is balanced exact accuracy, the mean of exact move and stay accuracy. Compare with the graph oracle, exact/canonical lookup, recent context, opcode counts and the strongest family-specific three-query adaptive link rule. The previous 32-quartet set is supplementary because that adaptive shortcut solved 30/32. Require each law in each block to beat the requalified adaptive balanced baseline by at least five percentage points on each family. Also record both-law exact performance on the same literal prompts whose labels flip. Use all eligible conditions for this frozen readout. The earlier estimates of the adaptive baseline were 83.1% and 89.3%. [Adaptive audit and full-assignment results](../minifly-ordered-front-end/CAMPAIGN_REPORT.md)

3. **Test attribution and delayed reuse only if the E3 screen passes.** Advance one qualifying condition. If several qualify, select the one with the greatest minimum margin above the adaptive baseline across the paired blocks, laws and families. Break ties in favor of the ordered-window model and then the simpler teaching condition. Re-run matched A histories from the same births and with the same prefixes, timing and target counts. In these controls, assign half the semantic keys in each outcome stratum to each law within an epoch. Reverse each key’s assignment on every new epoch and counterbalance the first assignments across paired histories. Generate each trace under the law of its source episode, then apply the selected auxiliary condition. This removes a consistent stream-wide law without making one law dominate the final epoch. Compare the candidate and its matched inconsistent-law reference on the same held prefixes before any held feedback. Require a ten-point balanced exact advantage under each scored law and on both families in each block. Carry the qualifying A histories through 2,048 B episodes with separate opcode and actor bytes, then score untouched, never-reinforced A renderings of the full held mask sets again. Keep the E3 floor and allow at most a five-percentage-point drop in balanced exact accuracy from A to post-B, under each law and on each family. Report B acquisition and A retention separately. This is a development result about one task family. Correction and a local-rule reproduction belong to subsequent decisions.

If every condition misses the final taught floor, the result is an acquisition failure. If taught acquisition passes and every eligible condition misses the E2 gate, the result localizes to the tested presentation change. End the run at A in either case. If worked steps beat both controls and recurrence adds little, the teaching change is the supported intervention. If recurrence helps with matched teaching, it earns a comparison under the project's local update constraints. If the improvement requires both, retain the interaction as the result. Failure of the reference identifies a limit of the tested setup and dose.

## Preflight and resource limits

Use one separate engineering block to verify the oracle, opposite-law witnesses, unique byte keys, absence of held layouts and topologies in feedback, and the exact baseline ceilings. Inject an exposed key and an answer-bearing trace to confirm the leakage checks reject them. Verify matching primary loss and timing, recurrence ablation, deterministic replay, free-run causality, state immutability during scoring and fresh-process checkpoint restart. Train only enough engineering records to check numerical stability and profile both complete update paths. Freeze the renderer, split, seeds, optimizer settings, all gates and permitted analysis before opening the two development blocks.

The 24 histories use at most **196,608 answer/auxiliary pairs** at the final A checkpoint. Each pair delivers 123 symbols including EOS, giving **24,182,784 delivered symbols** in the main roster. Conditional controls and B add at most **5,038,080** delivered symbols. Count engineering and inference separately. Set a measured wall, CPU and memory budget with 25% reserve from the end-to-end preflight before launch. Numerical, exposure, baseline or checkpoint failures invalidate the affected comparison. An engineering or development result does not substitute for independent confirmation.
