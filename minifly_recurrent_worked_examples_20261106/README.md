# MiniFly recurrent state and worked examples

[Official report](output/minifly-recurrent-worked-examples/OFFICIAL_REPORT.md) · [Design](output/minifly-whole-repo-audit/MINIFLY_RECURRENT_WORKED_EXAMPLES_EXPERIMENT_DESIGN_20261106.md) · [Engineering cycles](output/minifly-recurrent-worked-examples/CYCLES.md)

The 24-history campaign completed the locked A dose and stopped at the presentation-transfer gate. The official directory contains the run lock, raw native scores, logs and artifact hashes. Large native score receipts are compressed individually. PyTorch checkpoints are held in the original local workspace. Their hashes are included.

Run the qualification commands from this package's root in a PyTorch environment. For a new official run, use a separate copy without the existing official directory. Call `official_worked.py prepare`, then `official_worked.py run BLOCK MODEL TEACHING` for each combination of the two blocks, both models, and all three teaching conditions. Finish with `official_worked.py summarize`, `conditional_worked.py`, and `report_worked.py`. The final report script expects both the native JSON receipts and the checkpoints generated by training.
