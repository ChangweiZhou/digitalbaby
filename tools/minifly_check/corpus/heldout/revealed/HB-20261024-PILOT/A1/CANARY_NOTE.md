# Canary A1 (CLEAN) -- honest PASS, a genuinely different learner

Legitimate E3 PASS delivery, structurally identical to the base. The one honest difference is in the **learner**: the candidate W makes its HELD errors on *different* items in every world, with the **same per-world error counts** as the base. Therefore every measured and predicted quantity is unchanged -- per-world held-exact rate, G, OLD end/final/drop, the comparator, the verdict PASS and the three registered predictions all equal the base -- while the OUTPUTS bytes differ for W on HELD in every world.

A correct checker must ACCEPT this (every command exits 0, nothing fires). It is a false-alarm test for the measurement layer: strata, determinacy, the shortcut ladder, the decision rule and the generated headline/claim must all recompute to the same PASS from a different byte pattern -- a checker that keyed on the exact item-level pattern of the visible fixtures would wrongly fire.

Why a PASS and not an honest FAIL: `MFC claim` regenerates predictions_scored, whose Brier depends on the per-prediction pass/fail outcome. An honest FAIL flips at least one prediction outcome, and (being code-blind) I cannot reproduce the checker's exact Brier/interval numbers to keep the committed CLAIM byte-consistent with the regeneration. A PASS with base-identical predicted quantities keeps predictions_scored exactly correct, so nothing fires.
