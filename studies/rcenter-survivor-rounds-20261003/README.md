# R_center survivor programme

This isolated study tests taught-dependent held-out table completion using the frozen R_center observed-outcome learner. It does not establish abstract symbolic composition or broad transfer. A simple row-completion rule can solve the chosen fixture.

The official round is gated on three distinct design→independent audit→test cycles, a frozen64-world protocol, operational recovery/private-backup/public-sync qualification and launch review. Preflight receipts are technical evidence, not official results. Later rounds are conditional and never automatic.

See protocol/ for the three design iterations and the eventual OFFICIAL_LOCK.json, audits/ for independent acceptances, receipts/ for immutable bounded JSON evidence, and source/runtime/ for the evaluator and analysis. The source-essential frozen model is under source/baseline/. Historical old R3 raw receipts and the private original archive are not republished here.

Scientific execution uses Python3.11.15, numpy2.2.6, scipy1.14.1 and numba0.61.2, as inherited. The authenticated transport adapter expects the coordinator's authorized GitHub/Library tools; it contains no credentials. Private transport state and helper implementations are excluded. Scientific source and operational artifacts are separately identified, and a public branch is not evidence that an official run has begun.

## Recovery bootstrap

A replacement executor must materialize the retained checkpoint into its own workspace through the currently supported Library flow, verify its archive and payload identities, and restore the pinned scientific runtime. It must obtain the current private transfer helper through that supported flow; neither a stale helper nor a path from another executor is assumed usable. The helper and credentials are not distributed in this repository.

Start a fresh active tool-host session and run the production planner before any learner job. A pre-job reservation has already charged the full900-second cap and must be readback-acknowledged off-host before execution. Interrupted reservations are reconciled conservatively; exact-key retries and complete-receipt crash dispositions require independent infrastructure review. The outer runner stops at unresolved remote phases and proves already-completed uploads/refs with read-only checks before changing local acknowledgements. It does not pretend a Python daemon can survive an executor reset or authenticate GitHub by itself.

The acknowledgement embedded in a checkpoint predates that checkpoint's upload. On replacement-executor startup, use the stable retained Library identity to obtain the actual current version and readback, verify its bytes, and rebase the local acknowledgement paths before any replacement. Never infer the current remote version from the archived prior acknowledgement. Uncertain remote phases or a changed public branch head stop for read-only reconciliation. Isolated restore qualification includes the production historical-evidence and missing-only planner, not only receipt parsing. The terminal analysis job is also pre-reserved, supervised and persisted after all64 world barriers.
