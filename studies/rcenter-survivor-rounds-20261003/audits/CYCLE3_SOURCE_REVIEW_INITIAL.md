## Required bounded corrections

### R1. Production reconciliation, local revalidation and missing-only sequencing

`operations/supervise.py:27-45` trusts completed-attempt entries and compares their recorded manifest SHA only with persistence state. It does not open/hash/validate the completed local receipt. A pure isolated call to the actual admission function admitted `science/310002` while the claimed completed `science/310001` manifest did not exist. This contradicts startup and missing-only integrity requirements.

No production function reconciles a stale running attempt, charges its unknown elapsed time, validates the attempt journal, or handles the crash window between a complete receipt and ledger finalization. `tests/cycle3_recovery.py:29-38` simply adds 900 to a mock dictionary and computes a list comprehension. Its source-mismatch check raises its own assertion. Those examples cannot qualify production recovery. Partial output at the fixed destination also makes every future retry fail at supervisor line 69, even after recovery approval. Cycle-3 job prerequisites are not checked, so replay can consume a full native life before discovering that its pilot is missing.

Required fix: add one production reconciliation/planning path under the same lock. Verify journal chains, attempt/source/runtime identity and every completed local manifest/part; verify historical-cycle receipts against their accepted snapshot maps. Reconcile stale identities only after establishing the old writer is gone, charge an interrupted unknown-duration attempt at the full 900-second cap exactly once, preserve/quarantine partial output without overwriting it, and require the existing independent infrastructure classification before an exact-key retry. Handle receipt-complete/ledger-incomplete crashes explicitly. Return a missing-only plan and enforce operations → pilot → replay prerequisites. Exercise these exact functions in the single pure operations job using isolated mock files/processes, including deleted/tampered completed receipts, interrupted attempts, repeated reconciliation, partial output and budget exhaustion. Do not add native outcomes.

### R2. Freeze the actual automatic tool-host runner and its stop boundary

`operations/controller.js` defines a callable transfer function, but no checked-in caller watches or awaits the supervisor, validates the finished manifest, invokes the function, and advances only after both acknowledgements. `supervise.py` never calls it. The prior manual Cycle-1 commit is preliminary path evidence, not this automatic pipeline.

Required fix: add a small audited active-tool-host entry/runner that awaits each exact supervised completion, detects the immutable receipt, invokes the existing controller with the fixed authorized scope, persists the manifest-bound acknowledgements, and only then considers the next world. A lost host, permission, connection, unresolved phase or failed acknowledgement must stop admission before a second unbacked world. Keep the limitation explicit: this host does not outlive executor reset. Freeze the read-only reconciliation flow for an uncertain Library upload/ref update before retrying any mutation; do not merely require a manual edit to clear `TRANSPORT_PENDING.json`.

Qualification must invoke that exact runner/controller on the full pilot through actual Library replacement/readback and GitHub tree/ref readback, then demonstrate an unchanged second invocation causes no archive, Library version or Git commit. Bind the qualification report to the pilot manifest and tool-host/controller hashes. No extra native run is needed.

### R3. Complete the receipt/clock validator before spending the pilot

`validate_receipt.py` never reads probe `clocks`, final `end_clocks` or `end_wrapper`; it does not validate mandatory runtime, birth/state-budget, endpoint/tie-policy or acceptance fields. The writer checks the old-delay end (`new_start`) but discards that clock vector. Its scalar final flush-error check accepts negative values. A pure synthetic 48-part receipt was accepted with all probe clock vectors absent, all final clock/wrapper vectors absent, runtime/birth/state-budget fields absent, and `clock_error=-1`. This was synthetic structure only, not a learner result.

Required fix: define/check mandatory schemas and exact kind/world/source/acceptance/runtime identities; validate the fixed canonical birth and budget fields. Persist and validate all eight-store old_end, new_start, new_end and final clock vectors, pending state and correct counters/last-byte relationships, with finite nonnegative flush errors. Validate final wrapper identities and their intended linkage to the final probe guards. Validate the current clock-bearing probe fields, rather than only their query timestamps. Require canonical official directory names and science-kind receipts in final inference. Add semantic tamper cases to the pure job, recomputing the part manifest in those cases so the semantic validator is genuinely tested. Keep the first-pre-feedback and disposable-query behavior unchanged.

### R4. Make private restore preserve results and conservative accounting

`checkpoint.py:15` omits `results/`. Its content identity excludes all execution state even though a few state files are placed inside the ZIP. A pure isolated call confirmed that changing `RUN_LEDGER.json` from 1 to 901 charged seconds reused the same archive with `changed=False`, and the archive still contained 1 second. Interruption-only progress and final analysis can therefore fail to trigger a new durable checkpoint.

The checkpoint also omits the actual `operations/journal/`, transport journal/pending state, persistence/publication acknowledgements and other state needed to reconcile its own runner. The controller verifies ZIP bytes but never restores to an isolated path and invokes the pure receipt validator there. Its Library helper is intentionally private and excluded from the scientific closure/backup, so its supported bootstrap must be explicit rather than assuming it magically exists after reset.

Required fix: include final results and essential recovery/accounting state in a nonrecursive logical checkpoint identity or separately durable acknowledged journal. Avoid self-triggering on acknowledgement timestamps/paths and still prove unchanged invocation is a no-op. Preserve sufficient private reconciliation information to recover without dropping charged attempts or clearing uncertain mutations. Add safe isolated restore plus source/manifest and pure receipt validation, and document the supported private helper/runtime bootstrap. Use relative logical paths in persisted recovery records or explicitly rebase them on restoration. Validate this with the fixed pilot archive; no extra learner execution is required.

### R5. Close durability/concurrency and accounting gaps around transport

The supervisor lock only covers one worker; controller/checkpoint/transport mutations have no corresponding exclusive coordinator lock. Two active tool-host invocations can race the phase state and remote update. Mutable journal/ledger integrity is not verified before append/admission. `checkpoint.py` fsyncs ZIP bytes but not the directory after link/unlink; new receipt directories likewise lack an explicit parent-directory fsync. A hash-valid JSON file alone does not close these crash windows.

The 18-hour active-wall ledger is incremented only by the same worker duration as the 12-hour worker ledger, so transport, checkpoint and restore activity is uncharged and the wall limit cannot independently bind. `output_size()` omits mock-test/journal and some operational output. Backup/disk caps are checked after archive construction and before, but not after, Library readback; the latter adds another local copy. These paths are outside the native-worker monitor.

Required fix: serialize the entire host/transport operation, validate/anchor journals at startup and make directory creation/publication durable. Define and charge active wall across the operational session, and enforce the output/local-backup/disk-reserve limits before and after checkpoint/readback/restore, including temporary copies. Maintain cumulative accounting through reconciliation. Use streaming file hashing, ZIP writing and readback verification rather than the current whole-payload dictionary and whole-file reads; do not retain archive buffers in the active tool host. Freeze safe cleanup of redundant materialized readback ZIPs only after byte identity against a preserved original is verified, retaining unique originals and the required restore-tested snapshots. Document any change from the current two-newer-snapshot cleanup condition in the pre-test amendment, and include final-64-world growth in the disk forecast. The native-worker cap may remain unchanged. Freeze a pilot-based launch forecast with measured pilot/replay time, remaining charged budget, explicit safety margin and transfer/storage overhead. Merely quoting 900 seconds cannot justify launch: 64 × 900 = 57,600 seconds already exceeds 43,200 seconds before qualification.
