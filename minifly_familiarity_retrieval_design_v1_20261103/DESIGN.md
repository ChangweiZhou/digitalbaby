This is a standalone local byte learner proposal in the memo's hashed-context lineage. No numbered version is reserved. V188's local run record is incomplete and supplies no verdict for this design.

## Decision

Can a learned retrieval gate use the familiarity of recent bytes to recall a taught answer in a new wrapper while preserving ordinary byte prediction, including when prose contains a familiar key and no answer is due?

The memo reports that its answer-gated bag memory recalls taught associations across wrappers when read directly, while a learned cue gate loses much of that recall. This nominates timing as a bottleneck. The reported numbers are development evidence from the attachment. Its memory-only next-byte results leave complete own-byte/EOS behavior open. V187 provides a separate reason to measure that behavior directly: its factorized prose head emitted no EOS on 192 continuations. The proposed trial tests retrieval routing before trying natural text, multi-discount relation maps or compositional arithmetic. Those are separate hypotheses.

## Fixed learner and causal contrast

Use a 257-class all-byte predictor and a separate 257-class association memory. Each computes logits by averaging the rows indexed by its current sparse active set. The predictor uses a bounded fixed lag hash, and the memory uses the union of four fixed hash addresses per observed bigram/trigram in the last 24 raw bytes. Freeze hash salts, fan-out, collisions, padding, byte ordering and tie breaking. A concrete compact reference uses 2,048 predictor rows and 4,096 memory rows, float32 weights and one bias per class per expert. These are new design choices. If the memo's source becomes available, record source differences before implementation. Reproduction of its exact result would require the original executable and manifest.

Both experts learn with the same output-local multiclass delta rule, using their respective softmax predictions. For a distribution p and arriving target y, each distinct active row receives a step proportional to onehot(y) − p, divided by the active count. Specify finite step sizes in the technical lock using public synthetic canaries only. The predictor updates at every observed byte and genuine record EOS. The memory updates only when the environment supplies an answer-teaching marker, including on the genuine EOS of a taught answer record. That EOS policy extends the memo's next-byte test. The marker comes **after** the site's prediction, goes only to the update path and gate loss, and is unavailable at inference. There is no evaluation-time query flag or external stopping policy.

Define familiarity with a third fixed hash table of 4,096 saturating uint16 support counters. Increment counters for bigrams and trigrams present on marked payload sites only. Do not index the table by predicted or observed answer class. At prediction, use the mean clipped support and fraction of supported n-grams over two fixed recent suffix lengths, 8 and 24 bytes. Compute all four summaries from raw history. No parser identifies the key, answer span, role, fact ID or template. Counters and features use pre-update state. Count memorized wrapper evidence and collisions as possible confounds.

The deployed gate is a sigmoid of a sparse cue score plus four scalars. Cue rows use generic recent suffix/lag hashes. Gate learning uses a local binary delta with the observed teaching marker as target, including zeros on ordinary bytes. A candidate probability is the mixture p = (1−q)p_predictor + q p_memory. Compare the following prespecified reads of the *same* predictor and memory trajectory.

| Read policy | Role |
|---|---|
| Predictor only | Prose reference, q = 0 |
| Fixed score sum | Reproduce the memo's template-tolerant reference. Use softmax of the two experts' summed logits, each centered by its mean. |
| Cue only | Same learned cue gate with four extra coordinates held at zero |
| Cue + sham familiarity | Same learned gate with four address-deranged support summaries |
| Cue + familiarity | Same gate and features, with aligned familiarity summaries |

For the sham, use the same fixed update stream and table, but apply a prospectively fixed derangement of address labels on reads only when deriving support summaries. Match feature count, delta rule and arithmetic. Report support mean, sparsity and range by arm, and use cue only as the direct baseline. The deranged gate controls for adding four trainable inputs. Derangement can change support statistics, so also run a fixed, within-world inference swap of familiarity summaries between matched familiar-key query and nonquery prefixes at the same byte offset. Interpret the swap as a sensitivity diagnostic, separate from the trained-arm contrast.

Learn all three gates online alongside the shared experts. Their predictions must never control expert writes, input generation or future training data. This makes weight and observation equality exact and permits paired readouts without replaying expert histories. Give each gate the same start, labels, steps and exposure. For free generation, clone transient history separately per arm, feed back only that arm's emitted bytes and forbid any update. The same model-generated byte/EOS decoder applies to all arms, with one deterministic argmax over all 257 classes and an eight-output cap.

## Fresh stream and continuous life

Use four prespecified paired development worlds. Freeze seeds as the first 64 bits of SHA-256 of MINIFLY|FAM-RETRIEVAL-V1|WORLD|i, i = 0, 1, 2, 3. Use separate salted deterministic streams for keys, balanced random values, presentation order, filler, edits and decoys. Lock exact bytes and hashes, source, checkpoint schedule and adjudication before training. A key is six raw bytes and its independent value is one raw byte drawn from 16 equally represented values. Use no arithmetic structure. Screen key uniqueness and accidental template/answer collisions across the complete frozen roster. Match cue lengths and key positions for query/nonquery distractor pairs. Verify that the visible prefixes contain enough information to distinguish which response is due. Keep identical-prefix opposite-label cases out of the primary assay and report them separately if used as an ambiguity stress test. Filler and query suffixes are ordinary byte sequences. The external interface supports all 256 payload bytes and a distinct EOS class.

- **A** introduces 32 facts. **B** introduces three further waves of 32 distinct facts. Present each fact four times, twice in each of two training wrappers. Mix one nonanswer prose record per four teaching records. At least half of nonanswer records must contain a known key introduced before that record, with the rest paired to unseen-key or no-key distractors. Teach no answer on these prose records. Use the same wrapper family in both query and nonquery contexts where grammatical, and counterbalance key, value and position.
- Probe at the end of A and after B without feedback. After B, clone the full state into **EDIT** and **NOEDIT**. Edit eight prespecified A keys to independently drawn different values, balanced across old and new values. Use four presentations per edited key. NOEDIT sees the same cues, templates, repeats and filler with the old value. Keep the other 24 A facts and all B facts valid. Probe both children.
- Hold out two entirely new wrapper families plus a position/spacing variant. Freeze the wrappers and prompt cut before any learning. Include matched familiar-key nonqueries, unseen-key queries, and same-key prose mentions near real query positions. Withhold the full held wrapper forms from both teaching and filler. Also report raw 8- and 24-byte context collision rates, whether the final cue suffix occurs in training, and n-gram overlap. Never teach or tune on evaluation queries. Probes run on read-only copies.

## Endpoints and interpretation

Primary endpoint is **complete own output** on taught A facts after B: emit exactly the assigned one-byte value and then its own EOS, with no repair or stop forcing. Compute separately for each new wrapper family. Report value-only accuracy, EOS at the expected position, extra bytes, truncation and exact completion. Keep familiar-key nonquery, unknown-key query, original-wrapper and shifted-wrapper panels separate. For ordinary prose, quantify mean gate probability, false route rate at q ≥ 0.5, and excess predictive bits on distractor sites. For the complete mixed held stream, score normalized predictive distributions before observation and report payload bits/byte and EOS separately, with identical event weights and one query record per four nonquery records in a fixed evaluation stream. For distribution scoring, the evaluator advances the observed prefix without supplying marker feedback or updating weights. These are predictive metrics, separate from free generation.

A bounded positive requires all of the following on each world:

1. At least 80% exact complete output in **each** new wrapper family after B, matching the memo's proposed recall target with stricter EOS scoring. Require strictly more complete items than both the cue-only and sham gates in both families.
2. Mixed held payload bits/byte no greater than predictor-only. Ordinary prose containing familiar keys must independently meet the predictor-only bound, so query gains cannot offset false retrieval there. Report score-sum performance and compute. If it meets the same behavioral bounds and matches the candidate, the learned gate has no demonstrated advantage over that simpler read.
3. After EDIT, strictly more changed keys emit the new complete answer than after matched NOEDIT, separately report obsolete answers, and no fall in the count of complete answers for still-valid A and B keys versus the candidate's B checkpoint on the same roster. Report retention and correction by wrapper and all failed guards.

Use paired world and item counts, with no treatment of item repeats or correction forks as independent worlds. Four worlds support a bounded development decision. Evaluation-only references: an oracle routes to memory on actual answer targets including EOS, a literal trained-prefix table backs off to predictor, and a canonical key table with ideal query timing is the ceiling. Include a strong simple shortcut that extracts a known key and fires whenever it appears, plus answer-frequency and template-only references. The ideal canonical table can answer this task by construction. A success therefore supports changed-presentation recall of a taught relation (E2 ceiling under the objective contract), with retention and revision measured separately. It does not establish relation discovery, unseen addition or adoption.

If the oracle-routed memory cannot reach the complete-answer target, report the routing comparison alongside the memory/EOS bottleneck. The gate cannot be blamed for a failed expert ceiling. If the oracle can and familiarity misses the gates, reject this exact familiarity route. If it helps recall but fires on known-key prose, label it a key-presence shortcut. An explicit query marker can be studied later as a separate information condition. It cannot rescue the present verdict.

## Physical limits and launch qualification

Per world: 512 fact records across A/B, 64 across the two C children, and 144 filler records, for **720 records**. Four shared expert histories and eight correlated C children total **2,880 training presentations**. Cap each record at 127 payload bytes plus EOS for at most **368,640 target sites**. Report actual predictor writes, marked memory writes, support updates, and per-gate updates separately. Multiple updates at one site are distinct work and must be counted. Log technical and evaluator costs, all read policies, ordinary prose and generation separately. No full-state clone per byte.

The experts have 1,579,008 row weights and 514 biases, about 6.03 MiB in float32. A 2,048-row scalar gate plus its bias and four summary weights adds about 8 KiB per gate, and support adds 8 KiB. This is a separate size envelope from V187's 37k model and an explicit trade-off for the memo's memory addressing proposal. Admit only under 8 MiB deployed arrays and bounded scratch per candidate, 8 MiB per full checkpoint, 256 MiB total outputs, 1 GiB peak process RSS, 900 CPU seconds and 1,800 active wall seconds. Use sparse row access only, no dense feature-by-vocabulary copies per event, and count checkpoint copies and archive storage. Save all three gate states in each full checkpoint. Keep five full checkpoints per world (birth, A, B, EDIT, NOEDIT). Use the remaining reserve for verified summaries and the compact archive. Include repeat cost and actual work per byte in the report.

Before launch, qualify local updates, stable normalization, 257-class tie rules, causal marker timing, keyed-distractor coverage, actual EOS generation, and the oracle reference. Rehearse the production entry point on a reduced synthetic roster through score reduction, both forks, exact counts, finite/empty-stratum serialization, receipt verification and ZIP readback. Bind the rehearsal to the exact launch source hashes. Measure the actual full-roster profile before admitting it. Stop on invalid data or resources.
