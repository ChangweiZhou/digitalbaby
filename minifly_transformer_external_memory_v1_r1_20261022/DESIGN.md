# MiniFly external memory V1-R1: storage before host fitting

22 October 2026. Separate external-memory track. Parent: [V1](../minifly_transformer_external_memory_design_v1_20261022/DESIGN.md). User authorized this revision and three bounded technical cycles, not formal evaluation or publication. Historical addition results, gradual warmup, native kernel and arithmetic planning pointer remain unchanged.

## Claim and exposure

Primary purpose is E1 taught-association storage and causal delivery to a frozen host. No arithmetic or NLP improvement is claimed. Independent uniformly random byte values cannot be inferred from their keys: the Transformer can learn addressing, denoising and serialization, but contributes no independent information about a new random value. An exact table can solve this assay after one exposure. Keep that baseline and report cost; never promote E1 to an arithmetic-rule result.

The received audit correctly prioritizes native direct readout, dose and cross-address interference. Its account of R2 is an interpretation, not a new reduction: R2's published tables include varied wrong outputs and two unfinished histories. Overlap is a candidate cause, not a proof of causal interference. Likewise a declining teacher-prefix loss does not show eventual exact acquisition.

## Changes to V1

1. Put a cheap native storage diagnostic before H0 and H1. Use canonical N=5,177 anatomy, nine bit/EOS compartments, unchanged native `gated=False` equations, actual B/PN projection and side competition at native density. Random 88-channel signals are a **surrogate diagnostic**, not a learned byte encoder or deployment arm. Center thresholds on 256 disjoint random input frames. Sample input signals independently of targets; never select/reject neural addresses using correctness.
2. Before decoder fitting, measure between-key overlap at the same output slot, within-key overlap across slots, exact address collisions, activity count and a causal write-influence matrix. Subtract a passive matched-clock branch to distinguish learning from time/adaptation. Shared support alone need not imply indistinguishable reads. Report both overlap and signed target/cross-target changes.
3. Preserve original gradual strength `s(n)=(1/16)*(1/16+(15/16)*min(n/1024,1))`, counting completed external records from zero in each fresh life. Direct tests expose the 1/4/16/64-pass acquisition curve rather than interpreting 16 passes as maximum capacity. The 64-pass curve uses more samples and more simulated elapsed time; it is not a strength-only causal intervention. Fixed strength and faster ramps are **not authorized** here. Any later model/reward calibration must use training data, be locked before evaluation, and count every exposure.
4. Separate immediate acquisition, one-hour decay, NEW interference, and second-hour decay. Record fast/slow masses, byte-bit accuracy, whole value with own EOS, free outputs and margins at each point. Do not interpret a failed delayed endpoint as a capacity limit without checking immediate acquisition. The simple exp(-7200/tau) estimate describes a passive component, not the whole nonlinear/consolidating memory.
5. Gate expensive host work on a native causal effect: with stable addresses, correct writes must improve target-aligned margins over no-write and shuffled writes on fresh technical data; whole-value failures remain failures. This component gate alone does not qualify the hybrid. If only bit-level acquisition works, first identify errors/EOS/interference rather than launching the 32-world V1 plan.
6. When H0 is eventually implemented, audit **actual frozen learned** key/position addresses with the same measurements. Reconstruction and position classification do not guarantee separable KC supports. Random-input success is not qualification of this bridge. No key-specific channel allocation, semantic routing, arithmetic rules or target-dependent address selection is permitted. Generic geometric regularization would be a new separately reviewed arm, not a post-hoc repair.

## Three prospective cycles

Each cycle: freeze plan, self-audit interfaces/claims, run real native equations on fresh technical data, inspect result, write explicit revision. No delegation was requested; these are auditable self-reviews, not an independent scientific audit. All runs use one thread, a 240 CPU-second ceiling per invocation, canonical anatomy, four arbitrary payload bytes and own EOS, nine read slots; readouts use a private BEGIN-reset clone with no tick between slots. All values include arbitrary 0–255 bytes. A key/slot's fixed surrogate frame is independent of answer and prior generated bytes; this is an intentionally simplified storage diagnostic.

- **Cycle 1, seed 202610226101:** target-free random-PN address geometry and one-record W versus passive-N write influence. Include deliberately collapsed position addresses as a sensitivity control, all-257-token codec, readonly and no-write checks. Two record applications total; no claim about a trained host.
- **Cycle 2, seed 202610226102:** 16 random four-byte facts, 1/4/16/64 cumulative passes in one correlated life, unchanged gradual rule. 1,024 records maximum; report sample/clock and dose confounding. Independent slot inputs are an optimistic reference, not a representation selected for success. Fresh seed prevents tuning Cycle 1's addresses.
- **Cycle 3, seed 202610226103:** 16 OLD facts ×16 passes, rest1h, 16 NEW once, rest1h. W, passive N and cyclically shuffled OLD targets start matched. NEW correct for W/SH. 816 records maximum. Score original truth, also compare SH with its taught permutation in reduction. Evaluate identical-stage clocks. These three branches are correlated controls, not independent lives for significance tests.

Total prospective technical record applications 1,842. Five native events per record, plus readonly queries. No formal worlds, host optimizer updates or addition trajectories. CPU, peak RSS, all emissions, source hashes and actual counts retained. Resource limits are stopping rules, not permission to silently shrink tests. The parent two-hour hybrid budget is not launched by this exercise.

## Later hybrid plan

Keep the parent ~0.92M four-block byte Transformer, frozen key path, trusted native writes, no raw-record cache, non-differentiable native reads, host-only/table/delta and native no-write/shuffle/zero/foreign controls. H0/H1 budgets remain ceilings, not promised successes. Preserve variable-length own EOS and absence tests as interface requirements. Actual learned-bridge storage and oracle-fed host decoding must both qualify before full hybrid evaluation. Calibration uses training episodes only. No Transformer/attention is introduced into native MiniFly or the separate addition route.

Do not choose a final acquisition schedule from these three development outcomes and then report the same outcomes as confirmation. A prospective new schedule, fresh technical seeds and explicit execution authorization precede any full scientific run. Cost comparison includes all 64-pass exposures if that regime is used. Final practical usefulness still requires measured advantage against simpler stores; a causal memory effect alone does not establish it.
