# V156 revision — test accumulation before adding another mechanism

**Proposal only; not executed or included in the completed exercise.** The goal remains retained complete own-byte/EOS unseen-addition generalization per all training presentations and actual compute. Keep the native lineage, gradual warmup, local updates and all 257 output classes. No arithmetic-specific representation, rule, parser, attention, Transformer, ELM or fitted evaluator answer head is introduced.

## What V156 changes

The proposed finite decision obstruction was not found: all 12 declared family/case checks passed, including C16 without bias. Native stores have not thereby been proved capable of realizing those free interpolants.

The writer consistently helped its current record: all 178 required margins improved relative to the matched inhibited write. But no one-shot NEW record completed correctly immediately after its own teaching. Meanwhile, all 15 initially correct OLD answers in P_SLOW survived the final continuation and delay probes. Transient write losses exist, but making permanent-memory protection the next default would target a failure this exercise did not demonstrate. No observed complete losses were caused by the matched idle or observed-no-write controls.

The first next question is therefore **whether these helpful local increments can accumulate into a complete answer under a matched feedback schedule**. Do not change the output port, increase the learning rate, add a bias, enlarge the network or add a protection rule at the same time.

## One intervention: clustered versus interleaved feedback

Compare the unchanged N_2B/P_SLOW model under two schedules of the **same eight presentations of each of 16 NEW records**:

- **INTERLEAVED:** eight passes through the same fixed 16-record order.
- **CLUSTERED:** eight consecutive presentations of a record, then the next record in that same order.

Eight is inherited from V154's existing fixed-dose protocol; it is not a new outcome-selected maximum. There is no adaptive repeat-until-correct policy. Both schedules present exactly 128 NEW records, the same 16 unique cues, the same feedback bytes/EOS counts and the same total native elapsed event time. Their intermediate spacing and interference differ intentionally. Record distinct cues, repeated presentations and actual work separately.

This is a training/feedback mechanism contrast, not a new core or an assertion that repetition learns arithmetic. V154 already tested interleaved repetition; the missing contrast is whether grouping the same dose changes native complete-answer acquisition and survival. A clustered schedule might improve immediate recall while hurting later recall or generalization. That is a valid negative outcome.

## Prospective bounded comparison

Use two fresh development worlds, with seeds and splits committed before any data generation or model query. Retain the existing external addition-data construction: 64 OLD, 16 prespecified NEW selected without labels, and disjoint never-reinforced assessment orbits. The arithmetic evaluator may create correct external feedback; no operation semantics enter the learner.

For each world, teach the existing OLD episode to W and present identical observations/timing with those value writes inhibited to SH_OLD. Preserve their real warmup counters. From those two states create the two schedule branches: four correlated trajectories, not four independent lives. NEW teaching is enabled in all four branches. Keep front, codebook, native signed teacher, learning coefficient, time constants and readout identical. P_SLOW is a development choice because both V156 starts supplied acquired OLD controls; do not generalize it to every input path. I_FAST's initial EOS collapse remains a separate unresolved early-training question.

The proposed total is **3,072 observed record applications**: two worlds × (512 OLD W + 512 matched OLD SH_OLD + four branches × 128 NEW). All warmup and inhibited observations count. Reserve at most 16 additional technical records, with at most two payload bytes each. A later implementation must lock a common cap of 1,200 summed CPU seconds, one worker/thread and 1 GiB RSS/output; no automatic extension. This exceeds the completed V156 record allowance and needs a new instruction. Do not spend V156's unused allowance on it.

## Outcomes that answer the question

1. **Acquisition:** native complete own answers immediately after each teaching record, not only teacher-prefix loss. Report every required target's margin and the number of complete answers still incorrect despite positive local changes.
2. **Matched dose:** evaluate at 0, 16, 32, 64 and 128 NEW presentations in every branch. Show unique taught-key coverage as well as total presentations; the schedules intentionally differ in intermediate coverage. The final 128-presentation comparison is equal in both coverage and dose.
3. **Retention:** score OLD and all 16 NEW records at the final boundary and after the same 128-step idle. Earlier clustered cues endure more subsequent teaching; report results by fixed order position rather than hide that recency difference in one mean. Reverse the label-independent order in the second world as predeclared, not after outcomes.
4. **Unseen addition:** score the frozen never-reinforced set before feedback, through the native own-byte/EOS path. Compare W against the schedule-matched SH_OLD branch and raw/canonical-key, favorite and generic position counters. Never use the batch witness as the candidate or a source of answers.
5. **Efficiency:** include OLD preparation, all repeated/inhibited feedback, readout work, cloning, failed attempts and evaluator cost. Better taught recall at the same final dose is E1; it is not an unseen-sample-efficiency result. Any E3 evidence remains limited to the task and the prospective causal contrast.

No arbitrary BPS or percentage threshold substitutes for those contrasts. Publish complete counts and paired descriptive effects for both worlds. This small comparison is not a confirmation study or automatic adoption gate.

## Stop and interpretation

- If clustering crosses complete-answer boundaries but later teaching erases them, a subsequent selective-write/interference proposal becomes justified. It is not selected in advance here.
- If clustering improves taught answers without helping unseen answers beyond matched controls, report an associative-acquisition improvement only. Learned representations remain a separate hypothesis; Claude's text reference does not supply an arithmetic result.
- If neither schedule produces useful acquisition within the fixed dose, stop. Do not raise repetitions, learning rate or model size automatically. Native reachable read/write geometry and feedback gain remain open even though the free C16 witness exists.
- If both schedules behave similarly, reject this exact scheduling hypothesis rather than attribute the null to all local learning.

The current V156 exercise is finished. This revision requests no new run, automatic retry, GitHub publication or change to historical adoption.
