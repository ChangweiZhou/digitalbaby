# MiniFly v5.1 — three-cycle engineering report

**Result: NO_ADVANCE — the isolated native output port is qualified, but learned byte identity is not.** This is a bounded engineering result, not a failed arithmetic generalization experiment. No unseen-addition efficacy test or scientific campaign was run.

The goal remains retained exact own-output unseen addition per all training exposure and actual compute, with gradual warmup and no arithmetic-specific structure, attention, Transformers, ELM answer model or backpropagation. [Authorization](AUTHORIZATION.json) covered implementation and three bounded technical cycles, not a formal campaign, adoption or GitHub push.

## Three cycles

1. **Implement, audit and revise the native bridge.** Implemented the nine-channel native memory, matched zero-value reference, masked terminal EOS teaching, generic sequence-state prototype and strict signed record-confirmation gate. New event equations matched the independently called pinned native batch primitive exactly at both 5,177 and 65,536 cells. The new reference matched a direct zero-value native query exactly. All byte bit patterns/EOS, signed direction versus passive controls, strict zero slow allocation, spacing/identity/replay behavior, readonly generation, checkpoint continuation and target-independent frames passed the final audit. Early module-name collisions and overly literal pickle hashing were corrected and preserved; these are implementation failures, not model evidence.
2. **Test the port over a complete gradual dose.** Two births, 65,536 cells, eight fixed arbitrary replies of lengths 0–3, with NUL/high-bit bytes and own EOS. Activity depends on cue and generic reply step, never the target byte or expected answer length. At the first setting in the predeclared order—maximum strength 1/16 and a 1,024-record ramp—both births scored 100% exact at rounds 1, 4, 16, 64 and 256. Matched no-write scored 0%. Both retained 100% after one simulated hour. The remaining stronger/faster grid settings were not run because the smallest/longest qualifying setting was found.
3. **Test learned byte formation and revise the design.** Two paired worlds, the four permitted competitive-Hebbian rate/bias settings, and fixed 50k/100k/200k-byte checkpoints. Every setting in both births mapped the 12 observed byte types to only eight winning units. Assignments were stable but aliased; 56 units remained unused. Q1 failed at its cap. Context clustering, integrated port qualification, fitted-head analysis, long arithmetic teaching and confirmation were not started. The [written R1 revision](../minifly_v5_1_design_20261020/REVISED_DESIGN.md) proposes generic error-triggered sensory-prototype splitting; it has not been implemented or tested.

The zero-value reference fixes a concrete failure mode in the isolated port: the readout can now express and retain learned bit/EOS margins instead of emitting the birth offset's default bytes. It does not show that the full learner remembers taught addition facts. The synthetic cue/step activity grid is a diagnostic harness, not an answer-producing component in the candidate architecture.

The byte result identifies an earlier generic bottleneck. Winner-only learning can keep several input patterns in one centroid while unused prototypes never approach them; the weak bounded usage bias did not undo it. More KC memory or a consolidation change cannot establish that this learned identity path works. Because raw bits remain available, these aliases do not prove that all input information was lost or that arithmetic learning is impossible. We stopped at the written gate rather than testing an unqualified path and attributing another zero score to arithmetic.

No generalization, consolidation benefit, superiority over C-native, sample advantage or compute advantage was demonstrated. The learned context and segment mechanisms were implemented as a prototype but not trained or behaviorally qualified. The external fitted head was not run, and no fitted answer head supplies the native result.

## Exposure and costs

The accepted isolated-port calibration used **4,096 W presentations and 4,096 matched no-write presentations**: 8,192 native full-record applications across two births. These repeatedly teach only eight arbitrary cue/reply fixtures. They are not 8,192 independent relations or scientific records.

Cycle 1's accepted structural fixtures used five native full-record applications. Preserved failed engineering attempts used nine further full-record applications. Thus the complete exercise used **8,206 native full-record applications**, including no-write and failed work. Additional partial-event numerical/confirmation fixtures are itemized separately in [TRAINING_LEDGER.json](TRAINING_LEDGER.json); they are not complete records or independent histories.

M2 listening used **1,600,000 payload-byte exposures** across eight settings/birth combinations: 200,000 per tested learner. This includes **511,012 expected-answer byte exposures**, with no explicit correctness loss. The concatenated prefixes contain 155,664 complete record presentations plus eight partial presentations. The same per-world source stream was heard again for different parameter settings; neither repetition nor answer exposure is free. No native value writes were made during these listening tests. All examples belonged to the evaluator's globally filtered training-orbit partition; reverse orientations share the partition.

Final accepted cycle phase CPU was 0.869 s for cycle 1, 171.726 s for cycle 2 and 0.905 s for cycle 3. Cycle 2 includes production and its repeated diagnostic queries; those costs were not separately instrumented. Peak process RSS was about 669.5 MiB in cycle 2. Startup/import costs and CPU for the earlier failed attempts are not independently itemized; wall-time failure records are retained. These timing limits preclude any end-to-end efficiency claim. Compiled kernels and global KC projection/native sweeps remain explicit prototype costs; sparse activity is not a sparse-compute result.

Scientific jobs, confirmation worlds and scientific committed histories: **zero**. Technical births/settings are not statistical confirmation. Caffeinate followed each active test controller and was released after it exited.

## Revised next design

Keep the output fix and the selected gradual schedule. Address the demonstrated dead-prototype/aliasing problem with a bounded generic error-triggered splitting rule, preserving the raw-bit bypass and sensory warmup. Do not assign a unit to a named symbol or introduce arithmetic features. Require the same identity/stability gate, then context qualification, then complete-encoder taught acquisition before any arithmetic E3 escalation. The full unchanged E3 objective and causal/retention/cost requirements remain in the [revision](../minifly_v5_1_design_20261020/REVISED_DESIGN.md).

The qualification and [final independent artifact audit](FINAL_AUDIT.json) distinguish correct tested interfaces from failed behavioral prerequisites. No automatic continuation, adoption or GitHub push has occurred.
