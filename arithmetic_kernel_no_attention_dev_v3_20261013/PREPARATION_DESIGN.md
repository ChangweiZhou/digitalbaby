# KERNEL-SEARCH V3: three-cycle technical preparation

Authorized 13 October 2026: design, audit, test, revise three times. No formal science, background run, upload or core adoption is authorized. All kernels are raw byte-in/own-byte-EOS-out, with learned representations, no attention/Transformer and no arithmetic computation inside the learner.

Ten fixed technical arms: G0, G1 (raw replay), G4 (cadence-four comparator), R1, R8, RU8, C, P, P_STOP, P_RESET. G0/G1/G4 have width64, embedding 16; R/C/P width 32, embedding 16. R8 repeats eight chronological scans, RU8 has independently trainable but initially identical transitions. C uses radius-one local gates for L−1 steps (at least one) and terminal readout. P uses bounded neuronwise modulation, not associative key/value memory. G4 and the P controls use four-record optimizer cadence; other arms one-record. All losses are actual reply/EOS CE, with the same capped AdamW recipe. P writes only after real feedback and trains its update policy through subsequent permitted predictions; policy control stops that gradient, reset control removes cross-frame modulation. P uses current-modulation chronological prefix recomputation rather than a cached historical state.

Context: last128 raw events, disclosed evictions; gradient access limited to that window for reencoded prefixes. R work state has credit through the current response, reset at BEGIN; maximum admitted training reply64 payload bytes. Generation cap16 plus its own EOS decision. Long frames are generic interface tests, not unlimited-credit claims. No target application is created from a generated answer.

Cycle1: architectural/source audit, interface/derivative/no-write tests for all ten arms, then one full short technical life each (128 balanced binary records,32 mixed records per branch;512 external applications/job). Cycle2: revise causal/resource auditing, replay and modulation checks; one different technical world with 256 binary/64 mixed per branch (1,024 applications/job). Cycle3: revise retained-learning and preparation reporting; all ten arms on a third fresh technical world with 256 binary/64 mixed, plus G0 on a separate full-dose technical world with8,192 binary/2,048 mixed per branch (32,768 applications). Exact allocation is technical only. Maximum31 technical jobs,58,368 external applications, plus separately counted fixtures. No reclassified DEV/confirm or repeated science.

Every job executes three binary prefixes W/N_BINARY/SH_BINARY and four mixed continuations W/N_BINARY/SH_BINARY/N_MIXED. N_BINARY disables only the old binary teaching; later mixed learning remains allowed. N_MIXED forks the learned W prefix and disables all mixed writes. Whole no-write includes weights, optimizer, modulation, replay/RNG, pending learning state; resource counters may change. Clone and generation state checks exclude bookkeeping. All final histories are correlated, not independent lives.

Data uses the V1 family/group generator,0–15 seed range, opaque permutation of all 256 payload byte IDs,32 held SUM/PRODUCT families and16 held groups per operator pair. Only raw prompt/reply bytes and one whole-record permission reach model calls. Balanced fixed schedules and permutation are shared across arms. Correct arithmetic computation exists solely in data/evaluator code. Technical probes use up to8 fixed rows per operation/pair and observed literal taught rows; do not present this slice as full-family confirmation. Report actual exact generated payload/EOS, loss and degeneration separately. No significance/promotion verdict from these technical worlds.

Resource reports distinguish original record applications, permitted targets, internal replay, optimizer steps, recurrent visits/local field steps, CPU generation/training, parameter/optimizer/fast/replay bytes. Total process CPU includes evaluator/audit overhead separately from model phase counters. No FLOP or peak-memory measurement is claimed by operation counters. Full-dose G0 timing is measured; other full-dose timings remain projections until measured. All saved-source snapshots and failed tests remain visible. The cycles may establish numerical/causal preparation; they cannot establish better unseen arithmetic per sample or compute without fresh paired science.
