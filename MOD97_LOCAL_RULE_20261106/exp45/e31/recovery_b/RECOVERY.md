# E31 worker B, stage 2: recovering from a container reset

A container reset kills every process: the queue, the running lives and any watcher. On 15 November at about 00:45 UTC one killed the three P2a lives 10–20 minutes in. They were restarted from their start at 00:50; their logs and partial receipts are kept as `*.restart_killed`.

**Why a life restarts from the beginning.** The lives run on E26's life loop, which writes no checkpoint and no optimizer state, and resume is off. Only pushed results survive. Each life is about 72 minutes of CPU, so a reset costs at most one life's time per slot.

**What survives a reset, and what `recover.sh` rebuilds if it does not:**

| Piece | Where | If missing |
|---|---|---|
| Pushed lives | `origin/claude/charming-clarke-u9g850` | nothing to do; the branch is the record of what is done |
| Worktree | `/home/user/digitalbaby/.worktrees/codex` | rebuilt from the branch |
| Python | `/tmp/venv313`: Python 3.13.18, torch 2.15.0+cpu, numpy 2.4.6 | rebuilt from `/usr/bin/python3.13` and the PyTorch CPU index |
| Work folder | the clone's sources and `exp45/e26/e26_dev_*`, with `exp16_integrated.py` as at the E26 births (blob 774813cf) | rebuilt from the clone and git; tested: every file equal to the original |
| Queue scripts | `life.sh`, `sched.sh`, `jobs.txt` beside the logs | regenerated by `recover.sh` |

**Procedure after a reset:**

1. `bash MOD97_LOCAL_RULE_20261106/exp45/e31/recovery_b/recover.sh check` reports:
   - each of the six lives as pushed, running, or neither;
   - whether the scheduler is running;
   - free disk.
2. `bash .../recover.sh go` then:
   - repairs whatever is missing;
   - sets aside the partial files of each life that is neither pushed nor running;
   - writes `jobs.txt` with those lives;
   - restarts the scheduler, detached.

   It refuses to act while a scheduler or a life is still running, so it never starts a second copy. It also never rewrites a script that bash is still executing.
3. Re-arm the watcher on `wall.txt` (done, `exit [1-9]`, failed push, low disk).

A check-in is scheduled hourly into this session until the six lives are pushed, so a reset that sends no notice is still caught.

Optimizer state is not saved by E31's or E32's runners. Every finished birth and life is deterministic, as the ceiling reruns showed bit for bit, so its optimizer state can be regenerated by a rerun if it is ever needed.
